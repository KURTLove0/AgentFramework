LOCAL WORKBENCH

使用运行工作台

  1. 创建任务

    选择模拟运行时、本机 Codex CLI 或 Cursor CLI。在“运行时配置”中保存模型和执行参数。所有业务工具均为模拟工具，结果保存到本地 SQLite。

  2. 审查执行过程

    在运行详情查看结构化计划、动作提案、来源证据与三个独立验收项。运行成功表示草稿已核对，风险评级仍需人工审查。

  3. 演示失败恢复

    选择“写入响应丢失”会自动核对；选择“写后进程中断”，等待租约结束再恢复。工作进程中断不会停止 Web 服务。真正重启服务后，同一运行也能从记录恢复。

  4. 授权和取消

    缺少授权时可审查具体写入参数后授权。取消在当前执行步骤结束后生效，已产生的草稿保留并显示。

python3 -m agent_framework serve --port 8787

服务仅监听本机回环地址。停止服务后重新执行相同命令和数据目录，即可继续查看与恢复。

AGENT DEFINITION

创建 Agent

绑定运行时与 CLI 模型，为后续任务保存可复用的 Agent 配置。

Prompt 与启用的 Skill 将进入规划上下文；任务范围、业务授权和验收规则仍独立生效。

身份

岗位定义

名称与上方 Agent 名称同步；角色和归属团队进入任务的冻结快照。

切换领域会装载相应职责、标准与能力；不会更改历史任务。

职责与交付物

每项职责绑定交付物与验收项，所有必选验收必须有职责负责。

执行标准

选择已登记的版本化标准；运行时独立执行检查，Prompt 无法覆盖这些标准。

能力绑定与编译预览

能力由处理领域的方法决定。原生 MCP 仅可选择已登记的只读能力；编译通过后仍需取得任务写权限。

Skills

配置可复用的方法与领域说明，启用后随 Agent 版本冻结。

MCP 服务

历史端点配置保留供迁移。启用未登记效果的直连会阻止编译；新任务请在岗位定义的 native_read_refs 中选择受控读取能力。
