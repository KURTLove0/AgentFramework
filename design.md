# Design — Agent Framework

## Scope and context

Deep-space glass web application for developers and business operators configuring Agent roles, workflows and governed tasks. Existing API, business tool simulation, consent, authorization, verification and recovery semantics remain intact. Twelve routes share one design system; no marketing page or fabricated activity is added.

Current supported target: desktop Web and PC only. Prioritize mouse, keyboard, desktop window resizing and browser text enlargement at 1024, 1280, 1440 and 1920 CSS pixels. Phone-specific implementation and mobile scoring are outside the current product scope. Existing narrow-screen compatibility rules below are historical behavior, not requirements for a separate phone edition. Preserve ordinary desktop window resizing without introducing phone-specific flows.

## Genre and structure

Atmospheric, native productivity workspace with restrained cyber influences. App family: Index-First (overview → searchable resources → contextual details). N13 command search plus grouped persistent navigation; mobile uses a labelled navigation sheet, not nine tiny unlabeled tabs. Footer: a compact live connection status line. Preserve all routes and component ownership.

## Theme

Deep Space Glass: dark indigo is the default appearance, with cyan and ultraviolet accents, layered translucent panels and restrained edge illumination. A browser-local choice supports light/dark/follow system; light mode uses a low-glare daylight interpretation of the same palette. Semantic variables in `webui/hig.css` override existing tokens; existing global CSS is preserved. Data and form surfaces remain nearly opaque and highly readable, while decorative blooms stay behind content. Reduced transparency and increased contrast receive opaque chrome. Semantic success, warning and error colors remain independent of the decorative accents. Action fills use one anchor color rather than a cyan-violet gradient; the violet-cyan blend is reserved for the brand mark. Background blooms remain subdued, and dark selected states use neutral elevation and borders instead of colored halos.

## Typography and geometry

Interface headings, navigation, forms and body share a single platform sans-serif stack: system UI / Apple system / Segoe UI Variable and Segoe UI, with Noto Sans SC, PingFang SC, Microsoft YaHei UI and Noto Sans CJK SC fallbacks for Chinese. The locally bundled Space Grotesk is reserved for the product wordmark and display numbers; system monospace is reserved for code, identifiers and keyboard shortcuts. No external font request is required, and unavailable display fonts do not change the interface heading family.

The public DeepSeek reference informs typography roles only: its DM Sans and Montserrat files are not copied or requested. The adaptation uses local system equivalents, regular 16px body text, medium-weight interface headings, compact supporting roles and more generous desktop gutters. Its marketing-slogan tracking and homepage structure are explicitly not carried into this productivity workspace.

Typography roles in `webui/ui_details.css` distinguish compact controls from sustained reading. At the default browser text size: page titles 30px/500, section titles 20px/500, card titles 17px/500 with 1.5 line height, and dialog titles 22px/500. Body copy and resource prose use 16px with 1.6 line height; actions use 15px/500, controls and labels use 14px, and supporting card copy, dates, timezones and versions use 13px/400 with 1.6 line height. Compact badges and counters may use 12px. Shared roles and field text use rem units to respect browser text preferences. Task/workflow messages and their composers use 16px with a unitless 1.8 line height. Reply headings use 22/20/18/16px according to Markdown depth, with relative paragraph/list spacing and a 72ch reading measure. Short page/dialog headings balance naturally; descriptive copy uses progressive pretty wrapping. Main content is capped at 1440px with 40px desktop gutters and a 32px page-heading rhythm. The existing narrow-window compatibility remains, without creating a separate phone design.

Use regular 400 and medium 500 for interface text and Chinese headings; semibold 600 is reserved for numeric KPIs and inline emphasis. Chinese headings keep normal letter spacing rather than Latin display compression; emphasis does not change text content or semantics. Form hints explicitly use regular weight even inside medium-weight labels. Text uses low-chroma ink and secondary colors in both themes, preserving the indigo surfaces and cyan/violet accents. Counts, dates, versions and timestamps use the interface family with tabular numerals, rather than a code font. Reserve monospace for code, hashes, technical references and individual keyboard keys; keyboard instructions remain ordinary interface copy. Code blocks retain their own scrolling. Four point spacing scale; ordinary fields keep a compact 40px desktop minimum height, 14px text and 8px corners, growing with enlarged text. Conversation composers use the reading scale. Content panels retain 18px corners and dialogs 24px. Primary and secondary actions share a 10px corner radius. First-use resource states may use left-aligned desktop composition with a quiet solid boundary instead of a centered dashed placeholder. Historical evidence: `docs/ui-typography-20261106.md` and `docs/ui-text-roles-20261106.md`.

## Interaction

One primary action per context. Search and filters preserve focus and input method composition. Long Agent configuration has named keyboard accessible sections; resource detail and JSON stay behind disclosure. Empty states guide the next action with real navigation. Explicit business authorization and model sharing consent remain reviewable. Destructive/recoverable actions keep existing confirmation and restore paths. Local preferences never modify task scope.

Feedback: pending labels/disabled controls, inline recoverable errors, visible run states and check results. Support Cmd/Ctrl+K, Escape and predictable tab focus. Refresh must not rebuild an active form or change the current route. Navigation sheet traps focus and makes covered content inert. Focus rings appear immediately.
