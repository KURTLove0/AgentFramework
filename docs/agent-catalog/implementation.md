# 智能体目录按需读取技能资源

2026-10-30，当前源码改进。页面原先通过完整智能体列表刷新目录、任务选择器、工作流候选、每日任务与复盘候选。该列表包含每个智能体已绑定 Skill 的全部冻结文件；每个智能体允许的 Skill 总大小为 512 KB，重复刷新会传输许多当前页面不使用的资源正文。

本轮增加独立的目录读取方式，保留名称、岗位定义、模型、指令、领域、版本、归档状态、绑定信息及固定版本的方法正文，按需读取完整资源。

## 接口与页面

| 接口 | 返回内容 |
| --- | --- |
| `GET /api/agents` | 原有完整配置列表 |
| `GET /api/agents?view=full` | 同上，明确选择完整列表 |
| `GET /api/agents?view=catalog` | 目录配置与固定技能摘要，不含冻结文件正文 |
| `GET /api/agents/{id}` | 单个智能体的完整配置与全部冻结资源 |

目录记录带 `catalog_only: true`，以 `skill_summaries` 替代 `skill_packages`。每项摘要保留原绑定、方法名称、元数据、方法正文及原包摘要，省略 `package.files`。它用于显示与选择，不能当作可校验或执行的完整 Skill 包。没有额外 Skill 时摘要为空数组。其他配置字段与原值一致。

目录通过一条带租户、空间条件的 SQL 投影读取。Python 不解码这些冻结文件；SQLite 仍需读取存储的 JSON 来提取展示内容，不能据此推断磁盘读取量同比下降。没有新增缓存、迁移、分页或删减目录记录；更新时间相同时按 ID 稳定排序。

智能体目录、详情展示、任务候选、保存后的目录刷新、工作流、每日任务与岗位评测、复盘和本体候选，以及命令搜索改用目录视图。搜索仍能匹配绑定的技能名称，详情仍显示智能体所固定的原版本方法；技能库发布新版不会替换这些说明。

打开编辑器继续按 ID 读取完整配置。保存、编译、任务和工作流启动均在服务端读取完整配置，不使用客户端目录摘要作为执行快照。归档、版本冲突、当前 Skill 状态与摘要检查继续由原接受事务处理。

## 性能对比

临时数据库包含 100 个智能体，每个固定 4 个 Skill，每个 Skill 含 48 KiB 参考正文。两种读取在同一数据库交替顺序各运行三次；Python 3.14.3。计时包含查询、Python JSON 解码及规范 JSON 响应序列化，不含构造数据和网络传输。

| 单次列表读取及序列化 | 完整配置 | 目录视图 |
| --- | ---: | ---: |
| 耗时中位数 | 121.900 ms | 28.828 ms |
| 返回字节数 | 20,097,966 | 274,866 |
| Python JSON 解码输入字节数 | 20,088,880 | 261,880 |
| Python JSON 解码次数 | 100 | 200 |
| SELECT 次数 | 1 | 1 |
| 返回智能体数 | 100 | 100 |

该合成负载下约快 **4.2 倍**，目录响应减少约 **98.6%**。目录为每个智能体解码配置及技能摘要两份小 JSON，代替一份包含资源文件的大 JSON。保留字段及全部方法摘要与完整配置的投影逐项相同；结果并非通过减少记录或丢失绑定方法取得。

```bash
.venv/bin/python scripts/benchmark_agents.py --compare
```

脚本仅创建并清理临时数据库，可调整智能体数、绑定数与参考正文大小。原始测量见 [benchmark-20261030.json](benchmark-20261030.json)。这些是本机合成测量，不代表所有配置和部署的端到端耗时。
