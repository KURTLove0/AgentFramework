## 实际证据

独立产品经理 Agent 通过本机 Chrome headless 访问 `http://127.0.0.1:8801` 的临时数据预览，自行创建“独立PM定向评审”和“Multica 产品经理评审”两个工作空间，实际运行 `pm-audit.cjs` 以及仓库的 `tests/verify_multica_agents.cjs`。

现有主要动线回归 15 项通过、24 组布局通过、无未处理脚本错误，输出位于 `baseline/browser-results.json`。该脚本没有覆盖“归档写成功但随后的列表读取失败”以及“右侧箭头进入详情后的返回焦点”，本轮增加的专项审查发现这两处失败，记录在 `initial-audit-results.json`。

## 必须修正

1. **P1：归档成功后的读取失败会展示错误状态。** 注入后续列表 GET 503，实际归档 POST 已成功，按 ID 回读 `archived=true`；详情仍显示“可用”，提供“编辑配置”和“开始任务”，操作恢复为“归档”。用户会将已完成的操作误认为失败，无法直接恢复。`archiveAgent()` 应采纳服务端归档回执；列表同步失败应作为可重试同步问题呈现。修复前属于状态和动作不一致的阻断问题，不可宣布达标。
2. **P2：列表右侧箭头返回后丢失行焦点。** 从 `.agent-col-actions a` 进入详情，点击返回后焦点是 `#content`，没有回到原行。原因是箭头链接没有 ID，`agentListReturn.focus` 为空。给全部详情入口稳定焦点目标，并回归两个入口。
