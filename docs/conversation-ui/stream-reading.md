# 流式回复的阅读连续性

2026-11-04。源码改进，版本保持 1.3.0，尚未发布。

回复仍在生成时，用户可能已经开始选中文字或用键盘查看来源。此前每次追加都会替换整个回复正文，普通段落、列表及表格中的选区会被清空，已聚焦的来源链接也会失焦。长对话还会在每次片段到达时扫描全部轮次的代码与表格阅读状态。

## 当前行为

- 未变化的正文节点保持连接，追加其他内容时保留普通段落、嵌套列表、表格单元格和跨段的选区，包括反向选择。
- 同一文本节点只替换发生变化的字符区间。选区位于未变化前缀时保留原偏移；前文改变时，后缀中的选区随新位置调整。
- 已聚焦的来源链接保留焦点；未变化代码保留复制反馈和选区，表格更新可保留其他单元格选区与横向位置。
- 仅公开进度或预览元数据变化时，不重新解析相同正文。正文变化时，只保存和恢复这份回复的代码、表格阅读状态；历史轮次保持原节点。
- 输入草稿、对话滚动跟随、查找结果和原有复制恢复行为继续工作。

每次真正的正文更新仍执行完整 Markdown 解析，因此后来出现的引用定义、列表或表格结构能正确生效。新树先生成在模板中，再按节点类型与位置更新当前树；类型改变或代码内容、语言改变时替换对应节点。解析器的 HTML 转义、链接协议限制和图片链接策略保持原有规则。

这项保护针对流式就地更新。被删除、改写或转换结构的文本可能不再有原选区。后续源码已补齐任务完成和整页重绘时的普通选区与来源链接恢复，见 [状态变化后的阅读恢复](redraw-reading.md)；下文保留流式更新这一轮的测量和验收记录。没有引入历史分页，也没有省略对话内容。

## 验证与测量

真实 Chromium DOM 新增 **12 项检查**，覆盖段落及后缀偏移、嵌套列表、来源焦点、跨段反向选区、未聚焦代码选区、表格更新、引用和结构变化、代码反馈替换、危险 HTML／URL，以及相同内容零 DOM 修改。在原脚本上 9 项失败、3 项通过；修改后 12 项全部通过。

另新增 **3 项前端回归**，证明进度更新和相同预览文字不重新解析正文，正文变化不再扫描历史阅读状态。三项在原对话脚本上均失败，修改后通过。相关测试 **74 项**及全量前端测试 **1103 项**通过。

真实任务浏览器流程 `reply-markdown`、`task-search`、`task-reply-copy`、`conversation-ui` 全部通过。离线模型通过真实持久化和 SSE 追加片段，新增检查确认用户选择的“轮整理了”保留原文本节点、反向偏移与文字。代码复制、完整回复复制、输入草稿和查找流程继续通过，浏览器异常为零。已目视检查 [深色回复界面](stream-reading-dark.png)。

合成测量使用 160 轮对话，每轮含段落、代码和表格；修改前后顺序运行，各使用 3 个新页面。下表是每组 20 次更新的中位数：

| 更新 | 原实现 | 当前实现 |
| --- | --- | --- |
| 仅进度变化：读取／恢复阅读状态 | 各 3220 次 | 各 0 次 |
| 仅进度变化：Markdown 解析 | 20 次 | 0 次 |
| 仅进度变化：总耗时 | 40.3 ms | 10.7 ms |
| 正文追加：读取／恢复阅读状态 | 各 3220 次 | 各 20 次 |
| 正文追加：Markdown 解析 | 20 次 | 20 次 |
| 正文追加：总耗时 | 37.4 ms | 13.9 ms |

这些是本机合成 DOM 和模拟流式事件的结果，不包含网络、数据库、任务首次打开或真实模型延迟。另一个 200 段正文、30 次尾部更新的检查中，新实现没有移除既有节点，选区始终保留；完整解析仍有成本，不把节点保留等同于免解析。

首次 DOM 验证曾直接比较 HTML 字符串，将属性顺序差异当作内容错误。最终改为浏览器解析后的节点等价比较，同时修正布尔属性序列化差异；没有以放宽用户可见内容或链接检查的方式通过测试。
