# 备份发布与恢复持久性

2026-11-02。当前源码版本保持 1.3.0，已构建隔离候选并验证包内维护命令；未覆盖历史发行包或发布新版本。

## 修正的问题

先用两个回归用例确认了原行为：备份发布没有同步父目录；恢复撤去最后一个保护标记后若发生异常，旧回滚逻辑仍会删除已经恢复的数据库。

文件的 `fsync` 不代表保存文件名的目录项也已经同步。Linux 的 [fsync 接口文档](https://man7.org/linux/man-pages/man2/fsync.2.html) 明确要求对目录单独同步。这个区别也适用于本功能的备份文件名、目标目录及恢复保护标记；不能仅凭数据库文件写入成功就撤去保护。

## 备份发布

创建前检查目标父目录支持同步。备份仍先在临时文件中完整构建、检查清单与数据库完整性，再同步文件内容，通过排他硬链接发布，清理临时名称，最后同步父目录。所有步骤完成后才返回 `valid: true`。

如果文件已经发布而最终目录同步失败，命令返回失败，并说明“备份文件已生成，但未能确认发布完成”。已有文件保留，可以运行 `verify-backup` 检查其当前完整性；重试应使用新文件名，仍不会覆盖同名文件。完整性校验不能代替此前失败的目录同步，也不把不确定状态显示为成功。

## 恢复顺序

| 阶段 | 必须先确认的事实 | 此时中断的处理 |
| --- | --- | --- |
| 创建目标目录前 | 路径保护文件及父目录已经同步 | 即使目标目录尚不存在，也阻止在该路径初始化工作台 |
| 复制数据前 | 目录内恢复标记已经同步 | 保留对未完成目录的启动保护 |
| 完成数据复制 | 两个数据库、恢复回执和目录项已经同步，目标目录名也已同步 | 此后不再执行数据删除回滚 |
| 撤去目录内标记 | 标记删除已同步 | 外层路径保护仍然有效 |
| 撤去外层保护 | 父目录再次同步 | 返回成功，目录可以正常启动 |

完成数据同步之前发生错误，回滚只处理本次创建且身份仍一致的文件。先清除部分文件并同步，再删除目标目录、同步父目录，最后撤去外层保护。清理、同步或目录删除失败时保留保护；发现被替换的文件或目录时，也不会将其当作自己的文件删除。

完成数据同步之后发生错误，保留两个数据库和恢复回执。如果外层保护仍在，启动与只读历史查询都会明确拒绝该路径，可以使用原备份恢复到另一个新目录。如果保护已移除但最后的目录同步报错，完整数据也不会被回滚删除；命令仍返回失败，而不是声称收尾已确认。

源工作台、源备份、任务身份、已保存授权和业务幂等事实不因这些错误被修改。恢复命令本身不调用模型、不启动任务。

## 验证与范围

完整后端回归 **973 项通过**。27 项备份恢复专项通过，包括 10 项新增测试。新增测试覆盖真实目录同步顺序、六个目录同步节点逐一失败、六次子进程强制退出、备份发布状态不确定、文件系统不支持同步、回滚同步失败、保留其他进程的文件、撤去最后保护后异常，以及回滚结束前的同步顺序。原有数据往返、WAL、活跃租约、未知写入核对和命令行测试继续通过。专项还将 Python 数据库资源泄漏警告作为错误检查。

从当前源码构建的 wheel 通过 `pip --no-index --no-deps --target` 安装到临时目录，再从源码目录外执行包内 CLI：创建备份、校验、恢复、启动恢复目录、查看原任务和拒绝覆盖既有目标。两个恢复数据库的完整性检查通过，源数据库摘要不变；没有创建默认数据目录。该检查使用调用方 Python 已有依赖，不等同于全新环境的依赖安装验收。

测试使用本机临时目录，没有操作日常工作台、真实凭据或外部模型。故障测试验证同步边界、返回值和崩溃后的目录状态；未实施真实断电、磁盘固件故障或网络文件系统验收。持久性依赖文件系统和设备兑现同步调用；不支持目录同步时直接失败，不静默降级。
