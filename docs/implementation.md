# MVP 与原方案的对应关系

设计来源：2026-10-21「设计可落地的 Agent 框架」会话；原交付包位于 `/Users/kurt/agent-framework-design-20261021/`，重点采用技术方案第 3、6、8、9、10、13、16 节。此项目运行不依赖该目录。

## 运行路径

1. `submit` 校验任务契约，绑定 Agent/Skill/规划器/验收器快照及内容摘要；建立范围明确的模拟授权。
2. planner 产生六步计划和单步结构化决策。上下文包含角色、硬约束、任务、工作记忆、带来源的观察和未满足验收项。
3. 两类只读工具分别取得变更/服务/依赖/测试信息与发布规范。观察经过结构、范围及标准版本检查后成为持久化证据。
4. 模拟认知端依据能力清单生成风险报告。独立规则验证章节、事实引用、来源哈希、变更版本和风险判定。
5. 网关只接收注册工具，从参数解析实际资源，禁止模型提供幂等身份。参数摘要、前置来源版本、逻辑动作 ID 及 outbox 与检查点同事务持久化。
6. 分发前再读当前授权，持久化 DISPATCHED 后通过固定 Python 子进程调用工具。模拟目标数据库在同一事务中检查来源版本并按唯一幂等键写入。
7. 正常回执只表示 OBSERVED；随后独立 report.read 回读草稿。任务验证比较租户、项目、变更、草稿 ID、状态、版本、全文与哈希。
8. 全部必选检查通过且不存在未决动作，才能写入 SUCCEEDED。终态不再执行工具；经验候选单独标记待审核。

## 持久化与恢复

控制数据库有 runs、events、actions、outbox、evidence、verifications、grants、experience_candidates。所有查询的键包含 tenant_id；关键更新要求租约 owner、epoch、有效期及状态版本一致。

这是同步 outbox 分发器：PREPARED 对应 PENDING，DISPATCHED/UNKNOWN 对应在途，观察或终态后 DONE。恢复从动作表检查写意图，不依赖 planner 的文字记忆。outbox 与动作表同事务更新，可供后续拆成独立队列 dispatcher。

副作用边界分为两个数据库，模拟任意外部业务系统无法加入本地事务的现实。写入后退出时，目标草稿已存在，本地仍可能是 DISPATCHED。恢复优先做只读核对：

| 查询结果 | 恢复决策 |
|---|---|
| 找到草稿 | 补记回执和证据，继续业务验收 |
| 权威查询明确不存在 | 记录 CONFIRMED_NOT_APPLIED，保留原逻辑动作和幂等键，重新授权并有限重试 |
| 查询失败或结果不可信 | 有限次数核对；转 NEEDS_REVIEW，记录残留影响，停止创建 |

延续同一运行时复用幂等键；用户重新提交视作新任务，可以创建新草稿。MVP 不对跨任务业务去重作隐含承诺。SHA-256 快照摘要用于发现内容变化，不代替发布签名或访问控制。

## 替换模拟组件

- **真实认知端**：已有 `LLMPlanner` 实现 `Planner.plan/decide/compose`，通过本机 Codex CLI 登录态调用模型，将封闭 Schema 输出解析为 `Decision` 和 `ActionProposal`。其他提供方可以实现相同 transport 端口。模型不能直接访问业务工具；上下文中的观察内容属于数据，不可提升为运行时指令。
- **业务工具**：保留 Gateway 校验与授权链路，替换 worker 的固定适配器；注册输入/输出 schema、实际资源解析、超时、幂等域、条件写及核对语义。目标缺少可靠查询时必须保留 UNKNOWN，而不能把普通 404 假定为权威未发生。
- **IAM**：从已认证服务端身份构建租户和主体，替换本地模拟 grant 表；执行时检查当前政策版本、撤销及有效期。仍需将具体授权绑定到运行、参数摘要、资源与前置条件。
- **生产持久化**：将 Store 接口迁移到 PostgreSQL，引入服务端租约、RLS、独立 outbox dispatcher 和审计保留策略。旧 worker 的在途外部请求仍需依赖目标端幂等/条件写，本地 fencing 无法撤回已发出的网络请求。

当前版本有意保留单角色与小型显式状态机，先验证一个完整闭环；未实施多 Agent、自动经验晋升、在线自我修改和微服务拆分。

## 模型接入后的额外持久化约束

模型名称、推理强度、超时与格式修正次数、提示词哈希和 Schema 哈希随运行冻结。重启时由快照恢复适配器；授权仍按当前 grant 判断。调用用量在每次请求/响应时持久化，模型不可修改本地预算。

长模型调用期间后台线程续租，与状态检查点共用锁，避免同一 worker 的版本比较产生竞态。模型调用结束后重新确认租约与截止时间。模型输出未应用前，即使超时或 worker 失去租约，也不会分发业务动作。

PREPARED 意图优先于新认知决策。DISPATCHED/UNKNOWN 写入恢复只运行确定性 reconcile；模型不会被请求重新生成创建参数。由此，随机规划输出不会改变已经固定的幂等写入身份。

客观回读校验在观察保存后立即执行。模型看到内容不一致后可能请求补充输入，但这不能绕过或延后验证；不一致直接进入 NEEDS_REVIEW。恢复历史 WAITING_INPUT 检查点时，若已有失败的外部回读，也会先执行该独立检查，不再调用模型。草稿统计依据目标系统中可信的幂等键，而非模型填写的报告归属字段。

结构化输出依据 [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)；CLI 的 `--output-schema` 与非交互调用依据 [Codex non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)。本地校验器只支持项目 Schema 使用的封闭词汇，不声称实现完整 JSON Schema 标准。
