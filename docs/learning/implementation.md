# 运行复盘、四类沉淀与领域本体

> 本文保留初版实现与验收记录。当前岗位评测契约和业务对象本体扩展见 [岗位评测与 Ontology 优化](../ontology-v2/implementation.md)。

当前源码新增此功能；已生成的 1.2.0 安装包保持不变，尚未重新打包。启动源码工作台：

```sh
sh scripts/start.sh
```

打开 <http://127.0.0.1:8787>。默认工作台保持空白，验收只在独立临时目录进行。

## 运行记录 → Agent 复盘 → 审阅 → 沉淀

1. 在运行记录列表点击“复盘”，或在详情点击“复盘与沉淀”。运行应已暂停或结束；执行中的任务需先等待。
2. 选择当前工作空间的 Agent，查看将发送的来源，填写复盘要求。离线 Agent 可演示流程；Codex/Cursor Agent 复用本机 CLI 配置。真实模型必须明确勾选模拟上下文许可。
3. Agent 按封闭 Schema 返回总结与分类建议。运行结果、验收通过数和总数由原始事实固定，引用只能来自本次来源；模型没有 MCP 或业务工具执行通道。
4. 逐条编辑标题、分类、正文、依据和限制，勾选要保留的条目，再确认沉淀。全部条目与回执在一个事务内保存，重复确认返回相同回执，不重复创建。
5. 从回执进入对应知识库模块，分别审阅、评测和发布。复盘不恢复、不授权、不修改原任务，也不会重新执行它的写入。

| 分类 | 保存结果 | 生效方式 |
|---|---|---|
| 知识 | 私有知识草稿，含来源、版本、Agent 和审阅人 | 审核发布后按授权范围检索 |
| 记忆 | 工作记忆草稿，区别于偏好与自动情节归档 | 始终本人可见，审核发布后作为历史指导 |
| 经验 | 已归档运行的经验候选 | 现有隔离回放和反例评测通过后，人工审核发布 |
| 能力 | 能力方法草稿，描述输入、步骤、输出与验收 | 发布后可作为指导，也可导出标准 Skill ZIP，在 Skills 中导入、发布，再绑定 Agent 的固定版本 |

能力方法不会注册新执行器或扩大工具权限。经验评测验证的是已登记模拟执行规则与来源一致性，不能证明全部自然语言建议都正确。文字总结和归纳仍需人工审阅。

生成请求以请求标识持久化，区分生成中、草稿、失败和已沉淀。模型结果未知时不会自动重放；可核对已有记录。审阅采用版本检查，沉淀前再次核对原运行事实和来源。服务重启后保留提案、编辑版本和回执；中断的模型生成不能声称完成，可明确发起新请求。未保存的表单输入不跨刷新保留。

## 知识库 → 本体 Ontology

“本体 Ontology”是独立的知识库模块。可选择 1–12 份当前有效、已发布的知识、记忆、经验或能力方法，由 Agent 生成：

- 概念：名称、定义、别名和来源。
- 属性：名称、说明与 string、number、boolean、date 类型。
- 关系：上下位、组成部分、相关、依赖、产出与验证。

页面同时提供关系图和表单，可添加/删除概念、属性及关系。每个概念/关系均需引用选定来源；后台拒绝未知端点、自环、重复标识、重复关系、层级循环与相冲突的层级/关联关系。最多 40 个概念、每概念 12 个属性及 80 条关系。

生成结果先保存为私有本体草稿，审核后才发布。修订创建新版本，旧版和审计保留；发布前重新检查来源状态、有效期与哈希。来源失效的本体仍可追溯，但停止参与检索。

已发布本体可按概念/别名匹配，并沿一跳关系找出关联的已授权来源，扩展现有知识检索。它只影响资料发现，不修改任务范围、工具权限、关键标准或独立验收。

支持 JSON-LD 导出。概念、标签、定义、别名和上位/关联关系采用 [W3C SKOS](https://www.w3.org/TR/skos-primer/) 词汇；其他业务关系和属性使用应用自己的命名空间。这是轻量领域概念模型，不是完整 OWL 推理器；不包含自动逻辑证明、图数据库或跨系统本体对齐。

## 范围与数据

生成内容保留来源哈希、Agent 版本、模型用量和确认回执。仅本人当前工作空间的运行可复盘；资料和本体继续受租户、项目、环境与主体隔离。私有记忆不会被其他主体的查询或本体生成读到。

业务工具仍为模拟实现。真实模型联调只发送隔离环境的固定模拟证据和 Schema，不读取仓库源码、凭据或其他业务空间的资料。正式数据目录不写入演示任务或知识。

相关代码：`learning.py`（Agent 生成与事务沉淀）、`ontology.py`（本体校验、检索扩展和导出）、`webui/learning.js`（审阅与本体编辑）、`knowledge.py`/`knowledge_hub.py`（四类资产）、`context_builder.py`/`llm.py`（已发布指导的受控上下文）。

## 验收记录

209 项 Python 回归（其中新增复盘/本体测试 25 项）与 134 项 Node 前端检查全部通过。Node 检查使用模拟 DOM/API，另外执行了真实浏览器交互与 20 组浅深色响应式表单检查，覆盖 320、375、768、1280 与横屏 812 像素宽度。

真实 Codex Agent 在固定模拟上下文中分别生成四类复盘建议及包含 7 个概念、15 个属性、7 条关系的本体。人工修订、沉淀、审核、发布与标准 Skill 导出均在页面完成。复盘经验通过离线评测后仍等待明确发布。

重启服务后，重复确认返回同一沉淀回执，资产和原运行草稿均未重复创建。一个仅存在于本体的别名成功支持知识问答并通过全部验收；撤回来源后，该别名零命中，新问答进入 `WAITING_INPUT`。完整记录见 [验收汇总](verification.json)、[四类沉淀](four-module-verification.json)、[重启与幂等](runtime-verification.json) 和 [本体 RAG](ontology-rag.json)。
