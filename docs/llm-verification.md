成功场景的三个必选验收项全部通过。恢复场景保留 `action.reconciling` 和 `action.effect_confirmed` 审计事件，外部创建始终只有一次。对这些运行再次 resume，外部草稿和调用计数未增加，也未增加模型请求。

权限场景最初在 WAITING_AUTH 停止，未调用 create。稍后的重复检查已超过该任务 600 秒绝对期限，状态按规则变为 EXPIRED；外部草稿与创建调用仍为零。汇总同时保留验证时状态与当前状态。

## 联调发现并修复的问题

真实模型在发现草稿内容不一致后，曾选择 request_input。原流程只在 request_finish 时执行完整任务验收，导致该任务停在 WAITING_INPUT，客观回读校验被推迟。

修复后，普通回读和 UNKNOWN 核对都在保存外部证据后立即执行客观校验。内容不一致直接进入 NEEDS_REVIEW，不再征询模型。历史 WAITING_INPUT 检查点也会优先复核已有回读。该历史运行已在不增加模型请求、不重复创建草稿的情况下正确进入 NEEDS_REVIEW；全新真实模型场景复跑同样通过。

另将草稿数量统计改为依据运行时生成的目标系统幂等键，并独立检查报告的 task_ref，避免模型伪造报告元数据干扰归属与重复创建检查。
