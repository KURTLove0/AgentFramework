## 主要差距与优先级

1. **P1，目录信息过重，不能快速比较。** `agent_framework/webui/agents.js:46` 的 `agentCard()` 将身份、用途、领域/运行时/版本、职责与标准计数、Skill与岗位摘要、模型配置披露、执行/编辑/编译/评测/复制/归档并置于每张卡。`styles.css:1647` 使用两列卡片，`hig.css:211` 又强化独立卡片操作区。浏览器仍需确认高度和实际首屏密度。参考 Multica 的 `agents-page.tsx:85`、`:470`、`:1125` 使用可比较列式列表及独立行导航。

2. **P1，缺独立详情与可恢复阅读上下文。** `app.js:64` 的路由解析只为 workbench/runs/workflows/evaluations 保留记录 id，agents 只能进入目录；`agents.js:48` 的名称是静态 h2，读详情必须在卡片内逐个展开，编辑则直接打开三步表单。D1 目前缺失，D2/D5受限。建议添加 `#/agents/:id`，将概览、指令、技能与配置、实际运行/评测的阅读与编辑分开，保持开始任务入口明显。

3. **P2，缺排序，结果视角不够明确。** `filteredAgents()`（`agents.js:37`）只过滤状态、领域和查询，不排序。`agentsPage()`（`:59`）将状态放在下拉框且未区分主要生命周期视角。参考 `agent-list-toolbar.tsx:76`、`:190` 用 scope 与计数组织目录，并提供排序/筛选。此项目可采用全部/可用/归档与真实领域，不照搬没有事实支撑的 mine、online、owner 或运行数。

4. **保留并复验已有完整动线。** `agentConfigSections` 和 `initAgentFormLayout()` 将创建分成三步；`saveAgent()` 含防重复、配置快照与保存后通知；`agent_experience.js:21` 的 `agentSavedNotice()` 可直接开始任务。`tests/verify_agent_ux_browser.cjs` 已描述输入保留、失败重试、任务配置往返、权限重新审查等案例。改版不应牺牲这些能力。
