# 每日任务与岗位评测

> 本文保留初版实现与验收记录。当前岗位评测契约和业务对象本体扩展见 [岗位评测与 Ontology 优化](../ontology-v2/implementation.md)。

2026-10-23，源码增量。业务执行沿用两个已登记领域与模拟工具，现有 1.2.0 安装包未重建。

## 每日任务

启动工作台后打开“每日任务”（`#/daily`），点击“计划设置”：

1. 选择每日执行时间和 IANA 时区，默认 `Asia/Shanghai 09:00`。定时开关默认关闭。
2. 添加每日任务模板：选择空间内 Agent 的固定版本，填写目标和对象标识。初始目标取该岗位的职责说明；最多 16 项。
3. 按任务选择草稿写入、真实模型上下文发送及受控 MCP 读取许可。默认均未授予，修改目标、对象或 Agent 后重新确认许可。真实模型任务未许可发送上下文、所需受控 MCP 未许可时禁止保存。
4. 开启定时汇总与派发，可选择“派发后自动启动”。未选中时任务进入工作台待启动。
5. 也可以手动“生成今日计划”，审查待办汇总、可派发项、阻塞项和避免重复项，再点击“派发今日任务”。生成预览不会启动任务。

每日汇总根据当前空间的真实运行记录和配置模板生成，列出生成时的待办状态、职责映射、历史数量以及每项可执行性。可执行性检查包含 Agent 状态、固定版本、岗位编译、Skill 可用性和许可。目标与对象由模板明确指定，系统不会编造新的业务对象。

定时器随本机 Web 服务启动，每 15 秒检查一次。需要保持服务运行，操作系统睡眠或服务退出期间不会执行；恢复后只补当前时区的当日计划，不重放遗漏的全部日期。删除空间后停止为其派发，配置与历史保留，恢复后可继续使用。

同一租户、工作空间、主体、当地日期只保存一份计划。数据库短租约串行派发，每项任务绑定稳定运行 ID。提交后、关联计划前发生进程退出，重试会找回同一运行；不会再次创建。生成时和派发前都会检查相同 Agent、目标和对象的未完成任务，优先处理原待办。自动启动可恢复租约已释放的执行中任务；等待授权、等待材料和终态任务不会被自动推进。

计划保留配置版本、任务模板和 Agent 版本。编辑 Agent 后，尚未派发的旧版本模板会阻塞；需重新选择版本保存。修改计划配置后，无已提交任务的预览可以重新生成；已经派发过任务的当日计划保持冻结，新配置用于次日。停止定时开关会停止后续自动派发。

后台派发仍使用现有任务创建入口、网关、预算、授权、幂等核对和独立验收。未允许草稿写入的变更任务会等待具体授权；只读任务没有业务写入。

## 岗位评测与提醒

打开“岗位评测”（`#/evaluations`），也可从 Agent 卡片“执行评测”进入该岗位的历史。

任务进入 `SUCCEEDED`、`FAILED`、`EXPIRED`、`NEEDS_REVIEW` 或 `CANCELLED` 时，在终态检查点的同一事务内记录评测与未达标提醒，CLI、工作流和 Web 执行共用此路径。等待授权、等待材料及执行中的任务不作失败评分。人工取消保存为“不计分”，不进入均分或触发提醒。

评测读取本次运行**冻结**的岗位定义、标准检查映射、任务验收、快照摘要和证据引用。后来编辑 Agent 不改写历史评测。规则版本为 `job-history@1.0.0`：

| 维度 | 满分 | 计算依据 |
| --- | ---: | --- |
| 身份一致性 | 10 | 任务岗位引用与冻结编译岗位一致，名称、角色、团队齐全 |
| 职责履行 | 35 | 各项职责映射的验收全部通过才算履行，按职责比例计分 |
| 标准达成 | 35 | 冻结标准映射的去重验收项通过比例 |
| 任务交付 | 20 | 任务状态为 `SUCCEEDED` |

默认基础阈值 80 分，历史窗口 30 天。阈值可设为 1–100，历史窗口为 1–365 天，可暂停自动评测。总分低于阈值，或任一必选验收未通过/缺失、身份无法核对、职责/标准映射缺失、任务未交付，均产生站内提醒。因此总分超过阈值也不会掩盖基础验收失败。

“评测执行历史”可补评窗口内已有终态任务；规则或配置版本变化后会生成新报告，保留旧报告和提醒。旧版未冻结岗位映射的运行会明确提示人工复核。报告带运行 ID、Agent 版本、规则版本、阈值、维度分数、逐项原因、职责/交付物和证据引用。窗口内每次运行取最近评测后计算岗位均分，界面最多展示最近 200 条执行评测。

相同运行、相同评测输入重复评测不会新增报告或重复提醒。任务工作台、导航数量及评测页面显示未确认提醒；“确认已阅”只记录阅读时间，保留失败结论。提醒中的“查看此提醒的评测记录”可查阅当时规则与阈值，后续改分不影响该记录。没有发送邮件或其他外部消息。

这是基于已登记验收规则的客观评测，不对自由文本职责做额外语义推断。故障注入导致的失败也按实际未达标记录，报告不把系统故障直接归因为模型能力不足。

## 持久化与接口

新增 `workspace_schedules`、`workspace_daily_plans`、`evaluation_policies`、`agent_evaluations`、`agent_alerts` 表，均为加法建表，不修改已有任务快照。配置和操作受当前租户、工作空间、执行主体约束，写请求继续要求同源和页面令牌。配置保存检查 `revision`，冲突返回 409。

| 方法 | 接口 | 用途 |
| --- | --- | --- |
| GET / POST | `/api/workspace-schedule` | 读取配置、最近 60 日计划与下一时间 / 保存配置 |
| POST | `/api/daily-plans/generate` | 生成当前当地日期的计划 |
| POST | `/api/daily-plans/{id}/dispatch` | 派发或核对同一计划 |
| GET | `/api/agent-evaluations` | 读取窗口评分、最近报告和提醒 |
| GET | `/api/agent-evaluations/{id}` | 读取原始评测报告，含旧规则版本 |
| POST | `/api/agent-evaluations/evaluate` | `{}` 补评窗口历史，或 `{ "run_id": "..." }` 评测单次执行 |
| POST | `/api/evaluation-policy` | 保存阈值、窗口和自动开关 |
| POST | `/api/agent-alerts/{id}/acknowledge` | 确认已阅 |
| GET | `/api/operation-status` | 当前空间未确认提醒数 |

## 验证

- 全量 Python 回归 **226 项通过**；包含 17 项新增测试，覆盖日期/时区、关闭与删除、版本冲突、重复派发、跨进程并发、提交后关联前中断、预览后的重复检查、运行恢复、授权等待、冻结岗位、基础验收失败、历史补评、取消排除以及租户/空间/主体隔离。见 [Python 测试日志](python-tests.log)。
- 新增 **8 项界面交互检查**，覆盖内容转义、旧计划冻结、范围变更许可重置、延迟响应跨路由/空间、重复提交、保存中关闭保护及冻结岗位显示。见 [界面检查日志](ui-tests.log)。
- 浏览器实际完成配置 → 生成 → 派发 → 自动运行 → 评分流程。正常任务 **100 分**；草稿内容被篡改的运行 **50.83 分**并生成提醒，确认后未处理数量从 1 变为 0。
- 375、768、1440 像素的每日任务与评测页无横向溢出、无页面脚本错误；另验证手机设置页和深色评测页。见 [浏览器验收记录](browser-verification.json) 与 [后台实际触发及追溯验收](live-verification.json)。
