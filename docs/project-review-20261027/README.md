# 任务执行与跨模块动线核查

本次源码核查遵循现有工作台设计，重点是让普通任务按用户目标执行，并让每日任务、工作流和复盘采用同样的执行语义。

## 结果

- 普通任务直接调用模型执行，不要求生成计划、检索回读、引用回答、独立验收的固定模型链路。必要的结果完整性与来源检查由本地执行器完成。
- 任务页按实际运行事件展示公开摘要、工具活动、连续生成的正文和最终结果。同一任务可继续提问、补充和修改；排队、取消、重试及草稿恢复均保留。
- 新建每日任务模板只需目标与固定版本的智能体。待启动任务有明确的开始入口；运行中的后续对话也参与去重，避免重复派发。
- 通用工作流不预填变更演示编号、业务目标或写入授权。节点目标可自由填写，正文条件支持“包含／不包含”，检索只检查有效已发布知识。
- 工作流节点收到补充回答后自动继续，并传递最新结果。后续节点的补充轮次保留上游输入；已经采用的产物固定在实际输出轮次，后续讨论不会改写已完成流程。
- 复盘读取任务最新结果，普通任务经验可经明确审阅沉淀。经验检查使用结果结构和来源的正反例，不重放历史写入或套用变更评估流程。
- 空工作台、任务列表、能力与标准、运行时设置和帮助文案均按实际配置显示。处理领域筛选使用当前空间的真实领域；手机可查看任务属性和导出完整对话。

## 核查范围与证据

工作台、运行记录、每日任务、岗位评测、智能体、工作流、Skills、处理领域、知识库、能力与标准、运行时、工作空间共 12 个模块。沿用既有颜色、字体与导航，没有引入新主题。

| 检查 | 结果 |
| --- | --- |
| 完整 Python 回归 | 335 项通过 |
| 新增跨模块重点回归 | 7 项通过，包含后续输入与已采用产物的固定行为 |
| JavaScript 交互回归 | 51 组通过 |
| 浏览器持续输出 | 9 项通过：摘要和正文增长、刷新、重连、停止、失败片段及安全显示 |
| 浏览器持续对话 | 12 项通过：中文输入、草稿、滚动位置、排队、取消、追问、重试、导出等 |
| 浏览器跨模块动线 | 8 项通过：每日任务、复盘、知识修订、Skills、工作流等 |
| 布局矩阵 | 12 模块 × 5 宽度 × 2 主题，共 120 次页面检查，无页面横向溢出 |
| 原有工作台 | 重启后只读验证；两条原有任务的状态与内容摘要均保持一致 |

## 重现方式

后端使用 `python -m unittest discover -s tests`，跨模块重点使用 `python -m unittest discover -s tests -p test_project_journeys.py`。前端交互使用 `node --test tests/test_*interactions.js tests/test_ui_session.js`。

浏览器验证需要本机 Chromium/Chrome 和 Playwright。分别启动以下临时服务并设置对应 URL，运行同名验证脚本：

| 临时服务 | 验证脚本 | URL 环境变量 |
| --- | --- | --- |
| `python -m tests.serve_project_review_fixture` | `tests/verify_project_journeys.cjs` | `PROJECT_REVIEW_URL` |
| `python -m tests.serve_streaming_task_fixture` | `tests/verify_streaming_tasks.cjs` | `TASK_STREAM_URL` |
| `python -m tests.serve_model_execution_fixture` | `tests/verify_task_conversations.cjs` | `TASK_CHAT_TEST_URL` |

服务默认端口为 8799；并行执行时可分别设置 `PROJECT_REVIEW_PORT`、`TASK_STREAM_PORT`、`TASK_CHAT_PORT`。验证地址仅指向临时服务。

## 验证边界

公开思考摘要取决于运行时是否提供；不展示隐藏推理，也不补造思考过程。浏览器检查覆盖上述实际动线和页面布局，不能代替所有真实模型、账号和外部服务的集成验证。旧业务任务继续保留授权、回读与恢复语义。已发布的 1.2.0 安装包没有在本次重新构建。
