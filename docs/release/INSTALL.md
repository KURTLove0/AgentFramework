# Agent Framework 1.2.0 安装与运行

本版本是单用户 Agent 工作台，包含岗位配置、标准 Skills、知识/记忆/经验管理、可视化 Agent 工作流，以及规划、授权、验收与持久化恢复。

**业务工具仍为模拟实现，只支持 test 范围。** 本发布不包含真实业务连接器、多人身份认证或公网服务。模型可使用运行机器自己的 Codex/Cursor CLI 登录态；登录凭据不包含在安装包中。模型请求需要在界面确认上下文发送许可。

## 安装

需要 macOS/Linux、Python 3.11+（含 venv/pip）和首次安装时访问 Python 包索引的网络。无需 Node 或独立数据库。安装包依赖固定为 PyYAML 6.0.3。

```sh
tar -xzf agent-framework-1.2.0.tar.gz
cd agent-framework-1.2.0
# macOS：shasum -a 256 -c SHA256SUMS
# Linux：sha256sum -c SHA256SUMS
sh scripts/install.sh
sh scripts/start.sh
```

打开 http://127.0.0.1:8787。首次启动只有一个待配置的默认工作空间和两个系统内置 Skill；没有测试任务、草稿、自定义 Agent、工作流、知识、记忆或经验。

启动脚本不运行 demo、不刷新模型目录、不调用模型。可在界面创建工作空间、Agent 和工作流，再选择运行时。所有演示任务都必须由使用者主动启动。

可使用单独的外部数据目录，升级时保持目录、租户和执行主体不变：

```sh
AGENT_DATA_DIR=/absolute/path/agent-data \
AGENT_TENANT=local AGENT_PRINCIPAL=local-user AGENT_PORT=8787 \
sh scripts/start.sh
```

默认分别为安装目录下的 `.agent-data`、`local`、`local-user`、`8787`。`AGENT_VENV_DIR` 可用绝对路径指定虚拟环境。`PYTHON` 可在安装时指定 Python 可执行文件。

## 使用服务器

在服务器解压、安装，用独立的普通用户启动。服务保持监听服务器的 `127.0.0.1:8787`；本机通过 SSH 转发访问：

```sh
ssh -N -L 8787:127.0.0.1:8787 your-ssh-host
```

本机打开 http://127.0.0.1:8787。若本机端口已占用，先停用占用该端口的本地工作台。当前 Host/Origin 校验要求转发前后的访问端口一致；不要直接绑定公网或仅用域名反向代理替代身份认证。域名与多人访问需要另行实现认证及受信入口。

真实模型需要在服务器上另行安装并登录 CLI；不会继承开发电脑的登录态，不要复制开发电脑的凭据。当前许可仅覆盖模拟任务及模拟证据，不应向模型发送未获授权的真实资料。

## 重启、升级、回退

1. 停止接收新任务，确认工作台无活跃任务，按 Ctrl+C 停止服务。
2. 同时备份整个数据目录（包括两个 SQLite 库和可能存在的 WAL 文件）。不要仅备份运行库，否则会丢失外部草稿与幂等核对事实。
3. 将新版本解压到新目录，安装后指向相同的外部数据目录、租户与主体启动。已有任务保持冻结的岗位、Skill、提示词和能力契约；不要新建任务来替代未决写入恢复。
4. 回退时停止服务，使用对应版本及其完整的数据备份启动。不要将新旧运行库和模拟业务库交叉组合。

测试/验收请使用另一个数据目录。源代码仓库中的 tests、examples 与 docs 验收证据作为开发资料保留；正式安装包不含这些资料、旧数据库、日志、模型载荷或本机凭据。
