## 验收覆盖

原校验器只证明首次启动后的读写可用。`scripts/verify_release.py` 现在使用归档内的真实安装和启动脚本，在同一个临时外部数据目录完成以下过程：

1. 在干净虚拟环境中离线安装候选包及固定版本 PyYAML，检查全部应用模块来自该环境、初始工作台没有用户记录，页面引用的脚本、样式和字体与 wheel 字节一致。
2. 保存两版运行配置，包含 `ultra` 和正小数超时；创建模拟 Agent、普通任务及模拟业务任务。等待两项任务完成，确认业务流程只产生一份模拟外部草稿，并用安装后的 CLI 校验导出文件。
3. 普通任务清理其已确认的草稿后，另存一份独立草稿。正常关闭服务，确认旧进程退出，使用相同数据目录重启；要求服务会话更新、工作空间 ID 不变。
4. 先读取并比较新配置、第一版配置的不可变回执、Agent、任务完整执行状态、模拟外部结果和独立草稿。随后重放旧的配置、Agent、任务请求，再读取实际状态，确认最新配置仍为 v2、任务仍为两条、外部草稿仍为一份，独立草稿没有被旧提交清理。
5. 明确删除独立草稿后，再执行一次正常重启和相同检查。删除后的空草稿及 v4 版本必须保留，旧请求重放不能复活或重置草稿。
6. 可选浏览器验收在第二次重启后的安装服务上执行，覆盖丢失回执、配置冲突、页面刷新恢复和迟到请求。

关闭超时会终止并回收测试进程，但此次重启验收失败，不会被记作正常重启。校验器先检查持久数据，再核对重放响应，最后重新检查实际数据，避免只凭正确形状的响应判定通过。

## 复现

依赖准备与离线验收分开执行；报告路径必须尚不存在：

```sh
.venv/bin/python -m pip download --only-binary=:all: --no-deps \
  --dest /tmp/agent-wheelhouse PyYAML==6.0.3
.venv/bin/python scripts/verify_release.py \
  /private/tmp/af-runtime-values-source-candidate-20261103/agent-framework-1.3.0.tar.gz \
  --wheelhouse /tmp/agent-wheelhouse \
  --report /tmp/agent-installed-restart.json --browser-check
.venv/bin/python -m unittest tests.test_release_delivery -q
```

测试只使用临时数据库和模拟运行时；服务退出后清理临时安装与数据库。浏览器结果和报告保留在指定输出目录。无需真实模型调用。
