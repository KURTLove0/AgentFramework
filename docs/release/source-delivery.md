# 当前源码的安装与交付验收

初始记录：2026-10-30。当前源码改进，历史发行产物保持原样。2026-11-04 已为最新源码候选补充全新安装和两次真实进程重启验收，见 [安装后重启与数据恢复](restart-delivery.md)。两轮均没有发布新的正式版本。

## 修复的问题

启动脚本此前会从调用方当前目录和 `PYTHONPATH` 查找 Python 包。即使虚拟环境中已经安装了正确版本，在另一份项目旁启动也可能加载那里的同名代码。安装器创建环境和运行 pip、内置工具子进程及受控读取代理也存在环境干扰。

原校验脚本直接运行 Python 并复用宿主依赖，没有实际执行包中的安装与启动脚本，也只检查四个固定页面资源。因此它不能证明完整安装链路及新增页面资源可用。

新增回归先使用临时同名模块复现了这些情况。修正后，安装和启动脚本使用 Python 隔离模式。内置工具与评测子进程显式使用父进程实际代码位置，既忽略调用方目录和 Python 环境变量，也保留未安装源码树的显式调用方式。受控读取代理继续使用自己的绝对文件位置。

## 构建候选包

正式输出默认仍为 `dist/`，不会替换已有同版本产物。验证尚未发布的当前源码时，使用独立输出目录：

```sh
python scripts/build_release.py --output-dir /tmp/agent-source-candidate
```

构建按当前保存的文件收录全部模块，包括尚未提交 Git 的新增模块。页面资源必须在包元数据中声明；符号链接、特殊文件及未登记的包内数据会被拒绝。运行数据库、日志、缓存和仓库外的本机文件不进入包。

构建使用独立源码快照，并逐文件核对 wheel 与快照；源代码在复制或构建期间变化时拒绝提交本次结果。输出目录有进程锁，避免两个构建相互覆盖。每个产物先写完整、刷新文件，再独占发布；校验和清单原子更新。文件已存在时不会替换，失败的临时复制不会留下半个可见产物。

锁在进程退出后释放。多个文件的发布不构成单个文件系统事务；进程在两个产物发布之间退出时，可能留下已完成的单个产物。此时同版本构建仍拒绝覆盖，应核对已有文件，或使用另一个候选输出目录重新构建。

候选清单包含来源标记 `built_from: saved-working-tree` 及逐文件摘要。版本号沿用源码声明；它是验收快照，不能当作同名历史正式产物，也不应直接覆盖已发布文件或在旧虚拟环境中冒充版本升级。

## 全新环境离线安装验收

先为运行验收的 Python 准备对应平台的固定依赖 wheel；下载是独立步骤，验收过程本身不访问包索引：

```sh
python -m pip download --only-binary=:all: --no-deps \
  --dest /tmp/agent-wheelhouse PyYAML==6.0.3

python scripts/verify_release.py \
  /tmp/agent-source-candidate/agent-framework-1.3.0.tar.gz \
  --wheelhouse /tmp/agent-wheelhouse \
  --report /tmp/agent-source-verification.json
```

校验器的构建与脚本启动范围为现有 macOS/Linux 安装流程。它会：

1. 检查归档路径、文件类型、重复项、大小预算、完整校验和清单，以及 wheel 和源码清单的一致性。不能用外层校验和掩盖错误的源码摘要。
2. 创建没有宿主依赖的全新虚拟环境，运行归档内真实的 `install.sh` 和 `start.sh`。调用目录和 Python 环境中放入合成同名模块，确认它们没有被执行。
3. 检查全部应用模块及 PyYAML 均来自该虚拟环境，确认初始工作台没有用户 Agent、工作流或任务。
4. 从实际 HTML 和 CSS 发现本机脚本、样式及字体资源，逐文件比较服务端返回字节与 wheel，而不是只检查几个固定文件。
5. 创建合成 Agent 并重放保存回执，创建任务并重放提交、查回原记录；执行完整模拟业务流程，核对唯一草稿；使用安装后的 CLI 校验导出 ZIP。
6. 在同一外部数据目录连续完成两次正常关闭与重新启动。分别保留独立任务草稿及删除后的版本，读取配置、Agent、任务结果和原请求回执，再重放旧请求并重新读取实际状态，确认新配置没有回退、任务和模拟写入没有重复。每次重启必须出现新的服务会话并保留原工作空间；强制终止不能算作成功的正常重启。
7. 停止原服务，使用安装后的 CLI 备份、检查内容摘要并恢复到新目录。确认原数据库摘要不变，重复恢复不会覆盖已有目标；从恢复目录启动服务，再核对配置、草稿删除版本、任务历史及回执重放。详细结果见 [备份内容核对与恢复验收](../data-protection/backup-contents.md)。

测试全部使用临时数据和模拟执行，不读取已有业务数据库，不调用真实模型。校验结束后停止服务并清理安装环境与临时数据库。

若开发机有 Node、Playwright 和 Chrome，可增加 `--browser-check`。浏览器连接上述真实安装且已恢复数据的服务，验收回执丢失、配置冲突、刷新恢复和迟到提交，并验证 200% 文字时的恢复入口。报告及截图保存在报告文件旁的新目录中。

独立 wheel 也可以作为位置参数；这种模式验证 wheel 配合当前源码中的安装/启动脚本，报告范围为 `wheel-with-current-source-launchers`。归档模式验证归档自己的脚本，范围为 `bundled-install-and-start-scripts`，两者会明确区分。报告文件不可覆盖。
