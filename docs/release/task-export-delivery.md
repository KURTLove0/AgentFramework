# 多轮任务导出的安装后验收

2026-11-04。将导出窗口的键盘修复纳入独立候选包，并把多轮导出接入安装校验器。版本仍为 1.3.0，尚未发布。

## 新增覆盖

`scripts/verify_release.py --browser-check` 现在运行七组流程：提交回执恢复、首次任务准备、任务名称、归档、收藏、多轮导出和消息草稿。全部浏览器检查连接备份恢复后的安装服务。

导出用例通过公开 HTTP API 创建独立工作空间、mock 智能体及两项任务。第一项任务完成后追加一轮，实际执行完成后设置名称并归档；第二项用于切换任务。共创建三个执行记录，没有直接改数据库、导入开发目录应用模块或使用专用的队列释放接口。两轮内容包含中文、英文、换行、代码围栏、表情和较长补充文字。

浏览器从“任务信息”打开导出窗口，实际保存 ZIP、JSON 和 Markdown。每个文件与该次 `fetch` 响应的副本逐字节比较，并核对已保存的各轮完整要求、回复、状态、名称、归档和快照版本。ZIP 使用安装虚拟环境中的 CLI 校验，还验证其两个执行记录与对话对应。校验进程使用隔离启动参数，并确认应用模块来自安装环境，避免误用开发目录中的同名代码。

完整流程同时验证：

- 准备期间保留键盘焦点，重复 Enter／空格不重发；用户移到关闭按钮后，成功或失败均保留其焦点。
- 503 显示原因，错误任务编号的 JSON 被拒绝，明确重试按原格式成功下载。
- 切换任务后，受控传输即使忽略取消并迟到返回，也不能下载旧文件或改变新窗口焦点。
- 安装后的 CLI 接受完整包，拒绝内容被改动但清单未更新的副本。
- 下载与恢复没有浏览器写请求，不修改历史、名称、归档，返回原任务时保留未发送草稿。

这些多轮测试任务在恢复服务启动后创建；本次没有声称它们自身经历了备份恢复。原有数据的备份、恢复和两次重启仍由交付校验器的独立步骤验证。排队修改历史和取消边界继续由 [完整任务包的源码流程](../reliability/task-exports.md) 覆盖；本次新增安装流程使用实际完成的两轮对话。

## 复现

准备适配本机 Python 与平台的 PyYAML wheel，以及 Playwright 与 Chrome。候选目录和报告路径须尚不存在：

```sh
.venv/bin/python scripts/build_release.py --output-dir /tmp/agent-export-candidate
.venv/bin/python scripts/verify_release.py \
  /tmp/agent-export-candidate/agent-framework-1.3.0.tar.gz \
  --wheelhouse /tmp/agent-wheelhouse \
  --report /tmp/agent-export-installed.json --browser-check
.venv/bin/python -m unittest tests.test_release_delivery
```

临时安装环境与数据库在结束时清理，指定位置的报告、浏览器结果和下载文件保留。
