# 智能体内快捷创建领域

2026-11-04。源码改进，版本保持 1.3.0，尚未发布。

在智能体配置中点击“创建并选用”时，此前只有创建按钮进入等待状态，其他字段与管理入口仍可操作。慢响应返回后会选用已提交的领域并清空快捷创建字段，等待期间的新输入可能被丢弃。

## 当前行为

- 提交后沿用现有保存流程，锁定当前智能体表单，并通过“正在创建…”及表单 `aria-busy` 显示等待。重复提交、Escape、关闭和打开另一份智能体均不会打断这次写入。
- 请求固定提交内容与工作空间。响应只应用于仍打开的同一表单、编辑会话、租户、操作人和空间；旧会话的成功或失败不再改写当前输入或显示错误。
- 创建失败后恢复编辑，保留原始名称、用途和工作方式，支持明确重试。成功后选用返回的领域版本，收起并清空快捷创建区，继续保留智能体名称与手工工作指令。
- 服务端已经创建、但响应丢失时，相同内容的明确重试沿用已有去重规则，返回同一领域，而非再创建一份。若用户改了内容或领域已被修改、归档，仍按现有名称冲突规则处理。

创建领域会立即保存独立的领域记录；只有随后明确保存智能体，才保存两者的关联。保留智能体草稿会记录当前选中的领域，刷新后可继续编辑。这里没有增加自动重试、撤销已受理写入或新的保存协议。

## 验证

新增 6 项单元测试，覆盖冻结提交内容、表单锁定、重复激活、失败保留与重试、关闭或其他写操作期间禁止创建、校验失败及编辑身份隔离。原脚本上 4 项失败、2 项通过。现有交互测试另补充了快捷创建期间禁止替换编辑器的场景。

相关测试 **40 项**、全量前端测试 **1126 项**通过。处理领域的后端契约测试 **15 项**通过，包括相同内容重试、同名冲突、版本、隔离及 HTTP 接口。

新增 `agent-domain-creation` 浏览器流程并接入统一运行器，连同配置打开、智能体草稿、智能体保存共 **4 组浏览器流程**通过。新流程验证：

1. 延迟 503 时，当前表单全部输入与按钮锁定，重复激活只发送一次；失败后原始字段恢复可编辑。
2. 让服务端真实接受创建，再模拟连接中断；明确重试后仍是同一个领域 v1，领域总数为 1，期间没有保存智能体。
3. 保留草稿、刷新并恢复选中领域，最后明确保存一个智能体，所选领域版本和手工指令准确保留。

候选包 **167 个应用文件**与源码一致，相比上一候选包仅修改 `agent_domains.js` 与 `agents.js`；启动脚本、随包说明和 6 份历史发行物校验通过。没有改动后端、依赖或数据库，本轮未重跑全量后端或全新安装。使用隔离合成数据，没有真实模型调用，未发布。见[验收记录](agent-domain-creation-verification-20261104.json)。
