# 智能体编辑草稿与刷新恢复

2026-11-02。当前源码改进，尚未发布。

此前 Agent 配置只在打开的编辑窗口中保留输入。刷新会丢失未完成的工作指令，以及保存响应丢失后用于核对的请求编号。本次在当前浏览器标签页保留恢复副本，刷新后从智能体目录或详情继续编辑。

## 使用与边界

- 编辑时自动保留当前标签页副本，也可点击“保留草稿并关闭”。目录会显示“继续编辑智能体”；同一空间已有副本时，创建和编辑入口先引导处理现有副本。
- 恢复名称、用途、岗位、工作指令、执行参数、职责与标准、领域版本、新领域输入、技能绑定及历史 MCP 原始字段。未完成的职责、空技能选择、格式错误的 MCP JSON 不会因尚未通过保存校验而丢失。
- 草稿中的模型与推理强度不会因为目录变化而静默换成默认值；不可用选择保留并提示重新选择。目录读取失败时保留原模型，需重新读取后再保存。
- 原保存编号在发出保存请求前写入恢复副本。响应丢失后，刷新恢复该编号及本页后续修改；恢复不会自动请求保存，也不会把本地数据当成已保存回执。点击“核对保存结果或最新配置”只读取服务数据。
- 保存重试、明确按所示版本更新、另存副本及采用服务配置，继续遵守[保存回执与冲突恢复](agent-saves.md)的规则。后续改进已将原提交与本页输入分开保留，提供明确的原提交重试，见[原提交重试与后续修改保留](agent-retries.md)。
- 成功保存或明确采用服务配置后清理副本。放弃输入只移除本地副本，不撤销已发出的请求，也不删除服务中的智能体。清理失败会说明残留情况；放弃操作失败则保持当前窗口。

副本按租户、操作人和工作空间隔离，使用 `sessionStorage`，每个空间在当前标签页保留一份编辑。它不是服务端保存、备份或跨设备同步，关闭标签页后可能丢失。正常编辑不会发送草稿正文到服务；真正保存仍由用户发起。

2026-11-04 补充：[执行配置读取期间也可保留草稿并关闭](agent-template-drafts.md)。恢复后保持原配置与输入，旧读取结果不再影响编辑；实际保存与领域创建的等待保护继续有效。

副本最多 500,000 字符，读取时检查版本、作用域、字段类型与集合上限。当前写入 v2，继续读取 v1；v2 同时保留原提交和后续输入。损坏或不支持的副本只显示清理入口，不渲染为配置、不发送请求。旧编辑会话、旧作用域和过期副本不能覆盖或删除新副本。

浏览器拒绝存储或容量不足时，页面明确提示刷新可能丢失，当前输入仍保留在窗口中。“保留草稿并关闭”会保持窗口并报错，用户仍可主动保存到服务。缓冲写入在页面离开和编辑窗口交接时补写，成功完成后排队的旧事件不能重新生成草稿。

真实浏览器使用临时合成服务和模拟运行时；模型目录变化通过合成响应验证，不调用真实模型。覆盖：

- 未完成字段与原始 MCP JSON 刷新恢复，不自动保存。

- 服务受理后丢失响应、继续输入、刷新、只读核对、明确更新同一智能体及成功清理。
- 取消放弃、损坏副本清理和浏览器存储拒绝。

## 2026-11-04：明确保留未修改的配置

此前“保留草稿并关闭”与后台自动保留共用“已有修改”的判断。刚打开或复制配置、尚未改动字段时，点击该按钮会关窗，却不会生成恢复副本。

现在明确点击该按钮会保留当前表单，包括尚未填写名称的新建配置、刚复制的配置和未修改的已有配置。存储成功后才关闭，回到“继续编辑智能体”入口；刷新恢复原字段、执行配置与版本。新建和复制仍是未保存的新配置，已有配置仍关联原智能体及版本；恢复不会提交保存。普通取消和未修改表单的自动保留继续跳过副本创建。

明确保留仍检查当前身份、工作空间、编辑会话和副本归属，不会覆盖较新的恢复副本。存储失败会保持窗口和当前字段，并允许明确重试；不以“尚未修改”为由跳过失败反馈。这里保留的是表单输入，不要求先通过服务端保存校验。

新增 4 项单元测试，在旧代码上 3 项失败、1 项通过；修改后相关测试 34 项、全量前端测试 **1120 项**通过。智能体草稿、配置打开、保存与原提交重试 **4 组浏览器流程**通过。扩展的草稿流程逐一验证新建、复制和已有配置的普通取消、明确保留、刷新恢复及原版本保留，并模拟未修改副本的存储失败；三个流程均未发送保存请求，原智能体内容保持一致。
