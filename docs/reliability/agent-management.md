# 智能体配置与领域、技能管理之间的往返

2026-11-04。源码改进，版本保持 1.3.0，尚未发布。

从智能体编辑器打开领域或技能管理前，需要读取当前目录。此前只核对空间与窗口是否打开：等待读取时关闭编辑器，再打开另一份配置，旧回复可能关闭新窗口并把它带到管理页；旧请求收尾也可能提前解除新请求的等待状态。

## 当前行为

- 两种管理入口共用一份跳转请求，固定工作空间、租户、操作人、编辑会话、表单和发起时的路由。同一时间只处理一次管理跳转；配置正在保存、核对或创建领域时不能开始跳转。
- 等待期间显示“正在打开…”。技能管理的两个入口同步显示等待，配置摘要重新生成后仍保留提示。读取期间可以继续编辑，也可按原有流程关闭或保留草稿。
- 关闭、离页、开始另一份编辑或开始保存、核对、领域创建及执行配置切换时，会立即释放旧跳转请求的界面状态。即使这些操作先结束，后来返回的旧读取也不会重新触发跳转。迟到成功不更新目录或关闭新窗口；迟到失败不显示旧错误，收尾也不解除后来请求的等待。
- 当前读取失败时保留窗口和输入，恢复入口文字，可再次明确点击。读取成功后保留当时最新的名称、指令和配置页签，再打开管理页。
- 返回也核对编辑会话、身份、原智能体及版本。选用领域或已发布技能版本后返回原表单，继续保留未保存输入；期间不自动保存智能体。

这些读取仍受现有客户端超时约束；关闭只放弃采用读取结果，没有声称取消已经发送的 HTTP 请求。原有领域归档检查、技能发布状态与绑定数量限制、智能体保存版本校验继续生效。

## 验证

新增 **17 项前端测试**，涵盖两个入口的作用域、可见等待、关闭后重新打开、路由与身份变化、开始其他写操作、新旧请求交错、明确重试、返回会话核对及两种目的地互斥。在原脚本上 15 项失败、2 项通过；修改后全部通过。相关测试 **178 项**、全量前端测试 **1143 项**通过。

新增 `agent-management` 浏览器流程并接入统一运行器，分别在领域与技能管理中验证：

1. 延迟成功，关闭并打开另一份配置后继续输入；旧回复不关闭新窗口、不发起跳转。
2. 旧失败与新读取交错；旧失败不显示、不释放新等待，当前失败恢复明确重试入口。
3. 明确重试后在等待期间修改名称与指令；进入管理页，选定领域或已发布技能版本并返回，核对字段和所选版本，保存请求数保持为 0。

管理往返、快捷领域创建、配置打开、智能体草稿和技能保存共 **5 组浏览器流程**通过。初次定位器发现技能管理实际有两个入口，最终实现同步处理两处等待状态；最终代码重新运行了全部五组流程。
