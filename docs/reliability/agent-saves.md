# 智能体保存回执与冲突恢复

2026-10-30。当前源码改进，尚未重新生成发行包。

此前创建接口不能识别同一次保存的重试：服务端已经创建成功、页面没有收到回执时，再次保存会生成另一个智能体。编辑请求遇到相同情况则会因旧版本号冲突，页面无法区分“上次已经保存”与“其他页面修改”。此外，匹配归档后的版本号仍能直接改写归档配置，过期工作空间视图也缺少最后的配置写入检查。

## 使用

- 创建与编辑都会为当前编辑窗口保留一个保存编号。回执丢失后，原页重试复用编号，相同请求返回同一智能体及接受版本，不重复创建或再增加版本。
- 保存报错时保留输入，提供“核对保存结果或最新配置”。核对只读取信息，不替换本页字段或自动修改版本号。
- 可以查看已保存配置的执行方式、模型、领域、工作指令及扩展配置摘要，再明确选择“按所示版本保存本页修改”“将本页设置另存为副本”或“使用已保存配置”。
- “按所示版本保存”仍执行版本校验。另一页面在核对后再次修改时，拒绝覆盖并继续保留输入，需重新核对。
- 上次保存已经被接受，但当前配置随后更新或归档时，分别显示接受版本与当前版本。不会关闭窗口或把新版本误报为本次提交的保存结果。
- 核对结果已明确时，普通保存按钮暂停，需从核对区域明确选择后续操作，避免再次发送过期请求。
- 归档配置提供明确状态和另存副本入口，原归档保持不变。配置编辑、另存副本均不启动任务，任务授权沿用原有动线。
- 未找到已接受请求时，仍可保留本页内容并重试原提交。2026-11-02 的[原提交恢复改进](agent-retries.md)将固定请求与后续修改分开，未知结果不会仅凭当前配置就换号保存；刷新后也可继续核对或明确重试。

“使用已保存配置”结束本页编辑并打开已保存智能体。其余操作保留当前输入，直到得到明确保存回执。读取或核对期间阻止切换工作空间，迟到的回复也不会覆盖其他空间或另一份编辑。

服务端回执跨服务重启和核心备份恢复保留；2026-11-02 起，当前源码还在当前标签页保留未提交输入与保存编号，刷新后可明确继续编辑，见[智能体草稿恢复](agent-drafts.md)。回执记录被接受的智能体及版本，核对页面展示当前配置；历史任务继续使用各自冻结的快照。

## API 与持久化

`POST /api/agents` 和 `POST /api/agents/{id}` 可在原配置参数之外提供 `request_id`。操作人由服务端本地身份取得，不接受客户端通过配置参数指定。

| 情况 | 结果 |
| --- | --- |
| 相同编号、配置参数与目标智能体 | 返回同一次保存回执，不重复写配置 |
| 相同编号用于不同参数或不同智能体 | 返回 409，要求先核对已接受结果 |
| 新编号使用过期版本号 | 返回 409，不能绕过并发保护 |
| 智能体已归档 | 拒绝新的配置写入；回放已接受请求仍能查询实际归档状态 |
| 工作空间已删除或在校验期间被删除 | 拒绝配置保存、归档或编译写入 |

返回值保留现有智能体字段，带编号的保存另含：

```json
{
  "save_receipt": {
    "request_id": "save-example",
    "revision": 2,
    "at": 1793318400,
    "replayed": false
  }
}
```

`save_receipt.revision` 是此次请求被接受的版本；顶层 `revision`、`archived` 和配置字段表达当前状态，两者可能不同。`GET /api/agents/save-requests/{request_id}` 可读取回执及当前配置，按租户、工作空间和操作人隔离；其他操作人不能凭编号读取回执。

新增 `agent_save_requests` 表，保存请求摘要、智能体身份、接受版本和时间，主键包含租户、空间、操作人及提交编号。配置与回执在同一事务内保存，失败整次回滚。两个进程同时处理同一请求时，在事务内再次核对，最多接受一次。

已接受请求在重新校验模型、Skill 和领域之前返回回执，便于恢复未知结果；新的保存继续检查配置可用性、当前版本及归档状态。保存结果直接来自提交事务，不依赖提交后另一次详情读取。编译也会在写入缓存前重新检查空间与智能体版本，避免把已变化或已归档的配置当作当前编译结果。

旧客户端不带编号的保存继续兼容；需要可靠重试时应携带编号，当前界面创建与编辑均已接入。独立使用、尚未注册工作空间的历史智能体注册表继续兼容。核心备份保留回执表，见 [核心数据备份与恢复](../data-protection/implementation.md)。
