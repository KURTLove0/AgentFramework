# 清理拒绝与管道退出

2026-11-03。当前源码改进，版本仍为 1.3.0，尚未发布。

上轮全量回归曾记录：主进程退出后，进程组清理返回 `PermissionError`，覆盖了原始 `ModelError`。本轮进行了 60 次隔离进程测量，没有再次复现该平台时序，因此不推断其唯一成因。源码检查与三项失败基线确认了独立问题：清理异常会跳过管道关闭；原始模型或租约异常被替换；阻塞中的管道读写线程可能仍然存活。

## 当前行为

RPC 和通用 CLI 的三条管道改为由执行线程统一管理的非阻塞读写。写入大段输入时同时排空输出，避免双方等待对方读管道；等待期间继续检查停止意图、租约和超时。输出按增量解码器处理分片 UTF-8 和换行，保留原有文本读取语义。队列中的未处理输出上限为 8 MiB。

本地管道的关闭独立于进程终止结果。终止被拒绝时，仍关闭选择器和三条管道，释放待发送输入及已排队输出；没有额外读写线程持有文件锁或等待管道 EOF。它不保证无法发信号的操作系统进程已经结束。

已有的模型、取消或租约异常保留原对象和原始原因，并附加经过筛选的清理状态。没有原始异常、但清理失败时，调用返回 `model_cleanup_failed`，不能将已生成的内容当作成功交付。日志和记录只包含进程编号、异常类型及关闭状态，不复制原始 stderr 或系统异常文本。

运行记录分别保存原始模型错误与 `model.cleanup_unconfirmed`。页面保留输入、公开片段和草稿，同时提示检查本机运行环境。刷新不会自动重试，原失败记录也不会因后续重试成功而消失。取消仍停止后续调度，清理未确认的提示继续保留；租约失效继续传播原 `LeaseLost`，旧执行器不会写入替代执行器的状态。

向进程组发信号被拒绝时，如果主进程已经退出，会在最多约 200ms 内使用信号 0 做只读探测。只有明确收到“进程组不存在”才视为该组已消失；进程组仍存在或无法核对时继续报告清理失败。不会将主进程退出、探测成功或权限拒绝本身当作整个进程组已结束。

## 验证

新增真实隔离进程验证：明确消失的进程组、仍存活的子进程被拒绝终止、RPC 租约异常身份与资源关闭、标准输入阻塞时取消、成功输出遭遇清理失败、双向大数据管道压力、分片 Unicode 与 CRLF、无效编码、运行时原错误和清理状态落库，以及取消后的清理提示。已有读取预算、公共输出、取消、租约替换及 RPC 阻塞输入场景继续回归。

浏览器中的真实 app-server 替身完成握手、输出公开片段后保持存活，测试注入终止拒绝。页面返回失败时，独立观测确认测试进程仍存活、三条本地管道均已关闭，诊断同时保留 `model_timeout` 和清理未确认状态。刷新后没有再次调用模型。测试通过专用端点显式结束自己的测试进程后，再点击重试，新轮次成功，原失败与草稿仍保留。

同时回归普通异常退出、RPC 输入阻塞、认知租约失效和工作流模型停止。普通退出的旧浏览器脚本仍统计普通消息入口，改为当前固定轮次重试入口后通过；不是修改生产行为来满足旧验收。

首次全量回归还在一个旧工作流测试的收尾函数中遇到直接 `killpg` 的权限错误，测试主体已完成。收尾改为使用同样有界且确认结果的清理函数；该用例新增子进程就绪握手，明确先确认主进程退出，再验证子进程回收和管道关闭。真正无法清理仍会使测试报错。

已检查 [清理未确认提示](cleanup-unconfirmed.png) 与 [显式重试后的记录](cleanup-retry.png)。测试使用临时数据库、合成模型和本次创建的子进程，不调用真实模型服务或业务系统。

## 边界

清理状态描述该次调用收尾时的观测，不是持续监控或跨重启的进程管理服务。持久化进程编号只供诊断，不会在以后自动按旧编号发送信号。真正无法终止的进程仍需检查本机环境；本地文件关闭与进程终止是分别记录的事实。

原先偶发的内核权限错误未在 60 次测量中重现。本轮通过确定性的故障注入验证错误保留、退出边界与未确认状态，未声称已证明该偶发错误的唯一原因。测试和生产逻辑都保留真正权限拒绝，未使用忽略异常的方式假定清理成功。

数量、原始日志、首次夹具修正与候选包校验见 [验收记录](cleanup-failures-verification-20261103.json)。候选包与源码逐项核对，并验证包内外校验和；未发布，未重复全新环境安装。
