# RPC 输入阻塞与恢复

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

此前 Codex app-server 的 RPC 请求直接写入带缓冲的标准输入。子进程完成握手后停止读取时，较长的 `turn/start` 消息会阻塞执行线程；停止、超时和租约检查只在接收阶段执行，无法打断这次写入。三项修复前回归均报错：固定进程约 2.2 秒后退出才解除写入，触发 `BrokenPipeError`，未按预期得到停止、超时或原始租约异常。测试环境还在已退出进程组清理时报告了 `PermissionError`，原始日志保留这项限制。

## 当前行为

输入管道改为非阻塞写入。每个 JSON-RPC 消息编码成 UTF-8 后，保留尚未写入的字节；管道可写时继续发送，当前消息完整发送后才开始下一条。管道填满时最多等待 50 毫秒，再检查停止、心跳错误和本次调用的绝对期限。发送与接收共用这些检查，发送阶段也计入调用超时，不另起可能遗留的输入线程。

租约错误原样传播；用户停止仍使用现有持久化取消流程。对端关闭输入时返回 `codex_input_failed` 模型错误。退出时关闭 selector，并沿用本次进程组与输出读取线程的收尾。提示词、RPC 顺序、Schema、公开输出处理及格式重试规则不变。

## 验证

新增 6 项真实管道测试覆盖：阻塞发送期间停止、调用超时、原始租约异常、慢速读取长 Unicode 消息、对端关闭输入，以及已有停止请求时不发送初始化消息。慢速读取以 4093 字节分段接收，核对握手顺序、Schema 和输入 SHA-256，确认没有截断或重复。首组相关回归 21 项通过，扩展后的 6 项专项测试通过；最终全量后端 1136 项、前端 787 项通过。

浏览器通过真实 app-server 握手替身，让子进程仅消费 `turn/start` 的第一个字节，随后停止读取。三轮实际输入分别为 72798、73256 和 73250 字节：

- 用户停止约 220 毫秒后完成，子进程退出，刷新保留未发送草稿；下一条明确发送的消息仅执行一次。
- 租约到期约 946 毫秒后显示中断，没有创建用户停止意图；显式恢复继续同一轮、原任务、配置和期限。
- 配置 2 秒模型超时后，发送中的调用结束并显示超时，保留输入和草稿，没有自动格式重试。

新建任务输入框的现有上限为 2000 字。首轮浏览器夹具错误地通过该入口构造长输入，大小断言失败；修正为产品支持的长消息续问后通过，未修改接口限制。认知租约失效、流式任务和取消三组现有浏览器验收也通过。以上时延是隔离验收结果，不是生产时延承诺。

## 边界

检查仍受数据库访问、心跳检测和进程调度影响。结束本机进程不证明服务端推理已停止，也不撤销先前业务动作。测试使用本机真实管道与固定模型输出，没有调用真实模型服务或使用生产数据。
