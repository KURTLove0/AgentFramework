# 模型调用中的租约失效

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

此前心跳续租失败会被记录，但静默模型调用只轮询用户停止意图。没有公开进度或模型返回时，执行器仍会等待模型超时，再抛出租约错误。两个失败回归通过真实租约交接重现了这个问题：旧式 CLI 和普通任务的 Codex RPC 都等待约 3 秒的配置超时才结束，尽管新执行器已经取得租约并写入检查点。

## 当前行为

模型传输的停止轮询先检查已记录的心跳错误，再检查用户停止请求。发现续租失败后，将原始异常抛回收集器，通过既有进程组收尾结束本机模型进程。即使模型一直静默，也不需要等到它返回内容。

租约失效继续以 `LeaseLost` 传播，不转换为 `task_cancelled`。这样旧执行器只退出自己的调用，不为接手进程创建取消请求。现有检查点、租约 owner/epoch、事件和结果写入仍受原有隔离规则保护；旧调用的读取会话与传输回调在退出时清理。

租约仅到期而没有新的执行器接手时，Web 执行器沿用既有中断记录，页面等待用户显式恢复原任务。正常心跳续租不会中断静默调用。

## 验证

新增 5 项回归覆盖旧式调用、Codex RPC、Cursor/Qoder 的普通与旧式模式、接手执行器已经完成任务，以及正常心跳。租约交接通过真实 `Store.acquire` 和新检查点完成，验证旧调用及时退出后，新状态、事件和执行权保持一致，没有新增取消请求；其中一项由接手运行时实际完成原任务，再核对成功结果未被覆盖。49 项相关回归通过，扩展后的 5 项专项测试全部通过。

浏览器中，真实本机等待进程配置为 60 秒超时。测试使当前租约到期后，约 997 毫秒确认子进程退出、页面显示执行中断，且没有用户取消记录。刷新保留中断状态和草稿；显式恢复继续同一任务、同一轮次、原配置、期限与授权，业务草稿最终只写入一次。该时延来自隔离测试，不代表生产时延承诺。

两处测试设置在验证中修正：比较检查点时读取实际持久化状态，包含 Store 更新的时间戳；健康心跳用例返回符合既有 schema 的有效计划，而不是不允许的空计划。首轮全量测试也记录了后一项夹具错误，随后按修正后的测试重新验证。

## 边界

此机制响应心跳已经发现的续租错误，受心跳间隔、数据库访问和进程调度影响，并非跨进程瞬时撤销。它结束本机调用，不证明模型服务端已经停止计算，也不撤销先前完成的业务动作。

测试使用真实本机管道、实际租约和固定模型替身；未调用真实模型服务，未使用生产数据。权限、冻结协议和恢复规则不变。候选包未发布，本轮不重复全新环境安装验收。最终测试、源码与包摘要见 [验收记录](cognition-lease-loss-verification-20261102.json)。

最终通过 1130 项后端测试、787 项前端测试，以及认知租约失效、执行器恢复、工作流模型停止和原生读取停止四组浏览器验收。候选包的 143 个程序文件与当前源码一致，包内 wheel 与单独 wheel 相同，内外校验清单通过。
