# 长对话的展示读取优化

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

此前对话展示逐轮读取完整执行对象，包括动作、原生资料读取和经验候选，再解析每轮的全部审计事件。流式回答按完整片段保存进度，旧片段已经被替代后仍会反复解析；对话越长，轮询和推送重复处理的历史数据越多。

## 当前行为

对话展示按最多 400 个轮次一批读取状态所需字段、停止回执、租约及最新事件序号，不再为每轮装载动作和经验候选。任务正文、回复、错误和公开过程仍全部返回；排队、取消排队和未能开始的轮次保留原有状态。

公开过程直接从审计记录选择展示所需事件：回答只读取最后一次执行请求或输出拒绝之后的最新片段；每个尝试和摘要流只读取最新摘要，但保持该摘要首次出现的位置。工具与其他公开过程保持原顺序，最终报告会替代未完成片段。原生资料读取只投影公开标签，不解析无关的原始回执正文。

最新事件序号仍覆盖全部事件，包括不显示在对话中的事件。状态、过程、停止和租约继续使用同一读取快照，进程提示仍在读取前采样。对话子轮次同时核对操作者和项目归属，错误关联不会把其他范围的回复交付给当前页面。

新增 `events_kind` 和 `events_progress_kind` 两个读取索引。首次打开已有数据库时会创建索引，所需时间取决于现有事件量；业务记录、事件数据和 API 响应格式保持原样。只读历史即使没有新索引也能得到相同结果，只是不享有相同的查询加速。

## 同一份历史的测量

测量使用 60 轮合成对话，每轮 80 个累积回答片段、8 个摘要更新，并包含非公开审计正文。新旧代码读取同一个临时数据库，各执行三次，响应正文均为 125,502 字节，SHA-256 完全一致。

| 指标 | 改进前 | 改进后 |
| --- | ---: | ---: |
| SQL 语句数 | 426 | 8 |
| Python 累计解码的 JSON 输入 | 53,889,560 字节 | 122,123 字节 |
| 读取耗时中位数 | 135.1 毫秒 | 33.8 毫秒 |
| Python 跟踪分配峰值中位数 | 1,562,312 字节 | 301,231 字节 |

脚本为 `tests/measure_conversation_reads.py`，会拒绝复用没有合成数据标记的既有目录。测试不调用模型。时间是在开启 JSON 解码计数和 Python 内存跟踪时测得的，不作为生产延迟保证；内存数字不包含 SQLite 自身或整个进程的内存。

## 验证与边界

新增 13 项回归覆盖按需读取、完整审计保留、摘要顺序、尝试重置、最终报告、非公开事件序号、并发快照、缺失轮次、授权阻断、范围隔离、跨批次读取和无索引的只读历史。交错事件用完整审计顺序回放作对照，确认投影没有改变公开内容。原有详情快照测试改为在新的批量读取边界插入并发完成，保留原来的一致性断言。

本次优化的是对话展示部分。完整任务详情中的根任务、当前运行审计和导出审计仍按原接口读取，不能把上述数字理解为整份 HTTP 详情的加速比例。全部可见正文仍会随对话长度增长，本轮没有加入历史分页或删除旧消息。

最终测试命令、浏览器结果、测量文件和源码摘要见 [验收记录](conversation-projection-verification-20261102.json)。候选包尚未安装或发布，没有调用真实模型或生产数据。

最终通过 1043 项后端测试、787 项前端测试，以及实时对话、多标签页连接生命周期和任务授权三组浏览器验收。候选包的 140 个程序文件与当前源码摘要一致，包内 wheel 与单独 wheel 相同，内外校验清单通过；本轮未重新进行全新环境安装验收。
