# 任务详情快照与停止结果核对

2026-11-02。当前源码改进，尚未发布。

任务执行器可能在页面读取详情时完成、停止或进入下一轮。此前状态、事件、证据和对话分开读取，即使反复核对时间戳，仍可能把不同时间的结果拼成一次响应。停止确认窗口也可能把“停止中”当作不可替换的状态，拒绝采用已经结束的新结果。

## 当前行为

任务详情的持久化内容在同一个 SQLite 读取事务中获取：根任务、当前执行轮次、对话、事件、证据、上下文清单、授权及执行租约使用同一份快照。读取期间执行器可以继续提交；本次响应保持读取时的状态，下一次读取展示后续结果。

页面优先使用对话版本、轮次、任务检查点版本和事件序号判断响应顺序。同一位置还会比较停止重试代次、处理错误和完成状态。较新的完成结果可以替换停止中状态，迟到的旧响应不能清除已经显示的重试或失败。

后台刷新整份采用或保留任务详情，避免保留旧对话的同时换入另一份任务状态。任务身份先校验；不匹配的响应保留当前页面并显示错误。已有流式内容保留规则继续适用于无法区分持久化先后的响应。

停止结果不确定时，“核对当前状态”只读取服务，不重复停止请求。核对确认结束后，说明和禁用的操作按钮都显示“本次运行已结束”，用户可关闭窗口查看保留的输出。排队的后续消息继续遵循原有调度规则。

复盘读取也检查持久化停止请求。即使停止由另一个进程发起，且本进程没有执行记录，只要停止尚未完成，就不能开始复盘；在预检查与生成受理之间新增的停止请求同样会阻止生成。

## 边界

- 事务覆盖应用控制数据库。独立模拟业务库的调用统计仍单独读取，不承诺与任务状态处于同一时刻。
- 进程内执行提示在读取前采样，租约及授权是否过期按读取时的时钟判断；它们不能代替持久化的停止请求或最终结果。
- SSE 仍是独立推送。本次改进保证单次 HTTP 详情的持久化内容一致，并改善轮询、操作核对和消息回执的采用顺序，不宣称整个页面与外部系统具有跨请求原子性。
- 后续补充了推送与轮询共用的持久化顺序标记、身份检查和操作详情恢复，见 [实时对话更新](stream-ordering.md)。
- 未修改数据库格式或版本号，没有发布、部署或调用真实模型。

## 验证

新增快照回归会在读取中间通过另一连接提交结果，覆盖事件、证据、上下文、停止请求、子轮次、进程提示和租约。另一个用例让真实测试工作线程在读取事务内完成，验证写入不被阻塞且下一次读取能看到结果。

前端用例覆盖停止完成、重试代次、失败保留、相同对话版本下进入下一轮、时钟回退、流式保留、完整刷新和错误任务响应。浏览器验收通过真实本地请求完成停止重试，再丢弃响应；显式只读核对后显示已结束，POST 次数仍为一次。

测试命令、结果路径、源码与候选包摘要见 [验收记录](detail-snapshots-verification-20261102.json)。本轮在隔离的合成数据上验证；候选包不代表已安装或已发布。

最终通过 1000 项后端测试、729 项前端测试，以及停止、授权和对话详情三组浏览器验收。候选包中 137 个程序文件的源码与 wheel 摘要一致；本轮未重新进行全新环境安装验收。
