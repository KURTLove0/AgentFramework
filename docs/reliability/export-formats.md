任务信息中的“导出完整对话”此前直接打开 Markdown 下载地址，失败时缺少应用内反馈；后端已有的 JSON 导出也没有界面入口。现在 Markdown、JSON 和 ZIP 共用下载窗口，可选择适合的文件，并在失败后保留原格式重试。

## 使用与内容

进入任务信息，点击“导出完整对话”默认选择 Markdown，点击“下载完整任务包”默认选择 ZIP。两处都可切换格式，查看内容说明，再点击下载。打开窗口和切换格式不会立即发起下载。

| 格式 | 用途与范围 | 文件名 |
| --- | --- | --- |
| Markdown | 阅读、编辑和分享整段已保存对话；含各轮要求、回复、实际状态和导出时间 | `TASK_ID-conversation.md` |
| JSON | 程序读取结构化对话；含各轮文字、状态、引用、运行边界、消息修改版本及读取快照 | `TASK_ID-conversation.json` |
| ZIP | 整段对话、完整消息修改历史和全部已创建轮次的执行记录 | `TASK_ID-task-export.zip` |

Markdown 和 JSON 不包含完整修改链与各轮执行审计，需要这些材料时选择 [完整任务包](task-exports.md)。三种格式都反映本次请求读取时的已保存状态：排队或取消的消息保留，尚未创建的执行没有运行记录。未发送输入和未保存编辑不进入文件，下载也不会清理这些草稿。

准备期间固定所选格式，重复点击不会重复请求。失败显示具体原因，点击“重试下载”按原格式重新读取；任务仍在进行时，每次明确下载都可能获得新的快照。成功提示“已交给浏览器下载”，最终保存情况在浏览器下载记录中查看。

## 响应与页面保护

每次请求固定任务、工作空间和格式。关闭窗口、切换任务、工作空间或身份后，旧回复不再触发文件或成功提示。60 秒超时后，即使传输仍返回内容，后续读取检查也会阻止迟到下载。

格式来自固定名单，响应必须有精确匹配的 MIME 类型及非空正文。JSON 还检查任务编号、正整数版本、快照版本与时间、连续轮次及必要字符串字段；错误任务或残缺结构会显示重试提示。通过检查后下载原始响应字节，不重新序列化 JSON。这是基本身份与结构检查，不等同于 ZIP 的完整性校验，也不证明内容来源。

格式选择使用带标签的原生下拉框，准备时禁用，错误通过提示区域发布；重绘保留窗口内滚动和可恢复的控件焦点。原有服务端格式、权限检查、只读快照和单轮记录包接口保持兼容。

测试观测曾发现下载文件与 Playwright `response.body()` 返回的 JSON 时间戳不同。检查安装的 Playwright 实现后确认：特定空正文读取会通过 `Network.loadNetworkResource` 再次请求原 URL，从而得到另一个快照。最终测试在浏览器内对实际 `fetch` 响应执行 `clone()`，保留原响应供应用使用，再将副本与落盘字节比较；同时核对请求次数。另修正了 Markdown 必须在正文包含任务编号的错误测试假设；现有格式通过文件名标识任务，正文检查实际内容、导出时间和取消状态。

新构建候选包的 **167 个应用文件**与当前源码逐一一致，相比上一候选包只变更两份现有前端资源，启动脚本与历史发行物校验通过。本轮未重复全新环境安装，未发布。详见 [验收记录](export-formats-verification-20261104.json)。

## 键盘下载与等待焦点（2026-11-04 补充）

此前按 Enter 开始下载后，原生禁用按钮会丢失焦点；请求完成又强制聚焦下载按钮。用户等待时已经移到“关闭”，成功或失败仍会把焦点抢回下载操作。窗口顶部的关闭图标也没有可供重绘恢复的稳定编号。

现在下载按钮在准备期间保留键盘焦点，以等待样式、忙碌状态和“正在准备”说明反馈进展；同一个请求未结束时，重复点击、Enter 和空格都不会再发请求。格式选择继续禁用。用户可用 Shift+Tab 移到下方或顶部关闭按钮，成功或失败后停留在自己的选择上。没有新焦点的情况不会自动指定控件，旧窗口的响应也不能聚焦重新打开的窗口。

新增 6 项交互测试，旧脚本有 5 项失败；修复后导出单元测试 **27 项**、完整前端测试 **1191 项**通过。真实 Chrome 在旧脚本上复现了开始下载后的焦点丢失，修复后通过以下检查：

- 导出 **7 项流程、26 组布局**：含 Markdown、JSON、ZIP 的成功或失败、上下两个关闭按钮、重复键盘激活，以及正常和 28px 字号下的准备状态。
- 实际保存 **9 份文件**：4 份 ZIP 通过 CLI 完整性校验，5 份 Markdown／JSON 与各自那次响应的字节完全一致。排队、修改历史、取消状态和未保存草稿的原有边界继续成立。
- 复制回复回归 **4 项流程、8 组布局**通过；两组浏览器均无页面错误。

已检查 [浅色等待状态](task-export-focus-pending-light.png) 和 [深色大字号等待状态](task-export-focus-pending-dark.png)。测试最初假定从窗口末项按 Tab 立即回到首项，当前 Chrome 返回的页面焦点编号为空；最终用窗口内部确定的逆向 Tab 顺序验证关闭按钮，不依赖浏览器自身的末项环绕行为。
