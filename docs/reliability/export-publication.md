# 导出发布与校验保护

2026-11-02。当前源码保持 1.3.0；已构建独立验收候选，未覆盖或发布正式发行包。

## 已复现的问题

修正前的六个用例出现五项断言失败和一项压缩解码异常：导出未同步目录项；收尾失败会删除完整导出；普通失败会递归删除其他进程放入的文件；未知 ZIP 成员在名单验证前被读取；带符号链接属性的 ZIP 成员仍可能通过；损坏 Deflate 数据抛出未经转换的异常。

另用独立 CLI 进程确认，顶层输入为命名管道时会等待写入者，两秒后仍未返回。该实验主动终止了测试进程，没有接触实际工作数据。

## 发布与失败处理

导出仍使用新目录，拒绝覆盖已有目录、文件和符号链接。自动创建嵌套父目录的行为保留；新增父目录及其祖先中的目录项也会同步。备份和导出现在共用目录同步函数。

| 阶段 | 完成条件 |
| --- | --- |
| 准备父目录 | 新建父目录及最近已有祖先的目录项完成同步 |
| 创建导出目录 | `.export-in-progress` 已写入并同步，导出目录名已同步 |
| 写入内容 | 文件逐个同步，所有文件名和目标目录名完成同步 |
| 完成发布 | 删除未完成标记，再同步目标目录，随后返回成功 |

完整内容进入收尾阶段后，不再执行删除回滚。因此，标记删除或最终目录同步发生异常时，已生成的内容会保留，命令仍返回失败。可以对现有目录执行 `verify-export` 核对当前内容；未完成时使用新目录重新导出。

更早发生错误时，清理仅处理本次创建、设备与 inode 身份仍一致的文件。文件在开始写入前即登记归属，部分写入或文件同步失败也能被正确清理。清理不会递归删除目录，不删除被其他进程替换的文件或目录，也不删除后来加入的无关文件。清理或同步失败会留下不能通过校验的目录，而不会误报成功。

这些检查不改变任务数据库，不修改原消息、报告、事件、证据或上下文，也不改变导出的读取快照。

## 校验读取顺序

`verify-export` 先检查允许的文件名单、重复成员、普通文件类型和声明大小，再读取不超过 64 KiB 的清单。清单中的文件名单、长度和哈希字段有效后，才读取消息和记录正文。正文合计上限仍为 256 MiB，读取量按已声明长度限制；读取期间文件长度发生变化会拒绝。

ZIP 支持应用生成的 Deflate 压缩和未压缩存储。符号链接、目录、特殊文件、加密内容及其他压缩方式在打开成员正文前拒绝。未知路径、缺失文件、重复成员、超限清单及超限内容也会提前拒绝，不解压到磁盘。

目录中的文件和顶层 ZIP 来源均通过文件描述符检查为普通文件。使用非阻塞打开，避免命名管道等待写入者；平台支持时也禁止跟随文件符号链接。损坏的 Deflate 数据返回明确的导出错误，CLI 以失败状态退出，不输出 Python traceback。

格式版本保持为 1。有效的旧记录包、空事件文件、无报告的未完成任务，以及已保存的报告排版继续可校验；校验不调用当前 Markdown 渲染器。`valid: true` 表示内容和快照边界一致，任务是否完成仍由清单中的运行状态决定。
