# 多轮改写的来源核对

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

此前只能核对历史消息自身的引用。如果第一轮引用资料，第二轮依据前文改写但没有再次填写引用，资料撤回后第三轮只屏蔽第一轮，第二轮改写的内容仍会进入模型。两项失败回归重现了直接撤回和排队后撤回两种路径。

## 当前行为

每次模型调用前，先核对历史中的显式引用与已记录来源依赖，再把仍可见的历史来源集合保存到上下文清单的 `conversation_sources`。后续组装该轮回复时，将这些来源作为 `source_dependencies` 放入模型历史。正式报告的引用列表不变，不把“曾看到某份历史资料”伪装成“明确引用了这份资料”。

依赖会随多次改写保留，原引用离开有限历史窗口后仍可继续核对。来源撤回、过期、内容摘要变化或不可访问时，整条依赖回复的正文在下一次调用前替换为来源失效提示。原报告、完整对话和冻结的任务输入继续保存。已经屏蔽的来源不进入本次可见来源集合，因而不会自动附加到本次生成的新回复上。

上下文清单按批次读取，与轮次检查点共享同一个数据库快照。使用来源记录前核对清单摘要及运行、操作者、项目和环境。无法核对的记录不会把相关正文继续交给模型。此检查也覆盖来源列表为空的清单，避免无效空列表绕过核对。

旧清单没有来源集合时，按冻结历史和清单中的失效轮次重建依赖，并沿未被屏蔽的历史助手消息继续追溯。跨批次保存已验证依赖，因此不要求原引用仍在最近的展示窗口中。无法解析的关联或循环关联会屏蔽相关历史正文。兼容读取不修改旧清单或冻结输入。

## 验证

新增 13 项回归覆盖撤回后的无引用改写、排队后核对、有效来源保持可用、多次改写和窗口截断、旧格式追溯、已屏蔽来源不继续传播、清单摘要不匹配、范围错误、读取快照一致性、205 条旧记录跨批次依赖、循环关联、依赖内容变化及上下文格式兼容。

浏览器通过真实页面生成一条引用回复和一条无引用改写，再将第三轮暂停在待执行状态，撤回临时资料并刷新页面。恢复执行后检查模型替身未收到原文或改写，原报告和冻结输入不变。第四轮确认撤回后的新回复仍可见且不继承已屏蔽来源，四轮各调用一次模型。

在此前同一份 60 轮、无来源依赖的合成数据库上，新增检查后组装历史使用 3 条 SQL，Python 累计解码 5,291 字节，三次测量耗时中位数约 6.2 毫秒；输出仍是 119 条消息、15,216 字节，摘要与此前相同。带来源清单的历史还需要读取并验证清单，不应据此推断同样的查询负载或生产延迟。

## 边界

来源依赖描述历史资料的可见性，不判断哪一句话实际使用了哪份资料。因此，一轮回复即使部分内容与资料无关，也可能在资料撤回后整轮屏蔽。该规则依赖历史中已记录的显式引用及继承依赖，不会仅凭正文识别从未留下这些记录的资料来源，也不保证撤回前已经发出的模型请求能够收回。

测试使用隔离临时资料和固定模型替身，没有调用真实模型或生产数据。来源身份只保留标识和内容摘要，不重复保存引文；这些字段仍计入原来的历史字节预算。
