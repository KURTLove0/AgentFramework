# 慢请求期间的任务控制

2026-10-30。当前源码改进，尚未重新生成发行包。

2026-11-01 后续改进：[生成等待期间继续工作](proposal-responsiveness.md)。设计、复盘和本体生成已从普通命令锁独立出来，共用有上限的生成名额；普通写操作与后台计划检查无需等待模型。下文保留首次改进的范围和验证记录。

## 用户可见变化

页面正在保存配置、检测运行时或生成工作流提案时，其他页面仍可读取任务状态和提交停止。上传未完成、客户端迟迟不接收回复，也不会占用所有写操作或任务调度使用的锁。

任务停止、工作流停止、取消排队消息可以先于正在等待的普通配置写入受理。停止仍通过原有持久请求、租约和实际执行状态处理，接受请求不代表已经停止；已发出的业务操作继续按原规则核对。参见 [任务停止的持久请求与恢复](cancellation.md)。

普通写操作继续按顺序处理。配置保存的版本校验、重复提交回执、空间隔离与任务身份规则不变；本次没有并行放开所有写接口。

## 锁与网络边界

- 先校验 Host、Origin、JSON 类型与页面令牌，再接收正文。接收正文时不持有共享锁。
- 普通写请求与每日计划检查共用独立的命令顺序锁。模型、配置预检等等待不会占用执行器更新、任务状态读取或停止信号使用的任务锁。
- 三类停止接口经过相同的身份、空间、正文及版本检查，直接进入已有事务和服务层锁，不等待普通命令完成。
- 响应先序列化成固定字节，再释放命令锁，最后发送到客户端。慢读取或断开的客户端不会拖住下一个命令。
- 异常处理和正常响应都会释放命令锁；执行器与后台恢复继续使用原来的状态锁、事务和租约。

独立受理的停止接口：

| 接口 | 保留的检查 |
| --- | --- |
| `POST /api/runs/{id}/cancel` | 可信操作人、任务空间、空操作正文、持久停止记录 |
| `POST /api/workflow-runs/{id}/cancel` | 工作流范围、空操作正文、持久派发和取消意图 |
| `POST /api/tasks/{id}/messages/{number}/cancel` | 对话权限、当前版本、排队状态与运行尚未创建 |

停止仍可能等待短事务、磁盘访问、正在结束的实际操作或其他进程持有的租约；本次没有改变“正在停止”和实际终态的含义。

## 正文接收

正文从开始接收起默认最多 **10 秒**，分段读取时沿用同一个截止时间。持续发送少量字节不能延长预算。连接执行读写时的等待上限也为 10 秒，响应生成和合法模型执行不受正文接收截止时间限制。

超过正文时限返回 `408`，未收齐声明长度返回 `400`；两者都不执行路由中的写操作。重复的 `Content-Length` 或携带 `Transfer-Encoding` 的正文返回 `400`，避免长度歧义。原来的各接口正文大小上限继续生效。
