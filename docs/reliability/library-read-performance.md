# 知识库读取性能与一致性

2026-10-31，当前源码。知识库读取减少了重复取回资料、逐条查询评测以及提前读取全部情节记忆的开销，保留现有接口的内容、顺序、数量与可见范围。

后续新增的[情节记忆分页模式](memory-history.md)提供完整历史计数与稳定翻页。下述基线及响应对比针对保留兼容的默认接口，分页模式使用额外的计数读取。

## 合成基线

在临时数据库中建立 200 条知识、200 条经验和 800 条情节记忆。知识及记忆正文各约 8 KiB，每条经验有两份包含约 32 KiB 评测详情的记录。两种查询分别运行三次，下面为本机中位数。

| 查询 | 读取 SQL 数量，优化前 → 后 | 中位耗时，优化前 → 后 | Python 解码输入，优化前 → 后 |
| --- | --- | --- | --- |
| 全部资料 | 205 → 3 | 63.4 → 20.9 毫秒 | 10.52 → 2.12 MiB |
| 指定关键词 | 206 → 6 | 82.8 → 42.2 毫秒 | 16.51 → 1.85 MiB |

两种查询在优化前后的完整响应摘要均相同，三次重复测量也一致。响应大小分别仍为 2,375,603 和 177,631 字节；本轮降低服务读取开销，没有通过删减返回内容来缩小响应。

查询次数指应用发起的读取语句数；合并后的语句内部仍会按资料版本进行索引查找，并不表示只处理三条记录。

这只是固定合成数据在本机的对比，不代表生产环境延迟或容量承诺。原始结果见 [优化前](library-read-before-20261031.json) 和 [优化后](library-read-after-20261031.json)。

## 改动

经验列表现在直接查询当前范围内的经验版本，并在同一条查询中取得该版本最后写入的评测摘要。只传递评测编号、是否通过和时间，不把详细回放与来源记录复制到 Python 再丢弃。新增按租户、资料编号和版本检索的索引。

知识库复用首次读取的经验条目，不再为经验模块重复读取全部知识、偏好、本体等资料。普通资料列表仍保持原来的返回形式，评测摘要只由需要它的读取路径明确启用。

情节记忆在没有关键词时，直接按原顺序读取所需数量。带关键词时先检索授权范围内的摘要，匹配仍沿用现有分词规则；确定最多 50 个结果后，再读取这些记录的完整正文。两个阶段共用同一个读取快照，避免匹配时和展示时对应不同内容。新增按租户、项目、环境、主体读取的索引。

知识库的情节记忆计数复用已取得的结果，或用同一快照中的计数查询取得。原有最多显示 50 条的计数语义保留，其他模块的计数和能力契约验证继续沿用已有规则。

## 保留的行为

- 租户、项目、环境和私有主体条件在取回正文前生效，其他范围的无效 JSON 不进入解码或评测摘要读取。
- 评测对应确切资料版本，采用最后写入记录；不会因为更早的记录通过、时间戳更大或另一个版本已通过而替换它。
- 资料状态与评测摘要来自同一次读取，避免刚撤回、刚重新评测的资料呈现混合状态。
- 情节记忆仍只按摘要匹配，按插入顺序从新到旧排列；无有效词元的查询仍沿用原行为。
- 资料全文、评测详情、历史、权限及审核发布流程保留。没有引入跨请求缓存，后续读取继续看到已提交的更新。

## 验证与边界

新增 14 项专项测试覆盖读取成本、正文解码范围、最后评测选择、版本隔离、私有范围、原查询语义和并发快照。最初复现 5 项失败；修复后 14 项均通过。完整后端 **771 项通过**，五套浏览器验收全部通过；最终结果见 [验证记录](library-read-verification-20261031.json)。

```sh
.venv/bin/python scripts/benchmark_library.py
.venv/bin/python -m unittest discover -s tests -q
.venv/bin/python scripts/run_browser_tests.py --suite library-search --suite asset-versions --suite ontology --suite audit-fixes --suite legacy-modules
```

本轮仍会返回接口约定范围内的全部资料版本，关键词检索也仍可能扫描大量摘要或资料内容；这不是资料分页或全文索引重构。SQLite 仍需读取 JSON 才能提取摘要，本轮测量的解码量指进入 Python 的 JSON 字节数，不等同于磁盘读取量或进程峰值内存。

所有测量与验收使用隔离的临时数据库、合成资料和离线运行，未调用真实模型、修改既有业务数据、重新打包或发布。
