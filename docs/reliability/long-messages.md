# 长消息执行

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

续问允许提交最多 16,000 字的消息，但原上下文组装把整条消息直接用作资料和历史记忆检索条件。这两个检索入口只接受最多 2,000 字，导致消息已经受理并保存在对话中，却在调用模型前变为失败，页面只显示“认知调用失败：ValueError”。2,001 字和 16,000 字的真实任务回归均重现了这个问题。

## 当前行为

任务正文、保存的消息以及本轮模型输入保持完整。自动检索单独生成有界查询：2,000 字以内原样使用；更长内容取开头、中段、结尾各 666 个 Unicode 码点，以两个换行连接，总计 2,000 个码点。资料检索与历史记忆检索使用同样的规则。已验证的工作流显式查询原样使用，记忆检索仍基于任务正文。

这只是可选资料的查询取样，不是对用户材料生成摘要，也不会改写或删除材料。模型可用全文处理当前要求。检索入口原有的长度限制、资料可见范围、发布状态和引用核对规则继续生效。

每份持久化上下文清单新增 `retrieval_queries`，分别记录资料和记忆查询的来源、策略、输入字符数、查询字符数、取样范围和查询摘要。范围采用 Python 字符串的 Unicode 码点下标，左闭右开；按范围取片段并用换行连接，可从冻结任务数据重建实际查询并验证摘要。清单本身的摘要覆盖这些记录。旧清单不被修改。

## 验证

新增九项回归验证 2,000 / 2,001 / 16,000 字边界、超限拒绝、混合中文与 emoji、后续轮次继续接收完整长消息、尾段词对应的真实资料与私有记忆检索、跨用户隔离、显式工作流查询以及查询审计的可重建性。

浏览器用真实页面输入 16,000 字中文消息，暂停执行后刷新，确认受理正文和冻结任务完整保留；恢复执行后检查模型替身收到的全文和两类查询审计，再发送下一条消息核对历史中的全文。三个轮次各调用一次模型，没有重复发送。

测试使用隔离临时数据和固定模型替身，验证完整传递及产品流程，不证明真实模型对长材料的理解质量。取样并不覆盖长消息的每个位置；自动检索仍可能遗漏未被取样区域的关键词。本轮没有改变历史窗口的 96,000 字节预算或新建任务目标的 2,000 字限制。

完整测试结果、源码摘要与候选包信息见 [验收记录](long-messages-verification-20261102.json)。候选包未发布，本轮未重新进行全新环境安装验收。

最终通过 1064 项后端测试、787 项前端测试，以及长消息、历史引用上下文和消息提交三组浏览器验收。候选包的 141 个程序文件与当前源码一致，包内 wheel 与单独 wheel 相同，内外校验清单通过。
