# 模型请求前的上下文刷新

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

此前运行时在一次认知调用开始时组装上下文。模型返回不合格式的输出后，适配器会复用这份上下文重试；Skill 激活、资源选择与任务执行也可能沿用同一份资料。两个失败回归重现了窗口中的问题：可选知识撤回后，正文仍出现在第二次请求；历史回复的来源撤回后，旧正文也会再次发送。

## 当前行为

运行时为模型适配器安装请求前回调。每次准备请求时，都检查期限、调用与 token 预算、正常任务的取消状态和租约，再根据冻结任务与当前持久化证据重新组装上下文。资料的发布状态、有效期、内容摘要和访问范围继续由既有编译器核对，历史来源失效时保留明确提示。

格式重试能够收到此前原生读取产生且仍有效的证据，不需要重跑工具；已撤回资料的证据不再进入下一次上下文。当前发布的新版本也可按既有检索规则进入下一次请求。

Skill 激活、资源选择和执行各自记录实际阶段。已加载的冻结 Skill 指令、资源及选择状态保留，不额外重选 Skill。原生读取仍检查配置能力、当前策略、范围、租约与预算；已提供的 Skill 阶段知识也作为可读取的发现记录，避免阶段名修正后误拒绝原本允许的读取。

每份新清单记录 `model_attempt`，重新计算摘要；`model.requested` 记录对应清单编号与摘要，并保留提示词和 schema 摘要。因此格式重试的各次输入可分别核对。后续历史依赖包含执行与 Skill 阶段接触的资料，包括格式被拒绝的尝试，延续保守的整轮来源核对。

普通对话的知识仍是可选资料；工作流冻结的必需资料撤回时会等待用户处理。两者沿用原有规则。停止或调用预算耗尽在重试前被检测到时，不增加未发出请求的调用次数。回调、观察器和受控读取会话在成功或异常退出时清理。

## 验证

新增 12 项专项回归覆盖当前与历史资料撤回、逐次清单及用量、必需资料阻断、取消、调用预算、新版本、异常清理、Skill 阶段间变化与来源追溯、Skill 阶段原生读取，以及原生证据保留和屏蔽。与既有模型、Skill、流式任务和历史来源测试一起，95 项相关回归通过。

验证中修正了两处测试设置：必需资料应使用真实工作流绑定，普通对话不会将关键资料自动设为必需；浏览器的异步 API 条件改用已有的等待助手，确保实际等到第一次请求进入暂停点。阶段兼容检查另重现了原生读取误拒绝，并修复阶段识别后通过。

浏览器用例在首次请求已收到资料后暂停模型替身，撤回真实测试资料、刷新页面，再返回不合格式的输出。第二次请求不含撤回正文，两份清单分别关联请求记录，原始任务保留，最终结果正常显示。只提交一次任务，记录两次模型尝试。

## 边界

这是调用前的重新核对，无法收回已经发出的请求，也不保证资料在请求发出后保持可用。编译完成后若取消、期限或租约检查阻断发送，可能留有未发送请求的编译清单；来源记录按可能接触处理。

格式重试仍受原有次数限制。网络、鉴权和超时错误没有新增自动重试。独立使用、没有运行时回调的 `LLMPlanner` 仍处理调用者给定的上下文。Skill 包继续使用冻结版本，此处不会动态更新其内容或授权。

测试使用隔离临时资料和固定模型替身，验证实际输入、状态、审计和页面行为，不代表真实模型理解质量。没有使用生产数据。候选包未发布，本轮不重复全新环境安装验收。最终结果与摘要见 [验收记录](model-context-refresh-verification-20261102.json)。

最终通过 1102 项后端测试、787 项前端测试，以及请求上下文刷新、历史来源依赖、未引用资料来源和流式任务四组浏览器验收。候选包的 143 个程序文件与当前源码一致，包内 wheel 与单独 wheel 相同，内外校验清单通过。
