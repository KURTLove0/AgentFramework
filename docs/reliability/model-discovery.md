# 模型目录读取的超时与恢复

2026-11-03。源码改进，版本保持 1.3.0，尚未发布。

模型目录原先共用一把锁：一个 CLI 变慢，其他运行时的查询与有效缓存读取也要等待。Codex 目录使用阻塞输入与后台逐行读取，持续通知可能越过查询截止时间；未换行的大量输出和占住管道的子进程也可能使查询迟迟不结束。

现在 Codex、Cursor、Qoder 的目录读取统一使用非阻塞管道和独立进程组。一次查询的初始化、分页、通知处理与输入发送共用 20 秒截止时间；标准输出与错误输出合计最多 2 MiB，未换行的输出也受限制。查询结束会清理所属进程组并关闭本地管道，不遗留目录读取线程。清理有自己的有限等待，因此 20 秒不是 HTTP 响应的严格总时长。

不同运行时独立查询。同一服务实例内，同时发起的同类刷新共享一次查询及成功或失败结果，等待者最多等待 25 秒；等待者超时不会取消原查询或额外启动 CLI。成功后每个调用者获得独立结果副本。原有五分钟缓存规则继续生效，有效缓存可在手动刷新期间读取。多个服务进程之间不合并查询。

超时、非法响应、输出超限、CLI 非零退出或进程清理未确认，都不会发布不完整目录或覆盖原缓存。页面保留原模型选择和参数，显示原因与重试入口；Qoder 未登录继续提供登录指引。若清理未确认，提示先在终端检查查询进程；不把“本地管道已关闭”当成“所有进程已停止”。原始 CLI 错误输出不会返回给页面。

目录读取只枚举可选模型。Codex 仍只进行初始化与 `model/list`，不创建对话或启动模型任务；目录返回非目录操作请求会被拒绝。现有任务的冻结配置、运行时配置保存和模型执行流程保持各自原有职责。

## 验证

- 改动前，两个确定性并发用例复现其他运行时与有效缓存被慢查询阻塞。
- 新增 22 项测试覆盖查询合并、失败共享、等待者超时、缓存可读、持续通知、阻塞输入、并行读写、未换行输出、错误输出、分段 Unicode、分页总时限、退出与后代进程清理、清理拒绝、缺少命令，以及真实 HTTP 并发响应。子进程均使用临时 Python 程序替代真实 CLI。
- 既有目录测试继续验证 Codex 初始化、分页与推理强度，Cursor 解析和缓存，以及 Qoder JSON、文本与登录错误。Codex 握手测试已改用真实管道，检查实际发出的请求，不调用真实模型。
- 浏览器通过真实目录查询链路模拟持续通知和超时，验证另一运行时先完成、原输入保留、刷新失败缓存可读、主动重试与跨页面草稿恢复；另回归运行时配置恢复和智能体草稿流程。
