# 异常退出进程的回收

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

真实 RPC 进程在完成调用前退出时，清理函数直接向进程组发送信号。当前环境中，已退出但尚未回收的主进程会使该操作返回 `PermissionError`；回收之后，同一已消失进程组正常返回 `ProcessLookupError`。因此清理异常可能覆盖已有的模型失败或 `LeaseLost`，并跳过后续管道关闭。修复前 3 项回归均报错，覆盖直接清理、原始租约异常和提前退出的 RPC。

## 当前行为

清理先轮询并回收已经退出的主进程，再按既有顺序向本次进程组发送 TERM、等待、发送 KILL、等待。如果进程恰在轮询与发送信号之间退出，仅在确认主进程已退出后重试一次被拒绝的信号；进程组已经消失则正常结束，仍被拒绝则继续报错。

主进程退出不等于整个进程组结束，因此仍清理残留子进程。真正的权限拒绝不会被吞掉，也不会把仍在运行的进程标为已清理。原有等待上限、停止意图、租约隔离和业务动作核对规则保持不变。

## 验证

新增 8 项回归使用真实本机进程验证：已退出但未回收的主进程、保留同一个原始租约异常、RPC 提前退出仍是模型错误且三条管道关闭、主进程回收后仍终止忽略 TERM 的子进程、退出与信号竞争、仍存活进程的权限拒绝、主进程退出后的持续权限拒绝，以及重复清理。竞争和拒绝用例只注入信号结果；进程本身仍真实运行。相关回归 27 项通过，扩展后的 8 项专项测试通过。

浏览器中，真实 app-server 替身完成握手并返回一个公开片段，随后以 23 退出，未发送完成通知。页面和持久化记录保留 `incomplete_model_turn` 模型错误，子进程已回收、三条管道关闭，没有被清理异常替换成执行器中断。刷新保留失败记录、公开片段和未发送草稿；点击重试后新增一轮并仅执行一次，原失败轮次继续保留。诊断中的私有 stderr 内容没有出现在任务详情中。

首轮浏览器检查中，公开片段同时出现在运行动态和回答预览，测试的全页面文本定位产生歧义；修正为在回答预览区域定位后通过。RPC 输入阻塞、认知租约失效和工作流模型停止三组既有浏览器验收也通过。

## 边界

此改动处理框架创建并拥有的本机进程组，不提供跨主机停止保证，不撤销已经发生的业务效果。无法向仍存活进程组发信号时继续报告失败，不伪装为清理成功。测试未使用真实模型服务或生产数据。

候选包按当前源码、wheel 和包内外校验清单核对；未发布，本轮不重复全新环境安装。最终测试数量、命令、日志、截图和摘要见 [验收记录](process-cleanup-verification-20261102.json)。

最终通过 1144 项后端测试、787 项前端测试和四组浏览器验收。候选包的 143 个程序文件与当前源码一致，包内 wheel 与独立 wheel 相同，包内外 SHA-256 清单通过。
