# 运行列表浏览位置恢复

2026-11-03。当前源码改进，版本仍为 1.3.0，尚未发布。

此前搜索、筛选、排序和分页栈只存在于页面内存。进入详情后直接返回可以保留，但刷新页面会回到默认列表；同一页面的多个浏览器历史条目也无法各自恢复条件。初始新增的 3 项回归全部失败。

## 当前行为

运行列表把关键词、状态、智能体、领域、起止日期、排序、游标与分页栈，以及筛选面板展开状态，保存到当前浏览器历史条目。刷新第三页仍读取第三页，详情刷新后返回也会恢复原条件；浏览器前进、后退分别恢复目标条目，不被后来使用的条件覆盖。与现有滚动位置记录共存，目标条目已有的滚动位置优先。

保存按租户、工作空间和执行身份隔离。切换工作空间从该空间的条件开始，其他身份或空间的记录不会套用。显式导航前先保存当前条件，确保全局搜索等入口指定的新查询不会被旧条目覆盖。

仅保存查询条件，不保存运行结果、正文或读取错误，不把条件加入 URL。每次刷新从服务端重新读取；读取失败保留目标条件和页码，可明确重试原页。迟到的旧响应继续受请求、路由和空间校验保护。

保存前和恢复前均检查字段、状态和排序枚举、真实日期及日期顺序、游标与分页栈结构。关键词最多 16000 个 JavaScript 字符单位，每个游标最多 2048，分页栈最多 1000 项，查询序列化最多 1048576 个字符单位；这些是应用保护上限，并不保证浏览器允许同样大小的历史条目。

损坏的匹配条目被忽略，并提示当前列表将重新读取；刷新时使用默认条件，页面内已有有效条件则保留。显式选择新条件后清除旧恢复提示。浏览器拒绝保存时，当前筛选和读取继续工作，同时提示刷新后可能无法恢复；保存恢复后更新为最新条件。失败期间此前成功保存的条件仍可能被浏览器保留。

本轮还修正了恢复按钮的焦点丢失：列表重绘会按稳定标识恢复“刷新列表”“重试读取”“返回上次结果”和“返回第一页”的键盘焦点。

## 验证

新增 10 项条件恢复回归，覆盖历史条目、作用域隔离、损坏条件、存储异常、新鲜读取、迟到响应和显式导航。819 项全量前端回归与 38 项运行目录、HTTP 后端测试通过，4 组相关浏览器验收通过，详细结果见 [验收记录](run-history-state-verification-20261103.json)。本轮未改动后端生产逻辑，未重复全量后端测试。

隔离浏览器使用 137 条合成任务，验证完整筛选后的第三页刷新、恢复页读取失败与重试、详情刷新后返回、多个列表条目的前进后退、模拟历史保存拒绝、真实工作空间切换，以及损坏条目恢复。浏览流程无 POST、无页面脚本错误，截图已目视核对。另验证全局搜索与阅读导航。

原有运行历史验收首次在大字号布局检查中出现焦点丢失，单独复跑曾通过。检查发现错误区按钮缺少稳定焦点标识，后台刷新触发重绘时会丢失焦点。增加主动重绘断言后稳定复现，随后补齐标识并验证所有恢复按钮；保留原八组深浅色、1024 / 1440 像素宽度与正常 / 两倍文字布局检查。

## 范围

这是当前浏览器历史条目的恢复能力，不承诺新标签页、书签、分享链接、浏览器清理后或跨设备恢复。运行记录变化后重新读取可能得到不同结果；保存的页码不是冻结的数据快照。无效日期的未提交草稿不纳入恢复。
