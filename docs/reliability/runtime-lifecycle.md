# 运行时配置页的返回恢复

2026-11-03。源码改进，版本保持 1.3.0，尚未发布。

配置页离开时原先会解绑编辑器，浏览器从页面缓存返回后却没有重新绑定：表单仍然可见，编辑和保存无法正常继续。离开前正在保存时，缓存里的控件还会保持禁用。

现在离开时先保留表单原始输入与原保存编号，再解除旧编辑器。页面恢复后恢复控件状态并重新绑定；无未决保存时只读核对当前配置，有未决保存时提示用户明确核对。恢复本身不会提交保存。恢复前的读取与保存响应属于旧编辑器，不能覆盖新输入或回退当前版本。初始、重复的恢复事件以及其他页面不会重复创建配置编辑器。

同时修复缓存冻结时保存滚动位置的处理。此前在 `pagehide` 内写入历史记录，导致本机 Chrome 返回时报告 `IgnoreEventAndEvict` 并驱逐缓存。对 `persisted=true` 的离开事件，现在只保存内存与标签页存储中的位置；普通离开仍保留原历史记录写入。缓存返回和重新加载式返回都验证了位置恢复。

## 验证

新增 6 个交互用例覆盖恢复绑定、未提交的原始输入、保存中断、迟到读取、存储不可用和无关路由。修复前其中 5 个失败；修复后完整前端回归 **981 项测试通过**。

**5 组浏览器流程通过**：新增页面生命周期流程，以及配置保存、运行记录恢复、读取交互、会话流回归。新增流程分别验证：

- 独立临时 Chrome 通过原始 CDP 实际离开与返回，文档标识保持一致，`pageshow.persisted=true`，导航类型为 `BackForwardCacheRestore`。原输入与滚动位置保留，恢复后可明确保存。
- 默认 Playwright Chrome 重新加载式返回，草稿和滚动位置保留，返回本身没有写请求。
- 在真实浏览器和临时 HTTP 服务中，受控触发 `pagehide`／`pageshow`，配合延迟保存、延迟读取、存储失败和路由切换，验证控件恢复、原编号保留、旧响应隔离和显式核对。这些异步案例不是实际缓存导航。

当前服务的 `no-store` 响应在本机 Chrome 中阻止了缓存恢复。真实缓存案例仅在临时测试服务中将 HTML 响应改为可缓存，API 和生产服务的缓存策略保持原样。测试不承诺所有浏览器都会缓存页面，也不把缓存作为草稿持久化保证。存储不可用时，整页刷新或关闭仍可能丢失内存草稿。
