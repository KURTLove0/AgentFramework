# 未引用资料的来源核对

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

此前的历史依赖从显式引用开始追溯。若模型收到自动提供的资料，或调用工具搜索、读取资料，却在最终回复中没有填写引用，资料撤回后，旧回复仍可能被交给后续模型。三项失败回归分别重现了自动资料、原生工具读取正文和原生工具搜索结果这三条路径。

## 当前行为

组装历史时，来源依赖进一步包含以下证据所证明的知识资料：

- 当轮有效上下文清单中已选中的 `KNOWLEDGE` 资料；
- 上下文清单明确提供的知识搜索或读取证据；
- 状态为 `VERIFIED` 的受控知识搜索、读取回执及对应证据。

上下文清单继续检查摘要及运行、操作者、项目和环境。读取证据核对证据编号、内容摘要、租户与运行绑定、项目范围，以及原生读取回执中的工具类型。清单列出的证据摘要必须与实际证据一致；缺失或无法核对的证据会让相关旧回复变为不可核对提示。

来源仍在调用前按当前权限、发布状态、内容摘要和有效期重新验证。原报告的引用列表不会被补写，原报告、原生读取回执、证据和冻结任务继续保存。依赖可沿已有多轮历史机制传递。

没有进入上下文的候选资料、因预算被排除的资料、`PREPARED` / `REJECTED` 读取，以及未被清单或已验证回执关联的证据，不会给回复附加来源依赖。已有完整来源失效提示也被识别为屏蔽边界；旧格式重建不会沿这类提示重新继承其原始来源。

## 验证

新增 13 项回归覆盖三条无引用路径、有效来源去重、排队后撤回、上下文预算排除、未交付读取和孤立证据、证据缺失与摘要不符、范围错误、清单证据独立证明、清单与原生证据冲突，以及证据和检查点的快照一致性。

首轮相关回归还发现一项旧格式边界问题：已经在组装阶段替换成失效提示的消息，没有完整出现在旧清单的失效轮次列表中，新增来源追溯会错误恢复其依赖。现已集中识别三种既有完整失效提示，并将其作为重建终点及本次失效记录；原回归不变并已通过。

浏览器分别通过自动资料与真实受控搜索/读取生成没有引用的回复，然后暂停下一轮、撤回资料、刷新并恢复。模型替身未收到旧正文，原报告和冻结输入完整保留，工具读取证据仍可审计。两个对话各调用模型两次，原生路径只发生最初的两次工具调用。

同一份 60 轮、没有来源依赖的合成历史，组装使用 4 条 SQL，Python 累计解码 5,291 字节，三次测量耗时中位数约 7.0 毫秒。输出仍为 119 条消息、15,216 字节，与此前摘要相同。存在上下文清单或读取证据时，需要额外读取并核对这些记录；该测量不代表生产延迟。

## 边界

这是保守的资料接触记录，不判定模型的哪句话实际使用了资料。原生回执在响应交付前持久化，已验证但交付结果不确定的读取也按可能已提供处理。因此资料撤回后可能屏蔽整轮旧回复，即使其中部分文字与资料无关。

规则覆盖已治理知识资料及其持久化记录，不从自由文本推测没有记录的来源，也不能收回撤回前已经发出的请求。测试使用隔离临时资料和固定模型替身，不验证真实模型理解质量，没有使用生产数据。

最终测试、测量、源码摘要和候选包信息见 [验收记录](source-exposure-verification-20261102.json)。候选包未发布，本轮未重新进行全新环境安装验收。

最终通过 1090 项后端测试、787 项前端测试，以及未引用资料、历史来源依赖、历史引用上下文和长消息四组浏览器验收。候选包的 143 个程序文件与当前源码一致，包内 wheel 与单独 wheel 相同，内外校验清单通过。
