# 实时对话的顺序与操作详情恢复

2026-11-02。当前源码改进，尚未发布。

实时推送和后台轮询会交错到达。只比较更新时间无法区分同一时间戳下的新旧事件，也无法处理系统时钟回退。此前推送还会用仅含执行提示的当前轮次替换完整详情，授权等操作信息可能因此消失。

## 持久化顺序

对话快照新增 `snapshot_format: 1`。每个轮次包含检查点版本 `checkpoint_version`、最新事件序号 `event_seq` 和派发状态 `dispatch_state`；这些字段与正文、过程记录在同一数据库快照中读取，不增加数据库表或持久化字段。

页面先比较对话版本及当前轮次，再比较各轮次的持久化位置。事件单独增加、检查点推进、下一轮开始和排队派发失败都可以被识别。新格式不依赖更新时间排序；在同一持久化位置，允许更新执行提示和租约状态。旧格式保留已有时间戳处理方式。

迟到的片段或轮询不能覆盖较新的事件。格式修复产生的新片段即使更短，也按事件顺序正常采用。错误任务、缺失轮次、非法顺序字段和无效 JSON 会被忽略，不把连接标记为刚刚收到有效内容。流的归属包含租户、用户、工作空间和任务；旧连接或旧身份的事件不能改写当前页面。

## 操作详情与等待状态

推送中的执行提示在读取开始前采样，与可恢复状态使用同一份进程观察。只有当前运行 ID、检查点版本和事件序号全部匹配时，页面才保留已有的完整操作详情。持久化位置变化后，旧提案不再附着到新状态；需要操作的结构变化会触发只读刷新。

同一位置的完整 HTTP 详情可以补回操作信息，不会因连接仍然活跃而被无限保留的轻量推送挡住。重连收到相同位置时继续保留匹配的详情。任务进入等待授权后，服务发送当前状态和结束事件，页面刷新完整提案，避免空闲流持续覆盖操作入口。

正文增量仍使用原有局部更新，保留输入、光标、阅读位置、搜索和 Markdown 交互。顺序字段不进入结构渲染指纹，不会因为每次事件推进而重建整页。

## 验证与边界

单元回归覆盖同时间戳旧事件、时钟回退、派发失败、轮次切换、身份切换、无效推送、格式重试和完整详情恢复。HTTP 用例确认等待授权会结束流，导出保留持久化位置且不包含进程内执行提示。

浏览器夹具暂停合成模型，在检查点和时间戳不变时保存一条新的公开过程事件。随后断开推送并返回较旧的真实详情，检查新增记录、正文、输入焦点和光标不会倒退，再验证重连与完整详情恢复。授权、多轮对话、搜索及 Markdown 阅读另有浏览器回归。

这些顺序字段描述控制数据库中的持久化进展。进程提示、租约过期和独立业务库统计仍可能在相同位置变化；本次不承诺它们与所有网络响应具有统一顺序。SSE 与 HTTP 仍独立交付，没有跨请求事务。没有调用真实模型、操作日常数据、修改版本号或发布。
