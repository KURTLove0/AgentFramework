# 多页面任务草稿保护

2026-10-30。当前源码改进，尚未重新生成发行包。重点保护新建任务设置在自动保存、提交、放弃及多页面编辑之间的状态。

## 使用

- 自动保存发生冲突时，保留本页输入并显示“设置草稿已在其他页面变化”。后台暂停自动重试，避免反复发送过期版本。
- “查看已保存版本”只读取和展示另一份设置，不替换本页输入。核对后可选择“保留本页设置并保存”或“使用已保存设置”。选择保存时仍核对刚查看的版本；另一页面再次修改后，会重新提示冲突。
- 草稿冲突不阻止按本页目标创建任务。任务创建成功时，仅清理本页已查看的草稿版本；较新的草稿继续保留，创建回执也保留它的内容和版本。
- 放弃草稿的确认框显示将清理的目标。确认期间若有新版本，保留输入和确认框，提示重新检查。“重新检查草稿”只读取新版本，需要再次明确确认才会清理。
- 放弃请求失败或暂时没有回执时，输入和页面继续保留。请求等待期间阻止重复提交、关闭确认框和切换工作空间。网络恢复后的重试仍核对原版本，不能误删后来新建的草稿。
- 关闭已经自动保存的设置窗口继续保留服务端草稿；明确点击“放弃设置”才会请求清理。没有恢复或保存过草稿的本页，只放弃本地输入，不清理其他页面的草稿。

草稿保存与读取失败在设置窗口内给出提示和核对入口，不用错误状态覆盖用户输入。提示支持读屏播报，深浅主题保持同一动线，长目标在比较区换行并限制滚动高度。

## 版本与存储

`task_drafts` 仍按租户、工作空间及操作人隔离。放弃或提交清理后保留原记录，以 JSON `null` 表示无草稿，同时增加 `revision`。之后保存新草稿继续增加版本，不再从 0 或 1 重新开始。

例如“版本 1 的草稿 → 放弃后版本 2、无正文 → 新草稿版本 3”。旧页面携带版本 1 的保存或放弃请求会失败，不能把版本 3 当作旧版本 1 处理。初次从未保存过的空间仍返回版本 0；无草稿不再意味着版本一定为 0。

清理与版本递增在同一事务内完成。放弃请求的重复回执不会再次递增；任务提交中的草稿清理与运行创建沿用同一事务。空间删除后的旧进程也不能继续保存或放弃该空间的草稿，恢复空间后原草稿和版本仍保留。备份继续保存现有表中的内容及版本，没有新增数据表。

## API

| 请求 | 协议与结果 |
| --- | --- |
| `GET /api/task-draft` | 返回 `draft`、`revision`、`updated_at`；`draft` 可为 `null`，此时仍可能有非零版本 |
| `POST /api/task-draft` | 保持 `{revision, draft}`，需提供上次读取的版本；过期时返回 409，保存内容不变 |
| `POST /api/task-draft/discard` | 需要 `{revision}`；过期确认返回 409，无效或缺少版本返回 400；成功返回保留版本的空草稿回执 |
| `POST /api/tasks`、`POST /api/runs` | `clear_draft: true` 时需同时提供非负整数 `draft_revision`；任务创建时仅清理匹配版本，版本不同则保留草稿并继续创建任务 |

任务创建回执增加 `task_draft`，返回提交事务看到的草稿状态；相同任务提交编号重试时返回当前草稿状态，不再次清理。草稿清理版本不参与任务身份，改变它不会把同一目标重试误当作新任务。

当前客户端使用新协议；旧客户端不带版本的清理请求会被明确拒绝，避免无条件清理。界面不会把旧版本回执或其他工作空间的回执覆盖到更新后的草稿。保存、重新检查和放弃请求冻结目标工作空间，处理中阻止交叉切换。
