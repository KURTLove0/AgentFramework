# 待核对任务的编辑恢复

2026-11-03。源码改进，版本保持 1.3.0，尚未发布。

原来的待核对任务记录只包含原提交，后续输入依赖服务端设置草稿。草稿尚未保存或保存失败时，刷新可能丢失后续修改；存在另一份服务端草稿时，恢复还会直接采用它，混淆原提交与本页正在编辑的内容。浏览器存储写入失败没有单独提示。

现在同一标签页的待核对记录使用第二版格式，分别保留原提交和本页编辑。编辑内容包含未经裁剪的目标文字、所选智能体、来源任务，以及本页是否拥有设置草稿和已核对的草稿版本。输入、选择、输入法结束和页面隐藏时都会更新编辑副本，不会因此改写原提交编号或内容。

刷新后优先还原本页编辑，包括空目标和清空的智能体选择。服务中另有设置草稿时显示已有核对入口，必须明确选择“使用已保存设置”或用本页设置替换。采用草稿只改变本页编辑，原提交仍可独立核对。如果另一页面更新了本页曾拥有的草稿，保留原来核对的清理版本，暂停自动保存并要求核对，避免覆盖或清理新草稿。

无法再选择的智能体会显示为不可用的原选择。原任务仍可通过提交编号查回；明确另建时需要重新选择可用智能体，归档选项不能直接开始新任务。

本机存储失败会显示刷新恢复可能不可用的提示，并在离开页面时触发浏览器原有确认机制；当前页面继续保留输入，恢复可写后再次记录会清除错误提示。完成核对后若清理本机记录失败，会明确告知用户，并避免同一页面立即重新恢复已处理的编号。刷新后仍可能需要再次只读核对。

旧版记录缺少独立编辑副本，继续兼容原来的服务端草稿恢复方式。新版编辑副本损坏时，只恢复可核对的原提交，另行提供服务端草稿选择，不采用损坏字段。记录仍按租户、操作人和工作空间隔离；配置管理的返回过程可继续保留同一份任务编辑。

**5 组浏览器流程通过**：新增编辑恢复流程，以及异常回执、任务提交、设置草稿和任务复用。新增流程让临时服务实际受理后丢弃回执，阻止设置草稿写入，再修改目标和智能体并刷新；确认本页内容、原提交和另一份服务端草稿分别保留。明确采用草稿并再次刷新后，仍可查回原任务。模拟本机存储失败后验证提示、恢复可写后的持久化，以及原智能体归档后的重新选择。最终只有三次明确提交创建三项任务，独立服务端草稿仍存在，未调用真实模型。

恢复能力限于当前标签页会话；关闭标签页、清理站点数据或持续拒绝本机存储时，不能保证刷新后保留内容。服务端已受理任务不依赖这份编辑副本，核对与重复提交仍使用原来的持久化回执和版本检查。
