# 完整任务包

2026-11-03。源码改进，版本保持 1.3.0，尚未发布。

此前，ZIP 记录包只覆盖一轮执行，整段对话文档也不附带消息修改历史和所有轮次的审计材料。现在可以一次下载整项任务，把已保存的要求、回复、修改过程和各轮运行记录放在同一份可核对的文件中。

## 使用

打开任务，进入“任务信息”，点击“下载完整任务包”，再点击“下载 ZIP”。“导出完整对话”默认选择 Markdown，也可在同一窗口切换为 JSON 或 ZIP；选择后再明确下载，失败可重试。2026-11-04 的界面更新见 [选择导出格式与失败恢复](export-formats.md)。“下载本轮记录包”仍用于单轮执行。

完整任务包反映下载请求开始读取时的状态。任务正在进行时也可下载；后续保存和执行不会改变已下载文件，可以稍后再下载最新版本。排队和取消的消息保留在对话中，只有已经创建的执行才附带运行记录。尚未发送的输入和未保存的编辑不在包内，下载操作保留这些草稿。

下载失败显示原因并提供重试。准备期间重复点击只发起一个请求；关闭窗口、切换任务或工作空间后，旧请求不会触发迟到下载。界面显示“已交给浏览器下载”，最终保存位置和完成情况可查看浏览器的下载记录。

## 内容

ZIP 使用六个平铺文件，不嵌套其他 ZIP：

| 文件 | 内容 |
| --- | --- |
| `conversation.md` | 可离线阅读的整段对话、各轮实际状态及导出时间 |
| `conversation.json` | 对话结构、任务名称与归档信息、轮次、运行边界、修改版本及读取范围 |
| `edit-history.md` | 每次修改的轮次、版本、保存时间和修改前后完整文字 |
| `edit-history.jsonl` | 按轮次和修改版本排列的完整修改链；没有修改时为空 |
| `runs.jsonl` | 每个已创建轮次一条记录，含完整运行结果、事件、证据及上下文清单 |
| `manifest.json` | 格式与应用版本、读取时间、租户／空间／主体、轮次和修改计数、文件大小与 SHA-256 |

`runs.jsonl` 的每条记录包含 `turn`、`captured_at`、`run`、`events`、`evidence`、`context_manifests`。`run` 沿用现有完整运行结果，包括冻结任务、实际状态、动作及停止记录。没有为排队消息制造空运行；停止或失败的实际运行仍按真实状态导出。重试轮次继续保留对话中的来源关联。

## 离线校验

```bash
python -m agent_framework verify-export /path/to/TASK_ID-task-export.zip
```

也可校验已经解压成平铺文件的目录。命令只读取文件，不初始化执行器，不调用模型，也不恢复数据库。原有单轮记录包继续兼容。

新格式标识为 `agent-framework-task-export`，格式版本为 1。校验先检查文件集合和大小，再读取内容，检查 SHA-256、对话身份、工作空间与主体范围、各轮运行版本、状态、回复、连续事件序号，以及修改历史是否完整衔接当前消息。缺少或重复执行、混入其他任务、断裂修改链、未知路径、损坏内容或清单计数不一致都会失败。

两份 Markdown 同时记录自身哈希及对应 JSON／JSONL 的来源哈希，历史文件校验不依赖当前版本重新渲染文档。`valid: true` 表示完整性与内部对应关系检查通过，不表示任务成功，也不是数字签名或来源真实性证明。执行结果仍以包内状态为准。

## 一致性与接口

`GET /api/tasks/{id}/export?kind=bundle` 返回 ZIP；子轮次编号会归一到根任务。原 `kind=json` 和 `kind=markdown` 保持兼容。请求沿用现有租户、工作空间、项目和主体检查，逐轮确认执行属于当前范围。任务名称与归档信息一并读取，收藏标记不进入对话文档，已有收藏操作审计仍属于原始执行事件。

对话、所有修改、运行结果、事件、证据和上下文复用同一个 SQLite 读取事务。WAL 写入可继续提交，但新保存的内容只出现在下次导出。停止元数据统一使用同一快照中的完整数据库记录，避免摘要 JSON 对时间戳的舍入造成两种表示不一致。读取不触发排队调度、任务登记或详情接口的运行处理。

包内内容总计上限 256 MiB，清单独立受 64 KiB 限制。生成和压缩目前在内存中完成，超过上限应分别导出对话文档及各轮记录；上限不是进程内存占用保证。上下文清单保留已保存的来源记录，不会下载外部知识库或附件。本功能用于交付与核对，整个工作台迁移仍使用备份恢复功能。

## 验证

新增 18 项后端测试覆盖多轮完整性、排队取消、修改链、子轮次入口、并发修改与检查点、只读旧数据库、停止元数据、任务名称与归档、权限、大小上限、篡改拒绝、历史渲染兼容、CLI 与真实 HTTP 下载。新增 11 项前端测试覆盖明确下载、工作空间固定、重复点击、失败重试、超时、响应格式、窗口关闭和身份切换后的迟到结果。

浏览器以临时离线智能体实际下载 ZIP，再调用现有 CLI 校验。流程包含两次消息修改、取消排队、执行前后下载、独立草稿保留、503 重试和切换任务。布局覆盖深浅色、1024／1440 像素宽度和正常／28px 字号，检查焦点、操作区边界和内容横向溢出。已检查 [浅色下载窗口](task-export-light.png) 和 [深色下载窗口](task-export-dark.png)。

完整回归通过 **1299 项后端测试、925 项前端测试及 4 组浏览器流程**。构建及源码校验见 [验收记录](task-exports-verification-20261103.json)。使用隔离合成数据，没有真实模型或业务系统调用；本次未发布，也未重复全新环境安装。
