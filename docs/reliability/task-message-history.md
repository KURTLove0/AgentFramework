# 消息修改记录

2026-11-03。当前源码改进，版本仍为 1.3.0，尚未发布。

已修改的消息提供“已修改 · 查看记录”入口。窗口展示最初提交的消息、每次保存前后的完整文字和保存时间；运行已经创建时，顶部显示该运行实际采用的要求。用户可复制任一版本，用于核对或另行补充。查看、翻页和复制不会保存编辑、派发消息或改变原有草稿。

## 浏览与恢复

修改按版本从新到旧排列，默认每次加载 10 条。打开时固定当前查看范围；浏览期间其他页面又修改了消息，后续翻页仍沿用原范围，同时展示最新消息和“有新修改”提示。点击“刷新记录”才从最新版本重新开始，避免分页重复或漏掉旧版本。

加载更早记录保留已展开内容、滚动位置和键盘焦点。暂时读取失败保留已取得的记录，重试继续原页；分页位置失效时也可点击“从最新记录重读”。首次读取失败明确显示尚未取得记录，避免误认为没有修改。权限拒绝或记录不存在时清除旧内容；关闭窗口、切换会话或离开页面后，迟到响应不能重新显示旧记录。

完整文字按纯文本呈现，保留换行、空白和 Unicode，长内容可以独立滚动和键盘选取。复制失败时仍可手动选择文字。底部操作固定可见，深浅色、1024 / 1440 像素宽度及正常 / 28px 文字均纳入浏览器检查。

## 数据读取

`GET /api/tasks/{task}/messages/{number}/edits` 接受 `limit`（1–20，默认 10）和可选 `cursor`。根任务归属、工作空间与身份沿用任务会话权限。分页位置绑定租户、空间、身份、根任务及轮次，不能跨消息复用。

每次请求在同一数据库快照内读取当前文字、最新版本、原始提交、该页修改及运行中冻结的任务目标。单页查询最多读取 `limit + 1` 条修改来判断后续页，不加载完整会话详情或执行事件，也不产生写入或派发。排序使用递增版本，不依赖系统时间连续性。旧数据库没有编辑记录表时按无修改返回。

分页范围固定的是修改版本上界；顶部当前消息和实际执行要求反映本次读取的最新状态。用户须显式刷新，才能把新修改纳入历史列表。未派发或取消的队列消息没有运行要求，不会伪造执行记录。

## 验证与限制

新增 11 项后端测试覆盖完整修改链、并发写入下的一致读取、分页中新修改、时钟倒退、派发后目标、取消消息、权限隔离、无效分页、读取上限、旧数据库及 HTTP 路由。新增 15 项前端交互测试覆盖只读请求、分页合并、错误恢复、权限清除、迟到结果、关闭事件、复制、焦点与草稿隔离。

隔离浏览器创建 24 次实际修改，验证三页无重复遗漏、原始及前后内容、分页中新增修改、失败重试、两类草稿保留、迟到响应和真实运行采用的目标，并回归排队编辑、运行记录和消息发送。全部使用临时数据库及模拟运行时，无真实模型或业务系统调用。

已检查 [浅色记录](task-message-history-light.png)、[深色记录](task-message-history-dark.png) 和 [最早修改](task-message-history-original.png)。最终完整回归通过 1268 项后端测试、901 项前端测试及 4 组浏览器流程。浏览器检查中发现并修复了复制按钮编号与页面焦点恢复选择器不兼容的问题；历史轮次状态也使用“已完成”等本轮状态，避免误称最新一轮。完整日志、源码与候选包摘要见 [验收记录](task-message-history-verification-20261103.json)。本次增加查看和复制，不提供一键回滚；正在执行的要求仍不可修改。较长历史由用户逐页加载，已加载页保留在当前窗口内存中，关闭后释放；没有新增离线历史缓存。未改变版本号或发布，也未重复全新环境安装。
