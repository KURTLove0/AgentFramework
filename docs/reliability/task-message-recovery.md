# 连续对话的消息核对与恢复

2026-11-01，源码增量。补上“消息已经受理，但页面没有收到回执”时的恢复流程。发布版本仍为 1.3.0，未重新构建安装包。

## 用户操作

继续对话时，页面先保存本次消息、发送编号、当前对话版本和身份范围，再发出请求。发送结果不明确时，输入框仍可编辑，但不会因为文字变化就创建另一条消息。原消息与后来输入分别保留，发送区提供“核对发送结果”。

核对只读取记录。找到原消息后，显示已受理的轮次、原文和查询到的状态；用户选择“返回对话，保留本页输入”后继续编辑。若输入仍是原消息，清空已发送内容；若已经修改，则保留修改。已取消排队的消息也能查到，核对不会重新启动它。

暂未找到原消息时，页面读取当前对话并提供“沿用原编号重试”或“按当前对话重试原消息”。明确重试才采用核对到的对话版本，消息内容和发送编号保持不变。此后其他页面若又新增消息，服务端仍会拒绝过期版本，要求重新核对。

“暂未找到”不表示在途请求已停止。即使原请求随后才受理，重试也沿用同一编号，返回已经存在的轮次，不会再增加一轮。后来编辑的文字始终保留，需要在原消息处理完毕后明确发送。

核对失败保留原消息、输入及恢复入口。切换任务或空间后，迟到的响应不能覆盖当前对话。发送成功与核对回执使较早开始的页面刷新失效，已有较新对话状态也继续由原版本比较规则保护。

## 刷新与存储

未核对的发送保存在当前浏览器标签页的会话存储中，按租户、可信操作人、空间和任务隔离。刷新或离开后返回任务，会恢复核对入口，不自动发送或重试。现有输入草稿仍沿用原有浏览器草稿机制；核对回执不清空后来编辑的内容。

浏览器拒绝存储时，页面明确提示刷新恢复可能不可用；当前页面内仍保留原请求。关闭标签页、清理站点数据或浏览器限制存储可能影响恢复。服务端已经受理的消息、排队与运行记录不依赖浏览器存储，仍可从对话历史查看。

核对期间的动作具有各自的忙碌状态，重复点击不会增加请求。核对按钮提供明确标签、键盘焦点和状态说明；恢复区域展开时，任务面板随内容增长，使放大文字下的按钮保持可到达。

## 只读接口

新增 `GET /api/tasks/{task_id}/message-submissions/{request_id}`，返回：

```json
{
  "submission": {
    "task_id": "原任务 ID",
    "request_id": "发送编号",
    "content": "已受理的消息原文",
    "turn": 2,
    "run_id": "本轮运行 ID",
    "accepted_at": 0
  },
  "detail": "当前完整任务详情对象"
}
```

查询只读取既有 `task_conversation_turns`，不登记对话、不增加审计、不派发消息，也不清理草稿。消息事实与原文在一个读取快照中获得，随后读取当前任务详情；轮次状态可能继续变化，不把查询结果视为冻结的执行状态。

接口保留原有租户、空间与任务所有者检查。未找到返回 404；首轮任务目标不作为追加消息回执返回。已有消息在服务重启、成对备份恢复和取消排队后仍可核对。没有新增数据库表，也没有改变 `POST /api/tasks/{id}/messages` 的内容、编号和版本校验规则。

## 验证

完整前端 **576 项通过**，相关后端 **126 项通过**。新增消息核对测试为前端 **15 项**、后端 **8 项**。`task-messages`、`conversations`、`conversation-ui`、`task-permissions`、`task-submissions` 五组浏览器套件最终全部通过。

新增后端测试覆盖只读查询、未知编号、提交后派发异常、取消排队、迟到受理、原编号内容冲突、范围隔离、重启与备份恢复及 HTTP 路由。新增交互测试覆盖冻结请求、重复发送、刷新恢复、修改后输入保留、只读核对、版本采用、读取失败、错误回执、跨任务回调、存储限制与输入法保护。

浏览器实际让服务端受理消息后丢弃响应，再修改文字、刷新并核对，验证没有第二次发送；另用第二个页面制造对话版本冲突，以及查询未找到后原消息才被受理的交错，核对轮次与发送编号没有重复。浅色/深色、1024/1440 宽度、100%/200% 文字共八种布局检查横向溢出、键盘焦点和按钮可到达性。

命令、结果路径、最终计数及文件摘要见 [验证记录](task-message-verification-20261101.json)。截图：[浅色](task-message-light.png)、[深色](task-message-dark.png)。两个旧对话套件原先等待单行错误并直接重发，现已改为检查恢复区、只读核对后重试，仍检查输入保留、相同编号、历史上下文、安全渲染和任务数量。早期执行在后续浏览器套件进行中被中断，最终记录以完整结束的重跑结果为准；版式套件按新流程单独复验通过。

所有测试使用临时本地服务与合成数据，没有调用外部模型。本轮完善的是已有任务的追加消息；新建任务提交的恢复见 [任务提交回执与页面恢复](task-submission-recovery.md)，写入授权的恢复见 [普通任务授权、撤销与执行恢复](task-permissions.md)。
