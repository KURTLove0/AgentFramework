# 任务名称与编辑恢复

2026-11-03。当前源码改进，版本仍为 1.3.0，尚未发布。

任务标题此前只能显示最初的完整要求，长要求和相似任务不便辨认。现在可从任务详情的“修改名称”设置便于辨认的标题，最多 120 个 Unicode 字符。留空或点击“恢复默认名称”后保存，即重新使用最初要求。

## 使用行为

任务详情、运行列表、工作台待办和全局搜索显示自定义名称。搜索同时匹配新名称与原始要求，仍可用原要求找回记录。完整对话 JSON 导出分别保存名称和要求，Markdown 显示名称并标明原始要求。

改名不会重写执行输入、修改对话版本或改变结果。运行中的任务和已归档任务都可改名；继续对话保留名称，改名和恢复默认也不改变归档状态。最初要求始终保留在第一轮消息中。

保存前会固定本次名称和版本。保存期间可以继续编辑，迟到的保存回执只确认此前提交，后续文字仍留在输入框。多个页面同时修改时，旧版本不能覆盖新名称；页面保留本页输入，提供“核对当前名称”。

核对只读取。用户可以“使用当前名称”并放弃本页输入，也可以“保留输入，继续修改”，确认后再点击保存。核对失败可重试读取；核对后另一页面又有修改时，保存仍会再次检查版本。

关闭编辑器或刷新会保留当前标签页的名称草稿，重新打开可继续修改。保存回执丢失后，刷新不会重放请求，仍须明确核对。“放弃修改”清理本页副本；保存成功只清理属于本次提交且未继续修改的副本。浏览器拒绝存储时立即提示复制名称，当前页面仍可保存。

2026-11-04 补充：放弃修改或采用已核对名称时，如果本地恢复副本无法清理，窗口和输入保持打开，并显示可重试的原因。名称已在服务端保存、仅本地清理失败时，显示“任务名称已保存”和“清理并关闭”；该重试不再提交改名。继续输入则恢复正常编辑，沿用已保存版本，输入框与光标不被重建。直接关闭或刷新仍可能恢复旧副本，页面会明确说明。

清理前再次比较本页实际读取或保存的副本。若副本已被替换，既不删除，也不在保存收尾时覆盖它；用户可复制当前输入，重新打开核对。已被删除的副本可直接结束，当前编辑器读到的损坏副本也可明确放弃。大字号下底部按钮可以换行，所有操作保留在表单边界内。

## 一致性与边界

`task_names` 按租户、空间、执行身份和根任务保存名称、版本及更新时间。任务所属空间和执行身份继续接受原有权限检查；已删除空间拒绝改名。名称是个人整理信息，改名审计仅包含执行身份和版本，避免旧的公开运行审计泄露私有名称。

`POST /api/tasks/{task}/name` 只接受 `name` 和 `revision`。名称去除首尾空白、拒绝换行和控制字符；空名称表示默认。名称和审计在同一事务中提交。相同版本、相同状态不产生变更；紧邻的已接受版本允许相同内容重放，更旧的请求发生冲突。`GET` 同一路径只读当前详情，不登记对话、不启动任务。

名称版本独立于执行快照、对话版本和归档版本。HTTP、SSE 与运行操作回执分别合并名称元数据，迟到的操作回复不能回退已知的新名称。名称编辑器固定任务、身份、空间和页面生命周期；切换任务或空间后，旧回复不能覆盖新编辑器。

列表仅增加轻量名称列，不读取整段对话。服务启动初始化新增表；只读历史数据库没有该表时使用默认名称。核心备份与恢复包含名称。名称编辑草稿仅在当前标签页保存，不是跨设备同步，也不会改变模型收到的要求。

## 验证

新增后端验证原要求和结果保护、双字段搜索、归档兼容、并发重放、审计回滚、权限隔离、输入边界、待办、继续对话、HTTP、完整导出、备份恢复及缺少新表的只读历史库。前端验证固定提交、后续输入、刷新恢复、显式核对、旧回执、运行操作回复、身份切换、存储拒绝和待办搜索。

隔离浏览器验证完整改名流程、双页冲突、服务端已受理后丢失回执、延迟回执期间另一页面再次改名、保存期间继续输入、改名后继续对话、归档恢复默认，以及关闭和刷新草稿。归档、全局搜索与运行操作核对流程同时回归。

表单在深浅色、1024 / 1440 像素与正常 / 28px 大字号共八组布局下检查可见范围和重绘焦点；保持 CSP 开启，并断言实际计算字号。截图审阅后将表单改为单列，让说明紧跟输入框。已核对 [浅色](task-names-light.png)、[深色](task-names-dark.png)、[大字号](task-names-enlarged.png) 与 [冲突核对](task-names-conflict.png)。

全量回归首次出现一次已有 RPC 子进程清理的 `PermissionError`，单独复核原场景与进程清理测试通过。原夹具没有等待子进程安装忽略终止信号的处理器，因此不保证实际覆盖预期的顽固子进程；新增就绪握手，并明确断言主进程退出错误后重新验收。没有修改生产进程清理逻辑，也没有把该次失败记为通过。

测试使用隔离数据库、合成模型和临时子进程。数量、原始日志、夹具修正与候选包校验见 [验收记录](task-names-verification-20261103.json)。本轮未发布，未重复全新环境安装。

2026-11-04 的清理恢复补充验证增加 7 项交互测试，原实现有 6 项失败；修改后 18 项名称测试和全部 1160 项前端测试通过。浏览器覆盖清理读取／删除异常、只清理重试、继续输入后的刷新恢复和实际改名版本，另检查两个 1024px／28px 字号的清理失败布局。首次检查发现刷新清除了测试的字号规则，已重新注入并断言实际字号；目视检查随后发现长按钮挤压，已缩短文案并补上操作区换行与全部按钮边界断言。具体最终结果及原始失败记录见 [清理恢复验收](task-name-cleanup-verification-20261104.json)。此补充仅修改已有前端资源，未改变改名接口和存储结构。
