# 普通任务授权、撤销与执行恢复

2026-11-06 界面补充：[运行操作确认体验](../ui-run-action-navigation-20261106.md) 保留提交与核对期间的参数展开、选区、阅读位置和焦点，长正文独立滚动，成功后返回任务并经刷新保持焦点。本次前端改进沿用下方提案授权与回执协议；六组相关浏览器回归和 1325 项前端测试通过。

2026-10-31，源码增量。本轮将普通任务的授权与撤销绑定到用户已经审查的内容，并保存授权后的继续执行请求。发布版本仍为 1.3.0，未重新构建安装包。

## 操作行为

“确认具体操作”展示当前任务轮次的具体写入提案。确认窗口冻结任务、参数和审查标记；等待期间内容变化，服务端会拒绝旧提交，保留原窗口和错误说明。“核对当前状态”只读取服务记录；采用新内容需要明确选择“重新审查当前内容”，再确认提交。核对不会重发授权。

授权已受理但响应丢失时，核对可找回实际排队或执行状态。页面区分“等待执行”“正在执行”和“继续执行受阻”；执行失败提供“重试继续执行”，沿用原授权，不能借重试延长权限期限。旧任务、旧空间或旧确认窗口的响应不能关闭后来打开的窗口，也不能覆盖较新的取消结果。

撤销绑定当前审查到的授权。已接受的旧授权请求不能恢复后来撤销的权限；已接受的旧撤销请求也不能撤销后来重新签发的权限。撤销会移除尚未处理的继续执行请求。已经开始的动作可能完成，仍使用既有运行时检查及结果核对机制。

## 接受与恢复规则

服务端在一个写事务中读取当前运行、提案、权限与对话轮次，并检查访问范围、终态、取消请求、提案身份及参数摘要。授权、继续执行登记和 `task.permission_accepted` 回执共同提交；回执写入失败时全部回滚。相同已接受请求直接返回原回执，不增加权限或延长有效期。

继续执行请求保存在新增的 `run_permission_dispatches` 表，接受回执保存在原有 `events` 表。队列拥堵、服务关闭或执行器尚未启动时，请求仍然保留；服务恢复后推进同一任务。请求交给执行器后也不会立即删除，避免进程在工作线程启动前退出而丢失工作。

任务结束、停在补充输入或暂停状态、取消、授权撤销或过期、等待授权的提案已被替换时，原请求不再推进。执行器拒绝或工作线程中断会保留诊断并等待用户明确重试。明确重试更新执行请求时间，排除上次中断对新请求的影响；如果队列仍满，会持续等待容量恢复，不需要再次授权。授权本身的有效期保持不变。

## 接口变化

`GET /api/runs/{id}` 返回 `permissions.grant_token`、`permissions.revoke_token`、`permissions.authorized` 及可选的 `permissions.request`。对话任务应使用 `conversation.current` 中的当前轮次详情。

`POST /api/runs/{id}/grant` 和 `/revoke` 均要求：

```json
{"proof": "刚刚展示给用户的 grant_token 或 revoke_token"}
```

标记绑定租户、空间、主体、运行、冻结快照、操作及当前授权；授权标记另外绑定具体动作、工具、完整参数、摘要和资源。它用于核对审查内容，不替代身份、访问范围或 CSRF 校验。客户端不能在点击提交后悄悄读取并替换成新标记。

缺失、格式错误或额外字段返回 400；内容或状态冲突返回 409；私有任务仍先检查访问权限。队列满时，已经提交成功的授权返回 202 和持久排队状态。`POST /resume` 沿用空对象，明确重试已有请求。旧客户端需要读取并展示新详情后提交标记。

## 验证

最终命令、计数、结果路径和文件摘要见 [验证记录](task-permission-verification-20261031.json)。新增测试覆盖内容替换、参数摘要损坏、四个并发授权、回执回滚、权限撤销和过期、旧轮次、跨空间与主体、队列恢复、交给执行器后重启、显式重试与 HTTP 行为。

浏览器实际拦截请求并修改合成提案，验证旧授权被拒绝；模拟受理后响应丢失，再只读核对；用真实服务重启验证排队请求继续完成且只创建一份模拟草稿；另验证执行器失败恢复及晚到回执不会关闭其他任务的取消窗口。浅色/深色、1024/1440 宽度、100%/200% 文字共八种桌面布局中，核对按钮可聚焦、可到达且没有横向溢出。最终截图已检查：[浅色](task-permission-light.png)、[深色](task-permission-dark.png)。

早期回归发现私有任务的参数验证早于访问检查，已恢复为先检查访问权限。另一次测试命令误写取消测试模块名，已纠正并重新执行；未删减原有断言。测试均使用一次性本地服务和合成数据，没有外部模型调用。

## 当前边界

这是普通任务独立授权入口的后续完善，与 [工作流提案授权](workflow-grants.md) 共用运行时权限检查。页面内的错误和核对状态暂存于当前窗口；刷新后重新读取服务事实，没有增加跨设备的审查草稿。接受回执与继续执行请求在服务端持久保存。任务预算、期限和已完成动作保持原有规则，业务工具仍为模拟实现。
