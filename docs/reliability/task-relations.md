# 任务之间的来源与复用结果

2026-11-03 初次实现，2026-11-04 补充性能与旧库兼容改进。版本保持 1.3.0，尚未发布。

此前新任务能通过来源编号返回原任务，但原任务找不到基于它新建的结果。现在任务信息中的“查看关联任务”同时展示来源和直接复用结果，可通过名称打开，并查看读取时的任务状态、原智能体版本及归档标记。

## 查看与导航

打开任务信息，点击“查看关联任务”。来源任务展示当前名称和原始目标；来源来自另一任务的后续轮次时，链接定位那一轮。当前不可访问的来源只显示说明，不暴露其名称、目标或编号。没有来源与来源不可访问是两种不同状态。

下方“基于此任务新建”列出直接创建的独立任务，包括已归档任务。同一对话的后续消息和失败重试继续属于原对话，不会被误列成独立关联。这里不展开间接后代；打开某个结果后，可继续查看它自己的关联。

关联按记录加入顺序从新到旧排列，默认每页 20 项，可继续加载。第一次读取确定本次分页上界，新插入任务不会挤入旧范围；后续读取发现新任务时提示数量，点击“刷新关联”后进入最新范围。任务时间回拨或创建时间相同不影响插入顺序。翻页保留阅读位置与键盘焦点，刷新回到顶部。加载到最后一页时移除“加载更多关联”。

名称和状态是各页读取时的信息，已加载的卡片不会自动轮询更新。刷新会重新读取整个当前范围。分页依赖当前存储的行位置，并核对首项和上一页末项的身份；底层数据被删除或替换导致位置失效时要求重读，不声称跨多个 HTTP 请求保存完整数据库快照。

## 读取失败与隔离

首次失败显示“尚未取得关联任务”，不会冒充空列表。后续页失败保留已读记录，可以重试同一个游标，也可以从最新结果重读。权限拒绝或任务不存在时清除旧内容。关闭、切换任务、工作空间、主体或路由之后，迟到响应不能改写新的窗口；关闭同时清除窗口内容。请求是只读的，已经发出的查询仍可能在服务端完成。

来源和结果必须属于当前租户、项目及用户，已注册的对话还要匹配当前工作空间。入口可接受已经产生执行记录的对话轮次并归一到所属根任务；根任务与实际来源轮次都会检查归属。未知来源隐藏，不探测其他范围。读取不会创建对话、启动队列、迁移旧存储或修改草稿。

## 实现

`GET /api/tasks/{task_id}/relations` 返回来源、关联条目、总数、新加入数量和下一页游标。`limit` 为 1–50，默认 20。游标绑定租户、工作空间、项目、主体和根任务，携带上界、首项及末项校验信息。

查询只投影列表需要的字段，不加载完整回复、审计事件、动作或上下文正文。名称、归档、父子关系、数量及本页最新对话状态都在同一个 SQLite 读快照内取得；复用的任务摘要聚合器现在可以接收已有读连接，继续覆盖排队、等待补充、取消和待检查等状态。支持没有对话注册记录的旧根任务；只读历史库缺少后加的名称、归档表时采用默认值，不添加表。此兼容不扩展到缺少基础对话或取消结构的更早数据库版本。

查询按需执行。2026-11-04 增加按租户和 `source_run_id` 查找的 SQLite 索引，先取得当前根任务及其轮次编号，再查找候选关联；随后继续核对工作空间、项目、用户及对话轮次。没有增加业务表或改写任务正文。

可写存储在打开时为旧库建立索引，首次建立需要读取已有运行记录。索引仅包含有效 JSON，其他租户的损坏记录不会阻止建索引，原记录及现有诊断行为保留。只读存储缺少该索引时仍可查询，不执行迁移。关联的数量、分页顺序和权限检查沿用原规则。

## 关联读取性能（2026-11-04）

旧查询每次计算关联数量和分页记录时，都从当前租户的全部运行记录中解析来源及任务信息。现在先用索引定位当前任务及其轮次对应的记录，避免反复解析无关任务正文。新增回归在原有 8 个三轮任务外加入 400 个两轮任务，验证关联候选查询的 SQLite 执行工作量不会随这些无关记录成比例增长；结果和排序保持一致。

本机合成样本包含 600 个任务、每个 3 轮，共 1800 条运行记录；每轮回复约 32 KiB，另有 3 条同量审计文本。读取同一个根任务的 4 个直接关联，重复 5 次取中位数，建样本时间不计入：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 关联读取中位耗时 | 76.99 ms | 2.70 ms |
| 整次读取 SQLite 指令数（近似） | 128,900 | 40,100 |
| 其中关联候选查询（近似） | 90,900 | 2,000 |

这是本机临时库的服务层测量，不包括网络与浏览器渲染，也不是生产延迟承诺。任务摘要仍需查询历史轮次，整次请求并非恒定工作量。查询计划使用原 SQL 和绑定参数检查，确认按租户与来源编号命中索引；不能仅凭展开参数后的 SQL 推断实际计划。原始结果见 [优化前](task-relations-index-benchmark-before-20261104.json) 和 [优化后](task-relations-index-benchmark-after-20261104.json)。

当前实现可用以下命令复测；脚本仅创建临时合成数据，结束后清理：

```sh
.venv/bin/python scripts/benchmark_task_relations.py --tasks 600 --turns 3 --body-bytes 32768 --repeats 5
```

旧库覆盖新增的索引建立、原始运行记录保持不变、升级前游标继续翻页，以及没有对话注册的来源根任务。只读缺索引、缺可选名称和归档表的历史库继续可读，读取前后数据库结构完全一致。损坏 JSON 的兼容测试同时确认其他租户不受影响、当前租户原有诊断仍会报错。
