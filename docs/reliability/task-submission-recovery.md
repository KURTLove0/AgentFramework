# 任务提交回执与页面恢复

2026-10-30。当前源码改进，尚未重新生成发行包。适用于简化的新建任务界面及其 `POST /api/tasks` 接口。

## 使用

任务提交后未收到回执时，页面保留目标与所选智能体，显示“提交结果需要核对”。不会因为继续编辑目标就自动换用新编号并创建第二项任务。

- **核对提交结果**：只读取当前身份、空间下的原任务；找到后显示已受理的目标与智能体版本，可以打开原记录。
- **沿用原编号重试**：本页设置仍与原提交相同时，重试同一份请求，包括原草稿清理版本。不会因后台草稿保存而改变这次提交。
- **使用所示配置，保留目标**：暂未找到原任务时，先展示当前智能体的版本、模型、指令、Skill 和读取配置。明确采用后保留本页目标，后续提交继续使用原编号，仍受服务端版本校验保护。
- **保留本页目标，另建任务**：只有已经找到原任务时才提供。选择后准备一个新任务，仍需再次点击“开始任务”；不会点击核对后就自动重复执行。

“暂未找到”不表示在途请求已停止。查询后，旧请求仍可能先被受理；本页后续提交与它共用原编号，服务端只接受一个目标与配置。若原任务已受理但本页目标不同，返回冲突，再次核对即可打开原任务，当前输入继续保留。

核对期间会阻止重复核对、重新打开编辑器、关闭及工作空间切换。迟到的读取或提交结果不能覆盖另一个编辑会话或把页面导航到其他空间的任务。已有原任务确认后清除过时的红色网络错误。

## 刷新与浏览器存储

发出请求前，在页签的会话存储中保存原请求与身份范围，包括目标、智能体版本、来源任务、提交编号和原草稿清理版本。按服务端提供的租户、可信操作人、工作空间分别保存。

刷新后重新打开新建任务，会恢复待核对编号；已有较新的设置草稿优先恢复为本页输入，原提交仍单独保留以便核对。恢复和读取都不会自动发起任务。打开已受理任务、确认另建或收到成功回执后清除对应待核对记录。

存储作用域是同一浏览器页签会话。关闭页签、清理站点数据或浏览器禁用存储可能使刷新恢复不可用；存储写入失败时，当前页面仍保留原请求。服务端已接受的任务及审计不依赖浏览器存储，可以从任务列表查看。

原草稿清理请求始终保持冻结；成功回执或只读查询不会删除后来保存的草稿。详见 [多页面任务草稿保护](task-drafts.md)。

重试不会跳过服务端的提交事务核对。智能体或 Skill 在核对后再次变化时，仍拒绝旧配置，见 [任务接受时的配置一致性](task-acceptance.md)。

## 只读查询接口

`GET /api/task-submissions/{request_id}` 返回 `POST /api/tasks` 接受的原任务详情、当前设置草稿及：

```json
{"submission":{"request_id":"原提交编号","run_id":"原任务 ID"}}
```

任务 ID 沿用原有租户、工作空间、可信操作人及提交编号的确定性映射，没有新增回执表。查询进一步核对任务身份、空间、对话执行方式及首轮上下文，不能把其他普通运行当成提交回执。

未找到返回 `404`；读取不会启动执行器、登记对话、增加审计或清理草稿。已完成任务、归档智能体的历史任务仍可查询。服务重启及成对备份恢复后，相同身份仍能查回原记录。每日派发等内部入口显式指定的自有运行 ID 继续按其原协议恢复，不使用此界面提交查询。

会话元数据现在包含服务端可信操作人。刷新过期页面令牌时，客户端同时核对租户和操作人；身份变化会停止自动重试，不把原身份的写入转给另一个身份。

## 界面细节

恢复区域在原任务表单内，使用现有提示色与按钮样式。相同内容不会重建按钮，避免输入框失焦时吞掉点击；核对结束后仅在原焦点因按钮移除而丢失时恢复焦点，不抢走正在编辑的输入框。

2026-11-06 补充：读取期间继续保留核对内容与按钮，在原按钮显示进度。原目标与长配置可用键盘滚动，相同内容保留展开、阅读位置及正在阅读文字的选区；已受理回执不会把焦点从核对按钮移到打开任务。等待期间的新输入焦点继续优先。专项与相关回归见 [任务提交核对的等待、焦点与阅读](../ui-task-submission-navigation-20261106.md)。

任务弹窗底部支持提示与操作分行，提示不会再把“开始任务”挤出弹窗。原目标与当前目标分别展示；当前设置变更不会自动改写原提交内容。
