# 工作流草稿的标签页恢复

2026-10-31，源码增量。基于 [工作流保存回执与编辑恢复](workflow-saves.md) 补上刷新和关闭编辑窗口后的恢复入口。本轮未重新构建安装包，发布版本仍为 1.3.0。

## 使用方式

编辑工作流时，页面在当前标签页保留恢复副本。流程名称、说明、未填完的节点目标、依赖、分支、汇合、检索设置、专用智能体草案与节点位置均包含在内。对话设计给出的流程提案在打开编辑器时就会保留，无需先完成所有必填项。

底部“保留草稿并关闭”先确认浏览器能保留副本，再关闭编辑器。工作流目录显示“继续编辑工作流”或“继续核对原保存”。恢复只重建编辑窗口，不创建流程、智能体或运行，也不自动提交。

保存开始前，页面先保留原提交编号和原内容。响应丢失后修改本页输入，副本会同时保留原提交和后续修改。刷新或本地服务重启后，仍可只读核对，或者明确重试原保存。核对后继续编辑沿用已确认的流程，并复用原提交已创建且未修改的专用智能体。

恢复入口与正常编辑沿用既有版本检查。如果流程或智能体后来变化，最终保存仍会拒绝旧版本；浏览器副本不会成为覆盖当前记录的授权。

## 保留、放弃与故障处理

- 每个租户、身份、空间在当前标签页保留一份未完成编辑；不同空间相互隔离。已有副本时，新建或打开其他流程会提示先继续或放弃，避免静默覆盖。
- 选择“保留草稿并关闭”不向服务写入；若浏览器拒绝存储，编辑器保持打开并说明刷新可能丢失输入。用户仍可主动保存到服务。
- 从编辑器选择放弃，或在目录确认“放弃恢复副本”，只清理相应浏览器副本。原提交可能已经受理或仍在处理中；放弃不会取消它，也不会删除服务中的流程或智能体。
- 已保存结果清理自己持有的副本；旧定时回调不能重新生成它。清理失败会提示已经保存并保留可核对的原请求信息。
- 恢复副本带有独立标记。副本已变化时，旧编辑器不能覆盖或删除新的内容；等待放弃确认期间切换身份或空间也不会清理其他范围的副本。
- 损坏、超过大小限制、身份不匹配、请求内容不一致的副本不被采用，只提供明确的移除入口。

## 实现范围

恢复数据使用 `sessionStorage`，键为 `workflow-edit:v1:` 加租户、操作者和工作空间。单份记录限制为 500,000 个字符串字符，包含有界的编辑数据、必要视图状态及原提交快照；不会保存 CSRF 令牌、运行时凭据或缓存的服务回执。

草稿读取验证字段类型、数量和长度、节点与依赖标识、智能体草案、布局范围以及原提交编号和内容绑定。允许尚未填完的字段和未通过业务校验的草稿继续编辑；实际提交仍由原有页面与服务端规则校验。恢复不信任浏览器保存的“已接受”或“当前版本”数据，服务状态通过既有接口核对。

输入、选择、画布操作在短延迟后同步副本；保存前、页面刷新、页面离开、导航和空间切换会补做同步。恢复时不重放写请求。存储失败时可在当前页面继续使用内存中的输入，但界面不会把它宣称为刷新后可用的副本。

新增逻辑集中在 `workflow_draft.js`，复用既有工作流编辑器、保存核对与确认弹窗。服务端只增加脚本静态映射，没有新增草稿写入接口或数据库迁移。

## 当前边界

副本保留在当前浏览器标签页，支持该标签页刷新和应用服务重启后的恢复。它不是跨设备或跨浏览器同步，也不是长期备份；关闭标签页、清理站点数据或浏览器回收会话后可能丢失。浏览器打开新标签页时是否复制会话数据由浏览器决定，服务端仍通过原提交编号去重。

同一空间同时只提供一个未完成工作流的恢复入口。保存后的长期记录仍在服务端；节点画布布局仍属于浏览器侧视图信息。已经在途的保存不会因关闭、放弃或移除恢复副本而被取消。
