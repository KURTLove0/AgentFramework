# 工作流模型停止与进程收尾

2026-11-02。当前源码改进，版本仍为 1.3.0，尚未发布。

此前旧式工作流的 `plan`、`decide`、`compose` 调用没有接入模型停止回调。输出收集器在没有公开进度回调时还会直接使用阻塞的 `communicate`，跳过持续取消检查和实时输出预算。因此点击停止后可能一直等到模型返回或超时，格式修复也可能再发一次请求。

本机子进程回归还重现了另一处收尾问题：父进程已经退出，但子进程继续占住输出管道。只在父进程存活时终止进程组，会让关闭管道的操作等到子进程自行退出；合成用例原本约等待 3 秒。

## 当前行为

所有运行时认知调用都接入停止检查，包括旧式工作流。准备请求、登记调用和采用认知返回值之前重新核对停止意图；检测到停止后，不再发送下一次格式重试，也不采用刚返回的计划或其他认知输出。原有取消流程继续核对已经发出的业务写入。

真实文本管道始终使用有界收集流程。即使没有公开进度回调，也会并行发送输入、排空标准输出与错误输出，检查取消与期限。标准输出超过 8 MiB 时提前终止，标准错误只保留有界诊断片段。没有公开进度需求时不创建进度解析器，不额外发布模型文字。

CLI 调用均以独立会话启动。收尾向本次创建的进程组发送终止信号，等待父进程后清理仍存活的组内进程，再等待读取线程并关闭管道。父进程已经退出也会执行进程组清理。Codex app-server 的流式收尾复用相同逻辑。

模型配置、提示词、schema 和冻结协议没有变化。网络、鉴权和超时错误没有新增自动重试；原生读取和业务写入权限不变。

## 验证

修复前四项回归分别重现了无公开进度时忽略取消、输出限额未生效、停止后再次格式请求，以及父进程退出后的管道等待。修复后 83 项相关回归通过。

新增 10 项回归使用真实本机子进程，覆盖上述窗口、Codex/Cursor/Qoder 的旧式工作流调用、阻塞输入时停止、Unicode 输入完整性、错误输出缓存限制、静默超时、晚到计划拒绝，以及 Codex RPC 的派生进程收尾。扩展测试共 13 项通过，其中包含原有三项 Codex 流式协议测试。

浏览器使用真实本机子进程模拟旧式任务的模型等待：确认实际请求处于 `plan` 阶段，且没有公开进度事件，然后点击停止。配置的模型超时为 60 秒，本次测试约 424 毫秒后确认停止完成；仅启动一个子进程、调用一次模型，没有业务读取或写入。刷新后保留已停止状态和未发送草稿。该数值来自隔离夹具，不代表生产延迟承诺。

## 边界

停止在执行检查边界生效，无法撤销已经完成的模型计算或外部业务动作。进程收尾针对框架以独立会话启动的进程组；不把既有业务结果删除或回滚。已有写入的状态仍由取消核对流程确定。

测试使用固定输出或等待脚本代替真实模型服务，验证管道、取消、用量与页面流程，不验证模型理解质量；未使用生产数据。候选包未发布，本轮不重复全新环境安装验收。最终结果与摘要见 [验收记录](workflow-model-cancellation-verification-20261102.json)。

最终通过 1125 项后端测试、787 项前端测试，以及工作流模型停止、原生读取停止、持久化取消和流式任务四组浏览器验收。候选包的 143 个程序文件与当前源码一致，包内 wheel 与单独 wheel 相同，内外校验清单通过。
