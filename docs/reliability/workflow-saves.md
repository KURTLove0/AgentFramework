# 工作流保存回执与编辑恢复

2026-10-31，源码增量。发布包版本仍为 1.3.0，本轮未构建或发布安装包。

后续同日增量已加入 [工作流草稿的标签页恢复](workflow-drafts.md)：当前标签页支持刷新恢复与保留关闭。本文下方的测试记录对应保存核对初始增量，最新恢复边界与验证以该后续文档为准。

## 用户可见变化

工作流保存响应丢失后，编辑器保留原提交编号、原内容以及随后在本页进行的修改。修改名称、节点或专用智能体草案不会自动创建另一次保存。用户可只读核对原提交，也可用原内容重试；重复请求仍返回同一流程和同一批专用智能体。

核对区分别展示本页修改、原提交回执和当前版本，包括节点目标、依赖、执行智能体版本、分支、汇合与检索设置。当前内容可能已被其他窗口更新或归档，原提交回执不会替代当前状态。

- 已确认保存或明确拒绝后，可基于核对到的版本保留本页修改，明确另存为新流程，或放弃本页修改并载入所示版本。这些选择仅准备编辑器；保存仍须主动点击。
- 未找到回执不代表原请求已经停止。结果未知时继续沿用原编号，不允许把“未找到”直接转换为新提交。
- 已归档流程拒绝配置写入，即使提交使用了当前版本号。可以核对内容、载入所示版本或另存；原流程必须先恢复才能继续改写。
- 原提交已创建且本页未改动的专用智能体会被复用，包括多个节点共用一个草案的情况。提交后改动过的智能体草案会明确提示需要另建；用户核对后才可继续。新节点与新草案仍按本页内容保留。
- 核对后又修改输入，会重新显示对比并要求再次选择。并发版本检查仍在最终保存时执行；核对成功不授予覆盖后来版本的权限。
- 保存不再静默采用目录中已更新的智能体版本，用户需重新选择并核对节点使用的版本。
- 保存按钮在写入确认时恢复，目录刷新失败或缓慢不会锁住后来打开的编辑器。旧空间、旧身份、旧路由或旧编辑窗口的回调不能关闭、覆盖或解锁新窗口。

## 数据与接口

既有 `workflow_saves` 表继续在同一事务中保存流程、内联智能体与请求回执。请求内容和目标流程共同绑定请求编号，按租户、空间与操作者隔离；相同编号不能提交不同内容。

新增只读 `GET /api/workflow-saves/:request_id`，返回 `{request_id, saved}`。`saved` 是原提交当时的完整流程；当前状态使用既有 `GET /api/workflows/:id` 单独读取。明确缺失返回 404 和 `workflow_save_not_found`，其他 404、网络错误、回执不匹配均不会被当成安全重建的依据。

POST 响应及重复提交的原始响应保持兼容。已经接受的请求可以在流程后来归档后恢复原回执；新请求在写入事务内检查归档状态，并在创建任何专用智能体之前拒绝改写。失败不会留下部分智能体或保存回执。

页面保存逻辑集中在 `workflow_save.js`，保存请求固定空间和序列化内容。所有恢复选择都有编辑窗口与作用域检查，保存、核对、目录读取互相避免重入。画布坐标仍独立保存在本浏览器，不进入工作流业务数据。

## 当前边界

保存核对初始增量仅保留打开窗口中的修改。后续 [标签页恢复](workflow-drafts.md) 已支持刷新和“保留草稿并关闭”，仍不承诺关闭标签页后的长期恢复或跨设备同步。服务端已保存记录不受浏览器副本的保留与清理影响。

核对区的当前版本是一次读取结果。之后仍可能发生其他修改，最终保存继续检查版本。载入已归档版本不会绕过归档保护；实际写入仍被拒绝。现有流程历史与运行配置冻结规则保持不变。
