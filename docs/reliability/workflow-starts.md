# 工作流启动核对与恢复

2026-10-31，源码增量。补齐启动准备、结果不明确时的核对与当前标签页刷新恢复。本轮未重新构建安装包，发布版本仍为 1.3.0。

## 运行前检查

打开运行窗口时重新读取当前工作流和智能体目录，需要检索的节点同时检查知识资料。流程已归档、智能体版本变化、必需的读取失败时，保留窗口和说明，提供“重新检查运行准备”，不会创建运行。

读取属于当次窗口、路由、租户、身份和空间。关闭窗口、切换记录或打开另一流程后，较早的响应不能覆盖新窗口。重复点击提交只处理当前的一次请求；按钮在后续目录刷新前恢复，目录暂不可读不会把已创建的运行说成启动失败。

## 启动结果不明确时

发送前保留原提交编号和完整参数。网络中断、超时或响应丢失后，原请求保持不变，后来填写的变更 ID 和许可选择单独保留。

- “核对原启动结果”只读取已经存在的运行和当前状态，不创建、续跑或重新派发。
- “使用原参数重试”沿用原编号与原参数。即使后来清空了变更 ID，也能明确重试原请求；后续输入不会被覆盖。
- 查到原运行后可直接查看。若需要另一次运行，明确选择“保留变更 ID，准备另一次运行”，重新读取当前配置和显示适用的许可选项，然后再次提交。
- 首次请求被明确拒绝时，可重新检查配置；此前已经出现不确定结果的请求，不能仅因后续一次拒绝就被判断为从未受理。
- 未查到记录仅表示本次读取尚未找到；原请求仍可能在处理中。页面不因此自动换编号或创建另一次运行。
- 查到记录后再次读取失败，会明确保留上次读取的结果，不把旧状态称为最新状态。

结果核对同时验证原请求编号、流程标识、冻结流程版本和完整参数摘要。原运行已受理后，即使工作流后来更新或归档，仍可读取原运行。取消或完成后的运行也继续返回其当前状态。

## 当前标签页的恢复入口

启动尝试发生后，当前标签页为每个租户、身份、空间保留一份待处理启动。目录及流程详情提供“继续核对启动”。关闭启动窗口会保留入口，刷新或应用服务重启后可恢复原编号、原参数及后续输入；恢复本身不重发请求。

已有待处理启动时，打开其他流程的运行窗口会先恢复原启动，避免静默覆盖。不同空间的记录相互隔离，记录标记变化时旧窗口不能覆盖或删除新记录。

移除入口需要明确确认，提示该动作不会取消已受理或仍在途的启动，也不会删除运行；之后新建可能产生另一次运行。损坏或超出限制的浏览器记录不会被采用，只提供移除入口。

存储失败会说明刷新可能丢失恢复信息；当前窗口仍保留输入并可主动核对或提交。不能保留副本时，普通关闭操作保持窗口打开。已经成功创建的运行不会因为浏览器清理失败被改报为失败。

## 实现与边界

新增 `workflow_start.js`，使用按租户、主体、空间分隔的 `sessionStorage` 键 `workflow-start:v1:`。单份记录上限为 12,000 个字符串字符，校验类型、字段集合、标识、长度和参数结构；不保存会话令牌或缓存的服务回执。提交、输入变化及离开页面时更新记录。

新增只读接口 `GET /api/workflow-starts/{request_id}`。它复用现有确定性运行标识和持久运行记录，没有新增数据库表。查到后读取运行详情、队列和事件，不重新提交执行。服务端原有事务继续保证同编号、同参数并发重试只受理一份运行与派发登记；同编号改参数被拒绝。

明确不存在的运行使用专门异常和 `workflow_start_not_found` 响应码。存储内容损坏或必要字段缺失不会被误报为这个可核对的“尚未找到”结果，也不会触发重新创建。

恢复仅适用于已经尝试提交的启动，不保存尚未提交的全新运行表单。副本属于当前标签页，不是跨设备同步或长期备份；关闭标签页、清理站点数据或浏览器回收会话可能使其丢失。查看结果只代表该次读取时的状态，实际执行进度以运行详情为准。业务工具仍为模拟实现。
