# 工作流刷新与操作回执的一致性

2026-10-30，当前源码改进。检查异步请求的范围保护时发现，工作流目录和详情只核对工作空间，仍可能接受较早开始的读取。归档、保存或取消已经成功后，晚到的旧响应会把页面退回旧版本或旧状态；旧读取成功还可能清除后来一次刷新失败的说明。

隔离复现使用实际页面函数和可控延迟响应。首批 10 项回归中，改动前有 9 项失败，包括保存回执被旧目录覆盖、取消回执被旧详情覆盖、新读取被旧读取覆盖，以及切换记录后仍发布旧结果。原有的“当前读取失败时不应用半份目录”检查保持通过。

## 现在的行为

- 保存、归档、恢复使用、启动运行、恢复执行、授权和取消的成功回执会使更早的工作流读取失效。旧响应不能撤销页面中刚确认的配置、运行或排队状态。
- 新刷新先完成后，较早的刷新不能覆盖它。目录、设计对话摘要、智能体摘要和所选运行详情全部读取完成并通过范围核对后，才一起写入页面状态。
- 发起读取时固定工作空间与所选记录。每一步请求完成后核对空间、页面、所选记录及导航轮次；切换到其他运行、其他页面或离开后再返回，不会沿用旧读取。
- 智能体保存或归档后，旧工作流刷新内附带的智能体摘要也会失效，避免把刚更新的岗位状态改回旧值。
- 当前读取失败仍明确报错并保留已有内容。已经被取代的读取失败不再为新页面报错；它的成功响应也不能清除后来一次操作的刷新失败说明。
- 在取消或恢复请求等待回执时打开另一条运行，迟到的操作回执只更新对应的运行记录，不替换用户当前查看的其他运行详情。

页面已有的成功提示、刷新失败提示、忙碌按钮及重复提交保护继续工作。刷新失败时，已接受的操作结果留在页面，无需重新提交写请求。

## 实现范围

工作流读取记录本次请求序号、导航轮次和操作结果轮次，同时核对智能体目录的更新序号。成功操作推进结果轮次；新的读取推进请求序号。读取过期时停止后续请求，返回未应用；当前读取失败继续交由现有错误处理呈现。

这是同一页面中的异步响应保护，不声称多个 HTTP 接口共享一个数据库事务快照，也不能阻止其他页面或进程随后更新服务端数据。后续正常刷新仍读取服务端当前状态。无需迁移数据库或持久化页面计数，不改变后端幂等、授权、预算、执行队列与恢复规则。

新增 12 项并发界面回归，完整界面 **135 项通过**。工作流相关后端 **58 项通过**。四套浏览器验收全部通过：

- `workflow-sync`：真实 UI 发起归档和取消，拦截服务端已经生成的旧响应，控制其晚于新回执、新读取或页面切换返回；另检查新读取失败后旧响应不能清除提示。两个取消请求最终沿原记录结束，均未创建节点任务。
- `workflow-queue`：拥堵时保存启动、授权与取消，容量恢复后接续原节点，写入只执行一次。
- `workflow-agents`：画布创建专用智能体、保存回执丢失后重试、执行与配置更新校验。
- `journeys`：主要页面动线、任务与工作流详情路由，以及相关表单与导航行为。

浏览器全部使用隔离临时数据与合成执行器，不调用真实模型。新增验收暂停普通轮询计时器，手动调用同一个实际刷新入口以控制响应顺序；其他页面事件、网络请求、后端写入与执行器保持实际路径。检查 1024、1440 桌面窗口和深浅主题，验证取消提示与按钮状态、无页面横向溢出；浏览器没有未处理脚本错误。
