# Skill 目录批量读取与配置入口

2026-10-30，当前源码改进。Skill 目录原先逐项读取配置和完整历史包，数据增长后，打开技能库、创建或编辑智能体都会重复解析许多未使用的文件正文。本轮保留完整目录、版本摘要和文件描述，减少重复读取，并修复配置入口等待模型列表才切换分区的问题。

## 读取方式与兼容性

- 目录固定使用两次 SELECT：批量读取历史版本的元数据，再联接读取各技能当前版本的完整包。详情也使用两次 SELECT，只解析所选版本的完整包。历史正文仍保存在原库中，按需选中后读取。
- 同一次目录或详情请求使用一个只读快照。另一个连接在读取期间撤回或更新 Skill，当前响应的修订号、版本、状态与历史仍来自同一个检查点；后续请求可见新状态。
- 当前版本或明确选择的历史版本仍完整校验内容、文件摘要、包结构和数据库所存摘要。缺失当前版本仍报错，不能通过丢掉该条记录掩盖异常。无对应技能主记录的孤立历史不混入目录。
- 返回字段保持原有格式：草稿、已发布、撤回、归档和内置标记，以及全部版本摘要、文件大小、编码与摘要；跨租户和空间隔离保持有效。相同更新时间增加按 ID 排序，保持结果稳定。

没有增加数据库迁移或缓存。SQLite 的 JSON 投影仍会读取历史包以提取元数据；本轮减少的是传给 Python 的完整历史包及其解码工作，不能据此推断磁盘读取量同比下降。目录返回仍包含完整版本摘要，超大目录的分页属于后续工作。

## 性能复验

使用临时数据库，100 个自建技能、每个 20 个版本，加上 2 个内置技能。每个自建包包含 48 KiB 参考正文，各版本的正文和元数据不同。基准脚本保留改动前的读取算法用于对照，两种算法在同一数据库交替顺序各运行三次；构造数据不计时。运行环境为 Python 3.14.3。

| 单次完整目录读取 | 改动前算法 | 当前算法 |
| --- | ---: | ---: |
| 耗时中位数 | 301.532 ms | 123.390 ms |
| SELECT 次数 | 307 | 2 |
| Python 完整包 JSON 解码次数 | 2,104 | 102 |
| 上述解码输入字节数 | 104,826,548 | 4,995,874 |
| 返回技能数 | 102 | 102 |
| 返回内容字节数 | 557,387 | 557,387 |

该合成负载下约快 **2.4 倍**，耗时减少约 **59%**。六次完整响应的 SHA-256 相同，比较涵盖全部字段与版本元数据。计时包含查询及 JSON 解码计数开销，不含最终响应序列化；这是本机合成测量，不代表所有部署的耗时。原始记录见 [benchmark-20261030.json](benchmark-20261030.json)。

```bash
.venv/bin/python scripts/benchmark_skills.py --compare
```

脚本仅创建并清理临时数据库；可调整技能数、版本数与正文大小，默认限制历史正文预算为 128 MiB。

## 智能体编辑入口

“编辑指令”立即显示运行设置，“技能配置”立即显示高级设置并展开技能区域。模型列表在后台加载期间，保存继续受原有加载状态约束，用户已输入的内容保持原值。基础入口继续聚焦智能体名称；直接进入其他分区时聚焦对应页签，支持键盘导航。一次打开尚未完成时，后来的重复打开请求不会切换当前分区。
