# Agent Framework UI 与用户动线优化 PRD

- 文档版本：v1.0
- 日期：2026-10-26
- 评审对象：当前源码中的本机 Web 工作台
- 产品阶段：单机、模拟业务、两个领域包的 MVP
- 文档性质：代码与既有浏览器证据驱动的优化建议，不等同于真实用户研究结论

## 1. 执行摘要

当前产品已经具备完整的功能广度：工作空间、Agent、Skills、知识库、工作流、任务执行、授权恢复、每日计划、岗位评测与运行复盘均可从界面到达。既有工程评审也已证明主要操作、响应式和键盘动线具有较高完成度。

下一阶段不应继续堆叠入口或做视觉换皮，而应从“功能都能用”转向“用户始终知道下一步”：

1. **把分散在任务、工作流、每日计划和评测中的待处理事项汇总到工作台。**
2. **降低任务创建与失败恢复成本，补齐运行前检查、未提交草稿和基于原任务新建。**
3. **按业务决策组织信息，将原始 JSON、技术标识和高级配置退到诊断层。**
4. **为搜索、运行记录和工作流补齐规模化使用所需的分页、筛选与独立详情。**
5. **保持授权、模型发送许可、工作空间隔离和冻结版本语义不变。**

建议按三个里程碑交付：

- **M1｜核心任务闭环**：统一待办、运行前检查、任务草稿、恢复复制、运行详情。
- **M2｜资源与规模**：全局搜索、运行分页、工作流分区、资源生命周期与情境化权限。
- **M3｜精细体验**：移动端编辑效率、文案与视觉细节、完整可访问性补验。

## 3. 当前 UI 与用户动线盘点

### 3.1 应保持的优势

1. **执行可信**：授权、模型发送许可、MCP 许可分开审查；任务冻结 Agent、模型、Schema 和策略版本。
2. **恢复有据**：运行保留计划、动作、证据、审计和外部回读结果，不以界面状态猜测业务结果。
3. **连续配置已有基础**：任务与 Agent、Skills 之间可以保留本页输入并返回；保存失败与重复提交已有保护。
4. **结果有下一步**：运行详情会根据待授权、缺材料、失败、超时、完成等状态给出行动提示。
5. **可访问性基础较好**：44px 主要触控目标、键盘页签、焦点恢复、减少动态效果、深浅主题已有实现和实测。
6. **视觉系统稳定**：System Blue、紧凑目录、统一面板和状态标签已形成一致性，无需重做品牌风格。

### 3.2 模块地图

| 模块 | 当前主要任务 | 当前结构 | 主要优化机会 |
| --- | --- | --- | --- |
| 任务工作台 | 新建任务、看统计、进入最近运行 | 指标卡 + 最近运行 + 空状态引导 | 从“任务统计”升级为跨模块“下一步工作台” |
| 运行记录 | 搜索、筛选、查看执行与结果 | 列表与详情同页顺序渲染 | 独立详情、明确返回、分页与更多筛选 |
| 每日任务 | 配置模板、生成计划、派发与处理阻塞 | 设置弹窗 + 计划卡片 | 只显示与所选 Agent 相关的许可；接入统一待办 |
| 岗位评测 | 查看评分、提醒、评测契约 | 阈值概览 + 提醒 + 分数 + 明细 | 区分质量提醒与执行阻塞，减少重复跳转 |
| 工作空间管理 | 创建、切换、编辑、删除与恢复 | 空间卡片 | 入口可逐步收进空间选择器，主路由继续保留 |
| 智能体 | 查找、配置、检查、开始任务 | 紧凑目录 + 独立详情 + 三步编辑 | 保持现有结构，补运行前可用性检查与草稿恢复 |
| 工作流 | 设计、保存、运行、授权、恢复 | 定义卡 + 运行记录 + 设计对话 + 运行详情同页 | 定义与运行分区，降低单页信息负荷 |
| 技能 Skills | 创建、导入、校验、发布、绑定 | 目录 + 包编辑器 + 版本管理 | 保持版本安全，减少生命周期操作并排展示 |

| 能力与标准 | 查看默认岗位、能力和验收规则 | 说明面板 + 折叠技术内容 | 与 Agent/能力页建立清晰上下文入口 |
| 运行时配置 | 配置 CLI、模型、默认运行时 | 运行时选择 + 配置表单 | 将检测结果前置为任务运行前检查的一部分 |

### 3.3 UI 维度评估

| 维度 | 当前表现 | 优化判断 |
| --- | --- | --- |
| 视觉与层级 | 浅色 System Blue、深色主题、卡片、圆角、状态色和主按钮语义稳定；Agent 目录与详情的层级最完整 | 不换皮；重点减少同页竞争的主行动、重复状态和技术眉题 |
| 信息密度 | Agent 紧凑表格便于比较；工作台指标清晰；桌面留白充足 | 工作流和资源长页的首屏行动密度偏低，运行详情技术信息偏多，应按决策优先级分层 |

| 表单与编辑 | 三步任务/Agent、渐进披露、字段校验、未保存保护、提交锁定和失败恢复较完整 | 继续保留这些基础；新增内容应优先解决草稿持久化、运行前检查和无关许可降噪 |
| 反馈与恢复 | Toast、页面反馈、状态下一步、保存回执和版本冻结均有实现 | 将单模块反馈升级为跨模块待办；异常后提供保留输入的复制新建 |
| 资源生命周期 | 草稿、审核、发布、撤回、评测和固定版本状态真实可见 | 操作全部平铺会增加扫描成本，应让当前状态决定唯一主行动 |
| 移动端 | 侧栏抽屉、表格卡片化、弹窗固定底栏、画布/属性分屏已有覆盖 | 主要问题是工作流工具区占用编辑高度，不是重新设计整套移动导航 |
| 可访问性 | 跳转主内容、焦点管理、键盘页签、减少动态效果、44px 控件和文字对比已有基础 | 新需求沿用同一标准，并补原生 IME、完整缩放、实体设备与屏幕阅读器验证 |

## 4. 目标用户与核心任务

这里的角色是使用场景，不代表新增 IAM 或多人权限体系。

| 角色 | 核心目标 | 典型问题 |
| --- | --- | --- |
| 任务执行者 | 快速交办任务，处理授权/材料/异常，拿到可信结果 | “我现在该处理哪一项？失败后怎样不重复填写？” |
| Agent 配置者 | 配置 Agent、Skills、知识与工作流，并验证其可用性 | “还缺哪些依赖？配置是否真的能用于下一次执行？” |
| 空间运营者 | 管理每日计划、评测提醒、运行时和空间资源 | “哪些计划受阻？哪些问题需要介入，哪些只是提醒？” |

核心 JTBD：

> 当我有一项目标或异常需要处理时，我希望从当前空间快速进入正确的下一步，并在不重复输入、不误解权限、不破坏历史记录的前提下完成它。

## 5. 关键用户动线现状

### 5.1 首次任务

当前链路：

`工作台/空状态 → 新建任务 → 任务与范围 → 执行方式 → 审查与许可 → 创建运行 → 查看报告/证据`

已有优点：三步进度、集中审查、未保存关闭保护、配置往返、结果页下一步。

主要成本：

- 内置 Agent 可直接开始，但帮助与部分空状态又引导先创建 Agent，首次路径不够统一。
- 真实运行时可在未安装 CLI 或模型不可用时进入提交流程，缺少统一的运行前检查结论。
- 知识问答没有发布资料时，任务创建页没有前置提示和补资料分支。
- 未完成表单只保存在当前页面，刷新或关闭后无法恢复。

### 5.2 待授权、异常与恢复

当前链路：

`运行记录/详情 → 状态提示 → 授权/恢复/查看诊断 → 必要时另建任务`

主要成本：

- 单任务的待办在工作台，工作流等待在工作流页，每日阻塞在每日计划页，评测提醒又在评测页。
- `WAITING_INPUT` 明确提示“当前版本不支持在线追加材料”，但也没有保留输入的复制入口。
- 失败、超时或取消后没有“基于此任务新建”，用户需要重新填写目标、对象和预算。
- 部分状态同时显示通用说明和下一步说明，信息重复。

### 5.3 Agent + Skill + 任务

当前链路：

`创建/编辑 Agent → 管理 Skill → 保存/发布 → 返回 Agent → 保存新版本 → 开始任务 → 重新审查许可`

已有优点：跨模块返回保留输入，固定 Skill 版本，权限重新审查。

主要成本：

- 保护主要存在于当前页面会话，长时间配置仍怕刷新和关闭。
- 配置完成后只能说明“已保存”，运行前所需的 CLI、模型、知识和 MCP 依赖没有汇总为一份 readiness 检查。

### 5.4 工作流

当前链路：

`准备 Agent → 对话或画布设计 → 审查保存 → 启动并审查许可 → 按节点执行 → 逐节点授权/查看子任务`

主要成本：

- 同一页面依次堆放工作流定义、运行记录、设计对话和运行详情；默认还会读取并展示首条运行详情。
- 节点等待授权时需要进入详情定位，无法从工作台统一处理。
- 手机画布工具占据多行，压缩节点配置的有效编辑高度。

### 5.5 复盘与知识复用

当前链路：

`运行复盘 → Agent 生成建议 → 审阅编辑 → 沉淀 → 知识/记忆/经验/能力 → 审核/评测 → 发布 → 后续任务复用`

已有优点：来源可追踪、保存不等于发布、经验必须评测后发布。

主要成本：

- 生命周期横跨多个页签和状态，用户需要自行记住下一步。
- 资源卡可能同时出现原始运行、版本审计、编辑、导出、提交审核、撤回等动作，主次不够稳定。
- 顶部“新增资料”不随当前页签变化；本体页仍显示通用新增资料入口。

## 6. 问题优先级与优化方向

| ID | 优先级 | 代码事实与影响 | 优化方向 |
| --- | --- | --- | --- |
| UX-01 | P0 | 待处理事项分散在多个模块；工作台只完整覆盖单任务统计与评测提醒 | 建立统一待办，按阻塞类型和截止时间排序，逐项进入处理 |
| UX-02 | P0 | 创建任务缺少统一 preflight；未提交草稿仅保存在当前页面 | 增加运行前检查与每空间一个服务端任务草稿 |

| UX-04 | P0 | 运行详情位于列表下方，缺少与 Agent 详情一致的显式返回；部分状态重复说明 | 独立运行详情、统一返回与单一状态行动区 |

| UX-06 | P1 | 工作流定义、运行、设计对话、详情同页；移动工具区偏高 | 定义/运行分区、独立运行详情、移动工具收纳 |
| UX-07 | P1 | 知识库通用新建入口与当前页签不一致；资源卡动作过多，原始 JSON 暴露较深但仍偏技术化 | 情境化创建、状态驱动主行动、业务摘要与诊断分层 |
| UX-08 | P1 | 每日模板对每个 Agent 都展示写入、模型、MCP 三类许可 | 按 Agent 领域和运行时显示相关许可并集中复核 |
| UX-09 | P2 | 既有评审保留资料标题、JSON 错误、移动画布、重复状态、元数据间距五项轻微问题 | 纳入对应需求统一关闭，不单独做补丁式视觉迭代 |

## 7. 目标体验与设计原则

### 7.1 目标体验

1. 打开工作台后，用户能在首屏看到“需要我处理什么”和“从哪里开始新工作”。
2. 任一执行阻塞都有明确、单一的主行动，不需要理解完整运行时状态机。
3. 任一需要重复输入的恢复动作都优先复用已确认内容，但永不复用旧授权。
4. 业务用户先看到结论、影响和下一步；技术用户仍可展开完整证据与 JSON。
5. 列表、详情、配置和返回在不同模块中遵循相同模式。

### 7.2 设计原则

- **任务优先于模块**：首页围绕下一步，而不是围绕功能数量。
- **一个场景一个主行动**：次要操作进入菜单或诊断层。
- **安全可见但不喧宾夺主**：权限仍须明确审查，只减少无关说明和重复输入。
- **配置与执行分层**：定义、运行、历史、诊断分别呈现，避免一页承载所有状态。
- **优化不破坏历史**：所有新操作不得改写旧运行、旧授权、旧评测或冻结版本。
- **不大改导航做表面文章**：M1 保留现有路由与入口，先解决跨模块任务断点。

## 8. 产品需求

### 8.1 本期目标

1. 缩短首次任务与异常恢复路径。
2. 降低跨模块寻找待办和资源的成本。
3. 提升长列表、复杂工作流与资源生命周期的可扫描性。
4. 保持现有响应式、键盘和权限回归全部通过。

### 8.2 非目标

- 不接入真实业务平台、生产 IAM、公网多租户或模型 HTTP API。
- 不改变网关、授权范围、独立验收、幂等恢复和冻结版本规则。
- 不提供一键批量授权、自动继承模型发送许可或自动授予 MCP 权限。
- 不在 M1/M2 实现在原 `WAITING_INPUT` 运行上追加材料；本期通过复制新建降低重复输入。
- 不重做品牌、配色或组件库，不引入仅为视觉变化的重构。
- 不将界面优化解释为开放环境成功率或业务质量提升。

### 8.3 成功指标

当前没有真实用户行为基线，不虚构现状数值。上线前先通过可用性测试和本地匿名事件建立基线，再对比：

| 指标 | 目标 |
| --- | --- |
| 首次 Mock 任务完成时间 | 中位数较旧流程下降 30% |
| 异常恢复重复输入 | 支持复制的字段无需重新输入，权限字段除外 |
| 待办发现效率 | 任一阻塞事项从工作台最多一次点击进入对应处理上下文 |
| 任务设置放弃率 | 相对基线下降；单独统计因 preflight 不满足而主动离开的情况 |
| 跨模块配置路径 | Agent + Skill + 任务链路中的手工重复输入次数为 0 |
| 长列表可达性 | 超过 200 条的历史运行仍可通过分页和筛选到达 |
| 权限安全 | 自动继承授权、跨空间泄漏、旧运行被改写均为 0 |

如采集事件，只在本机保存事件类型、对象类型、状态和耗时，不记录任务正文、知识内容、模型内容或凭据。

### FR-01 工作台统一待办与执行概览（P0）

**用户故事**：作为任务执行者，我希望打开工作台就知道哪些事项需要处理，而不必逐页检查。

**功能要求**：

1. 工作台首屏调整为三个区域：
   - **新建工作**：新建任务、运行工作流；空空间继续保留内置 Agent 快速开始。
   - **需要处理**：展示当前空间所有执行阻塞和需决策事项。
   - **执行概览**：保留执行中、等待处理、已完成等指标，并提供进入筛选记录的入口。
2. 待办类型至少覆盖：
   - 单任务：`WAITING_AUTH`、`WAITING_INPUT`、`NEEDS_REVIEW`、`FAILED`、`EXPIRED`，以及可恢复但未在执行的任务。
   - 工作流：`WAITING_AUTH`、`WAITING_INPUT`、`INTERRUPTED`、`NEEDS_REVIEW`；多个待授权节点合并为一条工作流事项并显示节点数。
   - 每日计划：当前日期的 `BLOCKED` 或部分阻塞计划。
3. 岗位评测未确认提醒作为“质量提醒”独立展示，不与执行阻塞混算。
4. 每条待办显示：对象类型、标题、当前状态、Agent/工作流、产生时间、可获得的截止信息和唯一主行动。
5. 排序规则：有绝对截止时间的按剩余时间升序；其余按需要处理时间升序；同时间按对象 ID 保证稳定。
6. 主行动只进入对应上下文，不直接执行敏感操作：
   - 待授权 → 打开具体提案审查。
   - 缺材料 → 打开缺口说明与处理入口。
   - 待核对 → 打开未通过验收和证据。
   - 可恢复 → 打开恢复确认。
   - 失败/超时 → 打开诊断与“基于此任务新建”。
7. 不提供批量授权、批量恢复或批量关闭。处理后自动定位到下一条待办，但焦点移动必须可预期并有状态播报。
8. 空状态区分“没有待办”和“当前筛选没有结果”。

**验收标准**：

- 同一空间同时存在单任务待授权、工作流待授权、每日阻塞和评测提醒时，四类均可见且计数语义正确。
- 切换空间后待办完全替换，不出现上一空间的对象或操作。
- 1.5 秒自动刷新或手动刷新不打断当前输入、焦点和展开状态。
- 点击任一事项不会自动授权或执行，只到达对应详情。
- 所有待办处理完后显示明确空状态，统计卡与列表结果一致。

### FR-02 任务模板、运行前检查与可恢复草稿（P0）

**用户故事**：作为首次或回访用户，我希望只填写必要信息，在运行前知道还缺什么，并能从上次设置继续。

**功能要求**：

1. 新建任务提供两个明确模板：变更评估、知识问答；使用内置 Agent 作为默认快速路径，自定义 Agent 作为可选项。
2. 将“任务目标”作为第一屏主字段；Agent、运行时、故障场景和预算继续按现有步骤渐进披露。
3. 第三步增加“运行准备检查”，只读检查：
   - 必填业务输入是否完整。
   - Agent 是否存在、未归档、版本可用。
   - 运行时是否安装、模型是否已配置。
   - MCP/受控读取依赖是否可用。
   - 知识问答在当前空间是否存在可访问、已发布且当前有效的资料。
4. 检查项分为“通过 / 需处理 / 执行时才能确认”。“需处理”提供原地修正或保留草稿后前往配置的入口。
5. CLI 未安装、未配置模型、Agent 不可用时不允许“创建并运行”，但允许保存设置草稿；不得把 CLI 检测表达成账号已登录或模型一定有权限。
6. 知识问答没有可用资料时，主行动为“先添加资料”；返回后保留目标和其他非敏感输入。
7. 每个工作空间、当前用户最多保留一个未提交任务草稿：
   - 在字段失焦、步骤切换和离开配置时保存。
   - 保存到本机服务端 SQLite，不把任务正文写入浏览器 `localStorage`。
   - 页面刷新或重开后显示“继续上次设置”，不自动弹窗。
8. 草稿只保存业务输入、Agent/运行时选择和预算；**不保存或恢复 grant、consent、mcp_consent**。
9. 返回草稿时重新读取 Agent 和运行时版本；有变化则显示差异并重新进入审查。
10. “保存待启动”继续表示创建完整、冻结的 `CREATED` 任务，与未提交设置草稿是两种对象，文案不得混用。

**验收标准**：

- 填写一半后刷新页面，可从当前空间恢复非敏感字段，三个许可字段均为未勾选。
- 切换空间不会读到另一空间草稿；提交或明确放弃后草稿清除。
- Agent 在离开期间升级或归档时，返回后显示变化且不能沿用无效选择直接运行。
- 未安装 CLI 时有明确原因和配置入口，不会到执行后才以未知错误失败。
- 空知识空间选择知识问答时，可先添加并发布资料，再返回原任务目标。
- preflight 本身不调用模型、不启动 MCP、不产生业务写入。

### FR-03 基于原任务新建与恢复闭环（P0）

**用户故事**：作为遇到失败或缺材料的用户，我希望复用已经填写的信息，同时明确这是一个新任务并重新审查权限。

**功能要求**：

1. 在 `FAILED`、`EXPIRED`、`CANCELLED`、`WAITING_INPUT` 和已完成任务详情提供“基于此任务新建”。
2. 可复制：任务类型、目标、变更/对象 ID、预算、内置运行时选择、Agent ID。
3. Agent 默认使用当前可用版本；显示“原运行 vX → 新任务 vY”。已归档或不存在时要求重新选择。
4. 以下字段一律不复制：写入授权、模型发送许可、MCP 许可、故障注入场景、旧运行状态和旧执行结果。
5. 新任务获得新 ID，并保存 `source_run_id` 作为来源关联；原运行及其报告、动作、评测和审计不可修改。
6. 对缺材料任务提供“处理材料并新建”：
   - 先展示具体缺口。
   - 可跳到知识库或相关来源处理。
   - 返回后打开已预填的新任务审查页，而非恢复原运行。
7. 合并重复的失败说明，保留“发生了什么 / 已保留什么 / 下一步是什么”三段信息。

**验收标准**：

- 从失败任务新建后，目标和对象无需重输，新 ID 与原 ID 不同且可互相追溯。
- 原授权、模型许可和 MCP 许可均未被继承，故障场景恢复为正常默认值。
- Agent 版本变化在提交前可见，旧运行快照哈希保持不变。
- 用户取消新建后仍回到原运行详情，不产生额外任务。

### FR-04 独立运行详情与统一状态行动区（P0）

**用户故事**：作为查看结果或异常的用户，我希望有明确的返回路径，并先看到与当前决策相关的信息。

**功能要求**：

1. `#/runs/:id` 使用独立详情页；`#/workbench/:id` 保留兼容入口，可使用同一详情组件。
2. 页面顶部提供“返回运行记录”，返回后保留原搜索、筛选、滚动位置和焦点。
3. 顶部只保留一个状态区，统一包含：状态、简明解释、已产生的外部结果、主行动。
4. 保留四类内容，但统一命名和默认页：
   - 执行轨迹。
   - 任务结果（按领域显示评估报告或知识回答）。
   - 证据与验收。
   - 动作与授权。
5. 成功默认打开结果；待授权默认打开动作与授权；待核对默认打开证据与验收；失败默认打开执行轨迹。
6. 右侧运行信息按“任务身份 / 执行配置 / 预算与用量 / 外部结果”分组；低优先级技术标识折叠。
7. 原始 JSON 继续可查看，但位于“技术诊断”折叠区；业务摘要不得以 JSON 代替。
8. 页面主行动与 FR-01 待办主行动使用同一套状态映射，避免不同入口文案和行为不一致。

**验收标准**：

- 全部运行状态下只有一个主行动，无重复的通用失败提示。
- 直接打开、刷新、浏览器前进后退和显式返回均保持正确对象与列表上下文。
- 从待办进入与从运行记录进入，看到的默认页签和主行动一致。
- 320/375/414/768/1440 宽度、浅深主题、键盘与 200% 文字下主要信息和操作可达。

### FR-05 全局搜索与运行记录规模化（P1）

**用户故事**：作为回访用户，我希望直接找到任意资源或历史运行，而不是记住它属于哪个模块。

**功能要求**：

1. `⌘K / Ctrl+K` 搜索范围扩展到运行、Agent、工作流、Skill、知识和本体；导航命令单独分组。
2. 搜索结果按对象类型分组，显示名称、类型、状态和必要元数据；只允许搜索当前空间可访问记录。
3. 回车打开详情，继续支持方向键、中文输入法和无结果恢复；搜索上下文在返回后保留。
4. 运行记录新增：Agent、任务类型、状态、创建日期范围筛选，以及创建时间/最近更新排序。
5. 运行列表改为服务端筛选与游标分页，不再以“最近 200 条”作为不可见的历史边界。
6. Agent 详情的任务记录复用同一筛选；超过一页时提供“查看全部任务”。
7. 搜索和分页不执行模型、不修改资源，不改变现有工作空间请求头与访问校验。

**验收标准**：

- 准备至少 250 条运行，最早记录可通过翻页或筛选到达，Agent 任务记录也可到达同一对象。
- 搜索中文期间不发生误提交、丢焦点或错误选择。
- 任一资源结果只属于当前空间；不存在记录时提供返回列表和清除筛选。
- 筛选、排序和页码在详情返回后保持，浏览器后退行为一致。

### FR-06 工作流定义、运行与移动编辑分区（P1）

**用户故事**：作为工作流配置者，我希望分别管理“以后怎么运行”和“这次运行怎么样”，并在手机上有效编辑节点。

**功能要求**：

- 多节点待授权时只能逐条审查，节点计数与待办一致。

### FR-07 资源生命周期与情境化权限（P1）

**用户故事**：作为资源配置者，我希望当前页面只出现与资源类型、状态和 Agent 相关的操作。

**功能要求**：

1. 知识库顶部主按钮随页签变化：
   - 知识 → 新增知识。
   - 记忆 → 添加工作记忆 / 私有偏好。
   - 经验 → 从运行复盘创建。
   - 能力 → 添加能力方法。
   - 业务本体 → 生成本体。
2. 资料类型切换时，弹窗标题、正文帮助、可见范围和提交按钮同步更新。
3. 资源卡按状态只保留一个主行动：
   - 草稿 → 提交审核。
   - 待审核 → 发布。
   - 经验候选 → 离线评测。
   - 已评测且通过 → 审核并发布。
   - 已发布 → 查看使用位置或创建任务。

5. 复盘、经验、本体显示生命周期进度和下一步，不只依赖保存后的临时提示。
6. 版本与审计先显示结构化事件：时间、操作、状态、来源、操作者；原始 JSON 放入技术详情。
7. 私有偏好 JSON 错误在正文控件旁展示，通过 `aria-describedby` 关联，并提供摘要定位。
8. 每日任务模板按所选 Agent 动态显示许可：
   - 仅写领域显示草稿写入许可。
   - 仅真实模型显示模型发送许可。
   - 仅配置受控 MCP/READ 能力时显示 MCP 许可。
9. 保存每日模板前显示本模板将长期复用的范围和许可摘要；Agent 或业务对象变化后继续清空相关许可并要求重审。

**验收标准**：

- 五个知识库页签的主按钮均与当前资源类型一致，不再出现本体页的通用新增知识入口。
- 任一资源卡只有一个视觉主行动，其他动作仍可键盘到达。
- JSON 错误可直接定位正文，修正后错误清除且输入不丢失。
- Mock 只读 Agent 的每日模板不显示无关许可；切换为真实模型写 Agent 后，所需许可重新出现且默认未勾选。

### FR-08 文案、视觉细节与验证补强（P2）

**功能要求**：

1. 建立统一命名：任务、运行、工作流定义、工作流运行、每日计划、复盘提案、设置草稿不在同一语境混用。

## 9. 数据、权限与非功能约束

### 9.1 数据与历史

- 新草稿与既有 `CREATED` 任务使用不同对象和状态，不进入执行队列。
- `source_run_id` 只表达来源，不表示重试已经覆盖原运行。
- 统一待办、搜索和分页均为只读派生视图，不直接修改运行事实。
- 运行、工作流、资源、评测的既有深链保持可用；若做重定向须保留历史上下文。

### 9.2 权限与隐私

- 所有新接口继续限定当前租户、工作空间和用户可访问范围。
- 草稿、搜索结果、待办计数均不得跨空间泄漏。
- 任何复制、预填、返回和自动保存都不得恢复敏感许可。
- preflight 只读取配置和目录；账号权限、模型可用性仍以实际执行结果为准。
- 待办不提供批量敏感动作，不因“优化效率”绕过具体提案审查。
- 本地指标不得采集任务正文、知识正文、Prompt、模型输出或密钥。

### 9.3 可访问性与反馈

- 保持主要触控目标至少 44×44px、可见焦点、状态文字、减少动态效果和对比度要求。
- 新页面具备唯一 H1、连续标题层级、正确页签/表格/对话框语义。
- 异步保存显示等待、防重复提交；成功以后端回执为准，后续列表失败不得把成功改成失败。
- 错误同时提供摘要和字段级反馈，焦点可到摘要再定位字段。
- 轮询采用现有焦点与输入保护；如数据量增长，可改为活动状态高频、终态低频的自适应刷新。

## 10. 里程碑与依赖

| 里程碑 | 范围 | 主要依赖 | 发布门槛 |
| --- | --- | --- | --- |
| M1 核心任务闭环 | FR-01～FR-04 | 待办聚合查询、任务草稿存储、来源运行关联、统一状态映射 | 首次任务、草稿恢复、授权、失败复制、跨空间隔离全部通过 |
| M2 资源与规模 | FR-05～FR-07 | 搜索索引或查询接口、游标分页、工作流路由调整、资源操作归并 | 250+ 运行、完整工作流、五类资源、每日许可回归通过 |
| M3 精细体验 | FR-08 与专项补验 | 真实设备与辅助技术环境 | R1–R5 关闭，无新增主要可访问性或视觉回归 |

依赖顺序：

1. 先统一状态与下一步映射，再实现工作台和详情，避免两套规则。
2. 先完成任务草稿和 preflight，再复用到工作流启动检查。
3. 先完成运行服务端分页，再扩展 Agent 历史与全局搜索。
4. 视觉细节随对应模块交付，不单独进行全量换皮。

## 11. 核心验收场景

| 场景 | 必须验证的结果 |
| --- | --- |
| 干净空间首次 Mock 任务 | 默认可走内置 Agent；检查清楚；完成后看到结果和下一步 |
| 任务填写中断 | 刷新后恢复非敏感输入；许可不恢复；可明确放弃 |
| 运行时不可用 | 提交前显示原因和配置入口；保存草稿可继续；不调用模型 |
| 空知识空间问答 | 先补资料并发布，返回原目标后继续 |
| 待授权单任务 | 工作台可见；进入具体提案；授权只作用于该任务与参数 |
| 多节点工作流待授权 | 工作台只计一条流程事项并显示节点数；节点逐条审查 |
| 失败/超时复制新建 | 输入复用、权限重置、故障场景不复制、新 ID 可追溯 |
| Agent 版本已变化 | 版本差异可见，旧运行不变，每日模板要求重新选择并审查 |
| 250+ 历史运行 | 分页、搜索、筛选、详情返回均可达最早记录 |
| 跨空间操作 | 待办、草稿、搜索、分页和返回均不出现另一空间数据 |
| 手机与键盘 | 主要操作可达，焦点合理，无横向溢出，不依赖拖动或悬停 |
| 保存回执与刷新竞争 | 成功操作不被旧 GET 覆盖；失败可原样重试；重复点击只提交一次 |

## 12. 后续候选，不进入本期承诺

1. 在原 `WAITING_INPUT` 运行中在线补充材料并继续执行，需要运行时补充输入契约、证据版本和恢复规则。
2. 跨工作空间统一搜索与待办，需要更明确的身份、权限和空间选择语义。
3. 基于真实使用数据推荐 Agent 或任务模板，当前不引入自动路由或自动权限判断。
4. 工作流运行成本、模型 token 趋势和质量趋势图表，需在指标定义和样本量可靠后设计。
5. 多草稿、多用户协作、评论和共享，需要超出当前单机 MVP 的产品边界。

## 13. 需求到实现模块的追踪建议

| 需求 | 主要前端模块 | 需要的支撑能力 |
| --- | --- | --- |
| FR-01 | `app.js`、`operations.js`、`workflows.js` | 当前空间待办聚合、统一状态映射 |
| FR-02 | `index.html`、`journeys.js`、`agents.js` | 草稿持久化、配置/知识 readiness 查询 |
| FR-03 | `journeys.js`、`app.js` | 来源运行关联、复制预填与权限重置 |
| FR-04 | `app.js`、`journeys.js` | 独立详情路由、共享状态行动组件 |
| FR-05 | `app.js`、`agents.js` | 全局搜索、筛选排序、游标分页 |
| FR-06 | `workflows.js`、`workflow_designer.js`、`hig.css` | 定义/运行分区、节点待办与移动工具收纳 |
| FR-07 | `library.js`、`learning.js`、`operations.js`、`skills.js` | 生命周期组件、情境化创建与许可 |
