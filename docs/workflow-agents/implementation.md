# 流程内创建执行智能体

工作流不再要求提前配置全部执行者。对话设计可以根据目标自主设计专用智能体；画布中也可点击“创建专用智能体”，填写名称、职责、执行指令和模型设置来源。没有现有智能体的空空间可以直接进入画布创建流程。

## 使用

1. 打开“工作流 → 对话设计”，选择已配置模型的设计智能体，描述协作目标，例如“请自主创建分析和报告智能体，先分析输入再形成报告”。模型可复用现有智能体，也可提出多个新执行者。
2. 新智能体先以草案展示，打开画布可审查和修改职责、指令、节点目标及依赖。离线模式支持明确语法：`新建「资料分析员」负责分析输入；再新建「报告撰写员」负责根据上游结果形成报告。`
3. 保存时一起创建流程和智能体，将节点的临时引用转换为实际智能体 ID 和版本。同一草案可绑定多个节点，只创建一次。未被节点引用的本地草案不提交；关闭或放弃编辑不会产生智能体记录。
4. 保存后创建运行。新智能体与既有执行者遵循相同的版本冻结、节点验收、上游产物传递和恢复协议。

新智能体采用通用任务交付配置。对话草案使用设计智能体的运行时、模型与推理设置；画布内可以改选其他智能体的模型设置，或使用项目默认运行时。仅复用模型设置，Skills、MCP 和业务权限需在创建后另行配置。来源版本已更新或停用时，必须重新选择，避免悄悄使用不同配置。

## 保存一致性

流程图和全部智能体草案先完成校验，再在同一个数据库事务中创建和绑定。任一草案、版本或依赖无效，以及数据库写入失败，均不留下部分智能体或流程。

保存携带 `request_id`，按租户、空间和用户隔离。相同内容重试恢复原保存回执，内容改变需要新的请求 ID。界面在响应丢失时保留草案与请求 ID，修改内容后自动更新请求 ID。生成提案本身不创建智能体或运行任务。
