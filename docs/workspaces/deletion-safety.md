## 使用

点击空间卡片的“删除”后，确认框先检查当前状态，再开放删除按钮。检查会显示阻止原因及数量；处理后点击“重新检查”。读取失败时保留空间并提供重试，最后一个可用空间始终不能删除。

检查覆盖整个共享空间的未完成任务执行、尚未创建执行记录的排队消息、未完成工作流，以及正在派发的每日计划。返回总数，不返回其他主体的目标、任务标识或私密消息。仍持有有效执行租约的任务和流程也会阻止删除。

智能体提出问题后，原轮次的 `WAITING_INPUT` 会永久保存在运行记录中。已有后续有效消息时，这条旧记录不再单独阻止删除；最新轮次的任务状态、排队状态仍会检查。取消尚未处理的回答不会把原问题当作已回答。未登记为对话的历史等待任务仍需完成或取消。

提交删除时使用刚检查过的空间版本，并在写入事务内重新检查全部阻止条件。其他页面在检查后新建任务，或修改空间信息，都会使提交失败；界面重新检查，等待用户处理或再次确认。

## 并发与回执

- 新任务写入、对话登记和追加消息、工作流保存与启动、每日计划派发认领，在各自写入事务内校验空间仍可用。旧页面与旧进程不能在删除后继续创建新的执行或排队消息。
- 删除检查与实际变更共用状态判断。SQLite 写事务使删除和新工作写入串行完成；检查接口使用同一读取快照。
- 删除/恢复返回事务内生成的空间回执。相同状态的当前版本或前一版本请求可重放，不重复推进版本；发生恢复或后续编辑后，过旧的变更请求返回冲突。
- 界面合并同一空间的重复提交，并直接使用成功回执更新卡片与恢复入口。无需额外列表请求来判定写入成功。
- 删除当前空间后，打开剩余空间的管理页。恢复沿用原项目标识、快照和消息历史。
- 异步检查返回前关闭确认框、打开其他确认操作或切换空间，旧结果不会覆盖新的界面。

每日计划的配置与未派发预览继续保留；空间删除期间不会自动派发，恢复后按原有配置与派发规则继续。

## 接口

`GET /api/workspaces/{id}/deletion-check` 是只读接口，返回：

```json
{
  "workspace": {"id": "workspace-example", "revision": 1},
  "can_delete": false,
  "retains_data": true,
  "blockers": [
    {"kind": "queued_messages", "count": 1, "message": "有 1 条排队消息，请先处理或取消排队后再删除"}
  ]
}
```

示例只列出部分空间字段。阻止类型为 `last_workspace`、`deleted`、`tasks`、`queued_messages`、`workflows`、`daily_dispatch`。现有删除与恢复接口及权限校验继续使用。
