# Agent 岗位与工作空间

2026-10-22。本次完善两项功能：可视化定义 Agent 的身份、职责、标准；创建、编辑、删除和切换代表不同业务及场景的工作空间。

## 使用

```bash
python3 -m agent_framework serve --port 8787
```

打开 [工作空间管理](http://127.0.0.1:8787/#/workspaces)。创建时填写空间名称、所属业务、使用场景和说明。左侧空间选择器或空间卡片的“进入空间”切换当前范围。选择按浏览器标签页保存，互不改变其他标签页的当前空间。

进入“智能体 Agent”并创建或编辑岗位：

1. **身份**：名称、岗位角色、归属团队、用途说明、处理领域。
2. **职责**：添加/移除职责，填写具体说明，选择交付物和负责的验收项。
3. **标准**：选择登记的版本化执行标准，可查看其规则及对应检查项。标准或职责没有覆盖领域的全部必选验收时，表单阻止保存；任务提交仍必须通过后端编译检查。
4. 绑定模拟或 CLI 模型运行时、Prompt、Skill。展开“能力绑定与编译预览”可选择受控只读 MCP、模拟 Tool/CLI/MCP 适配器，并查看自动生成的定义。知识问答领域固定为只读适配器。
5. 保存后可检查编译；卡片“查看职责与标准”提供可读摘要。任务选择该 Agent 时绑定具体版本，后续编辑不会改变已提交任务。

领域切换会装载对应职责、标准及能力。支持“变更评估并创建草稿”和“知识问答·只读引用”；不能用角色说明或 Prompt 绕过运行时授权与独立验收。

## 工作空间范围与删除

每个空间具有不可变项目标识。Agent、任务列表、详情、操作、导出、上下文清单、知识、偏好、情节和经验均按该范围读取。HTTP 请求使用 `X-Agent-Workspace` 选择空间；下载链接携带 `workspace_id`。在空间内自行提交其他项目标识会被拒绝。主体隔离沿用原有权限控制。

本机运行时连接及能力/标准目录是全局配置，共用 CLI 登录态；没有新增成员管理或生产 IAM。业务工具仍为模拟实现。

编辑名称、业务、场景或说明不会改变项目标识及历史快照。删除为**可恢复删除**：从可用空间列表与切换器移除，禁止继续使用，数据保留在数据库；管理页的“已删除的空间”可恢复。空间有未完成任务时不能删除，至少保留一个可用空间。删除当前空间后切换到剩余可用空间；删除默认空间后，服务重启及无空间头的 API 请求也会选择剩余空间。

## 兼容与持久化

- 新增 `workspaces` 表，带租户、版本、项目、业务/场景、删除标志及时间。
- `agent_profiles.workspace_id` 为加法迁移，旧配置默认归属 `workspace-default`；不重写 Agent JSON、任务契约或快照。
- 默认空间映射原 `project-demo`。已有其他项目的任务登记为历史项目空间，仍能切换查看，不改动原任务。
- Agent 和空间修改都检查 revision，冲突返回 409。HTTP 变更沿用 Host/Origin/CSRF 检查，并串行校验空间生命周期，避免删除和创建任务交错。
- 恢复仍使用原动作参数、逻辑 ID、快照和幂等键。没有修改执行与验收内核。

## 接口

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET / POST | `/api/workspaces` | 列表（含已删除）/创建 |
| GET / POST | `/api/workspaces/{id}` | 查看/编辑 |
| POST | `/api/workspaces/{id}/delete` | 可恢复删除，正文 `{ "revision": n }` |
| POST | `/api/workspaces/{id}/restore` | 恢复，正文 `{ "revision": n }` |
| GET | `/api/session` | 当前空间与项目元数据 |
| GET | `/api/agent-definition-default?domain=...` | 所选领域的完整岗位默认定义 |

创建/编辑空间正文为 `name`、`business`、`scenario`、`description`、`revision`；新建 revision 为 0。项目标识由服务生成，不允许改写。Agent 沿用已有 CRUD、归档和 compile API，在选定空间内操作。
